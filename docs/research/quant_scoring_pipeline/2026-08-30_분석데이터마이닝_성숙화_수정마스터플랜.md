## Stage RES-04P — 사전등록

추천 브랜치:

```text
codex/process-research-res-04-prereg
```

### 목적

Episode E1과 Cross-Family Router R1의 outcome-free feasibility 측정 규칙을 실행 전에 봉인한다.

### 산출물

| 산출물 | 내용 |
|---|---|
| Markdown prereg | 사람이 읽는 목적·예측·Gate·STOP |
| JSON manifest | 입력 hash·필드 allowlist·sample Gate·seed·예산 |
| Forbidden field list | PnL·MDD·승률·미래가격·exit 결과 |
| Expected receipt | Stage F가 남겨야 할 정확한 schema |

### 완료 Gate

- Stage F를 실행하지 않는다.
- 입력 Event evidence SHA-256을 봉인한다.
- E1 onset/reset과 R1 overlap/conflict 정의를 봉인한다.
- 가설 선택 규칙은 성과를 사용하지 않는다.
- 최대 경제 실행량 40 jobs를 넘지 않는다.
- 둘 다 표본 부족이면 G0 없이 STOP한다.

추천 브랜치:

```text
codex/process-research-sys-05-golden-analysis-fixture
```

### 해결할 결함

- 현재 successful webbt job 0건
- V4에서 분석 파이프라인 종단 검증 불가
- malformed CSV와 NO_TRADES의 fail-soft 혼동

### 구현 방향

```text

├── fixed job JSON
├── modern 54-column trade CSV
├── strategy snapshot hashes
```

```text
VALID
NO_TRADES
MISSING_ARTIFACT
INVALID_SCHEMA
ROW_PARSE_PARTIAL
ROW_COUNT_MISMATCH
NONFINITE_VALUE
IDENTITY_MISMATCH
```

`load_trades_csv -> []` 하나로 합치지 않고 typed result로 파싱한다. 기존 무예외 UI helper는 typed 상태를 소비해 사용자 메시지로 변환한다.

### 완료 Gate

| 검증 | 완료 조건 |

| Contract | TradeArtifactContract가 result 분석 선행 Gate |

| Browser | Backtest→Result→Analysis Card→Episode deep link 실제 사용 |
| Safety | 운영 DB·실제 job history 쓰기 0 |
| Determinism | 같은 fixture의 모든 derived hash 동일 |

## Stage ANA-05 — Canonical AnalysisBundle v3

추천 브랜치:

```text
codex/process-research-ana-05-canonical-result-bundle
```

### 목적

여섯 개로 분리된 분석 계약을 하나의 content-addressed 결과 객체로 연결한다.

```text
full_analysis
AnalysisBundle v2
Analysis Card v2/V3
analysis_snapshot
TradePathAnalysis
program-specific RES JSON
        │
        ▼
Canonical AnalysisBundle v3
```

### 필수 섹션

| 섹션 | 필수 내용 |
|---|---|
| identity | job/candidate/parent/program/fold/evidence ID |
| source | strategy/config/data/engine/git/CSV hash |
| preregistration | manifest hash·period·cost·seed·stop rule |
| data_quality | schema·row·missingness·column availability |
| execution | terminal state·failure cause·attempt lineage |
| metrics | 공식 metrics와 CSV derived metrics 구분 |
| series | equity·drawdown·daily·rolling·monthly |
| distribution | PnL·MAE/MFE·exit·holding |
| statistics | effect·CI·p·q·multiplicity family·power |
| episodes | cohort definition·trade keys·episode lineage |
| attribution | segment·feature·ablation·orderflow |
| counterfactual | assumptions·matched/lost/new·advisory authority |
| robustness | folds·controls·posterior·capacity·cost stress |
| findings | descriptive/actionable/blocked findings |
| decision | execution/economic/authority/next action |
| evidence | artifact paths/hashes/generator version |

### 영속성

```text
analysis_artifacts/<content_sha256>/bundle.json
analysis_artifacts/<content_sha256>/tables/*.parquet 또는 bounded JSON
analysis_catalog.sqlite (read catalog only)
```

운영 `_database/`가 아니라 별도 연구 artifact root를 사용한다. bundle은 덮어쓰지 않고 content hash별 immutable 저장을 원칙으로 한다.

### Analysis Card 통합

- Dashboard도 v3를 읽는다.
- Loop prompt도 같은 v3 content hash를 읽는다.
- v2는 compatibility projection으로만 유지한다.
- `card_v3_to_json`을 실제 artifact writer와 reader에 연결한다.
- typed feedback v2를 연구 preset 기본으로 올릴지는 별도 compatibility test 후 결정한다.

### 완료 Gate

- 기존 v2 fixture를 v3로 lossless projection한다.
- episodes/counterfactual/robustness가 실제 미실행이면 reason과 prerequisites를 포함한다.
- UI·prompt·report가 동일 bundle/card hash를 표시한다.
- bundle API가 재계산이 아니라 immutable artifact를 우선 읽는다.
- source artifact 변경 시 새 hash가 생기고 과거 bundle은 유지된다.

## Stage ANA-06 — Episode/Cohort Mining Foundation

추천 브랜치:

```text
codex/process-research-ana-06-episode-cohort-mining
```

### 목적

거래 행만 분석하는 구조에서 독립 episode와 cohort를 1급 객체로 만든다.

### 최소 데이터 모델

```text
result_artifact
├── artifact_id / hash / schema / job / candidate / fold

trade_fact
├── trade_key / artifact_id / symbol / entry / exit / pnl / cost

episode_fact
├── episode_id / candidate / symbol / fold / onset / reset
├── trigger_count / selected_trade_key
└── outcome fields는 Stage F에서 projection 금지

cohort_definition
├── cohort_id / prereg_hash / input fields / filters / role

feature_snapshot
├── trade_or_episode_id / feature / value / observed_at

finding
├── finding_id / analysis_hash / axis / effect / CI / q / role / status
```

### Stage F Projection

Stage F 전용 reader는 다음 필드만 볼 수 있다.

```text
candidate
family
fold
day
symbol
timestamp
triggered
previous_triggered
```

outcome column을 물리적으로 포함하지 않은 projection을 만든다. 단순 코드 주석이 아니라 schema/column allowlist로 막는다.

### Mining 기능

| 기능 | 목적 |
|---|---|
| Episode onset/reset | 반복 발화와 독립 기회 분리 |
| Cross-family overlap | 상충·exclusive·consensus 상태 확인 |
| Missingness profile | feature별 결측·zero-only·coverage |
| Cohort census | day/symbol/fold 분산·집중도 |
| Matched random control | 단순 거래 감소 효과 분리 |
| Deterministic sampling | seed receipt·동일 결과 |

### 완료 Gate

- outcome-free schema에 금지 필드 0개.
- episode 생성이 순차·병렬 실행에서 동일하다.
- 같은 candidate/symbol 상태의 중복 onset이 없다.
- reset 누락·timestamp 역전·missing symbol은 typed failure다.
- Stage F 결과만으로 경제 성공 표현을 만들 수 없다.

## Stage ANA-08 — Finding→Hypothesis→Prereg Bridge

추천 브랜치:

```text
codex/process-research-ana-08-hypothesis-prereg-bridge
```

### 목적

분석 결과가 자유문 feedback으로만 사라지지 않고, 사람이 검토 가능한 구조화 가설과 사전등록 초안으로 이어지게 한다.

### 상태 머신

```text
DESCRIPTIVE_FINDING
        │ sample/CI/FDR/prereg axis Gate
        ▼
ACTIONABLE_FINDING
        │ hypothesis builder
        ▼
HYPOTHESIS_DRAFT
        │ human review
        ├── REJECTED
        ├── NEEDS_DATA
        └── ACCEPTED_FOR_PREREG
                    │
                    ▼
             PREREG_DRAFT
                    │ explicit commit/hash
                    ▼
             PREREG_SEALED
```

### Hypothesis 필수 필드

- 설명하려는 실패
- 반증 가능한 예측
- entry-time 변수
- 금지 변수
- 데이터 필요량
- 누수 위험
- negative controls
- budget
- normal STOP
- source finding IDs와 bundle hash

### 안전 원칙

- 모델이 threshold를 임의 제안해도 prereg 전 실행 불가.
- validation/OOS finding은 directive가 될 수 없다.
- free-text feedback은 descriptive로 보존하고 typed directive만 실행 입력 가능.
- 분석 실패/누락은 조용히 흡수하지 않고 feedback health에 표시한다.

### 완료 Gate

- 같은 bundle로 동일 hypothesis ID가 생성된다.
- hypothesis가 소비된 prompt/manifest ID를 역추적할 수 있다.
- 사람 승인 없이 prereg sealed 또는 실행 상태가 되지 않는다.
- RES-04 가설 문서를 machine-readable hypothesis registry로 표현할 수 있다.

| Role | train/validation/OOS directive 권한 |
| Program | missing Fold/control이면 fail-closed |
| Multiplicity | q family·seed·receipt 재현 |
| Persistence | immutable artifact, duplicate idempotency |
| API | bundle/card/path/finding/hypothesis parity |
| Browser | source→analysis→episode→hypothesis→prereg |
| Performance | 29GB source는 bounded/partitioned scan, UI request timeout 방지 |
| Safety | operating DB write·Holdout access 0 |

### Golden E2E Narrative

```text
Golden Job 선택
→ Data Quality VALID
→ AnalysisBundle v3 hash 표시
→ Summary/Fold/Episode 로드
→ Finding 하나 선택
→ 실제 trade/replay 이동
→ Hypothesis draft 열기
→ Prereg preview 생성

```

## 7. 데이터 엔지니어링 방향

### 원칙

- 운영 DB를 분석 warehouse로 사용하지 않는다.
- 공식 결과 artifact는 immutable source다.
- derived artifact는 content hash로 버전 관리한다.
- 대용량 tick source는 전체 메모리 로드가 아니라 partition/scan을 사용한다.
- SQL/column semantic layer가 한글 STOM 변수와 B/S/R 컬럼을 연결한다.

### 권장 저장 구조

```text
research_analysis/
├── catalog.sqlite
├── bundles/<hash>/bundle.json
├── facts/<hash>/trades.parquet
├── facts/<hash>/episodes.parquet
├── findings/<hash>/findings.jsonl
├── hypotheses/<program>/registry.jsonl
└── prereg/<program>/<hash>.json
```

실제 라이브러리 선택은 별도 구현 사전점검에서 결정한다. 기존 SQLite·JSON 자산을 보존하고, Polars/DuckDB/Parquet 도입은 성능·배포 의존성 검증 후 채택한다.
