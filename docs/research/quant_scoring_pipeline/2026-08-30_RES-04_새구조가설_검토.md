## 3. 공통 실패 메커니즘 합성

### M1. 확인 절을 추가하는 방식은 edge를 만들지 못했다

G1은 부모 threshold를 고정하고 `연속상승(3)` 또는 `호가상승압력(30, 0.7)`을 하나 추가했다. 이 설계는 올바른 상태를 새로 정의한 것이 아니라 기존 상태를 더 좁혔다.

Compression은 거래 412건을 유지하면서도 4Fold 평균이 모두 음수였다. 따라서 “확인이 부족해서 실패했다”는 설명은 Compression에서 반증됐다.

### M2. 일부 Family는 기회가 아니라 표본이 소멸했다

Failed Breakout은 372→15, Flow Divergence는 93→0이다. 이 경우 양수/음수 판단 전에 독립 episode 표본이 없다. 더 강한 confirmation을 추가하는 방향은 금지한다.

### M3. 상대 개선 신호가 Fold에 따라 뒤집힌다

Paired 3/7과 개선 Fold 15/28은 구조 변화에 반응하는 부분집합이 있음을 뜻한다. 그러나 동일 Family 안에서도 Fold별 부호가 뒤집혀 하나의 전역 AND 식으로는 분리되지 않았다.

“국면이 나빴다”는 사후 설명은 이미 등록부에서 종결됐다. 새 가설은 Fold 결과를 보고 국면을 이름 붙이지 않고, entry 시점에 관측 가능한 상태와 사전 고정된 routing 규칙만 사용해야 한다.

### M4. generic exit 교체는 우선 방향이 아니다

기존 Entry×Exit paired 연구는 generic S1/S2/hold300이 baseline exit를 구제하지 못했다고 결론냈다. exit만 다시 바꾸는 연구는 반복이다. Family thesis와 직접 결합된 invalidation exit만 후순위 가설로 남길 수 있다.

## 6. H04_E1 — 독립 Episode Onset/Reset

### 6.1 구조

```text
현재
조건 level=True인 모든 시점
        ↓
반복 발화·같은 상태 재진입 가능

제안
False → True 최초 전이 = EPISODE_ONSET
        ↓
episode당 첫 진입 후보 1개
        ↓
조건이 False로 reset될 때만 다음 episode 허용
```

숫자 cooldown을 튜닝하지 않는다. episode 경계는 동일 조건의 `False→True→False` 상태 변화로만 정한다.

| 요구 항목 | 내용 |
|---|---|
| 설명하려는 실패 | Event Gate 수 대비 독립 거래 기회 부족, 반복 상태에서 상관된 손실·MDD 발생 가능성, confirmation에 의한 무차별 표본 감소 |
| 반증 가능한 예측 | first-onset 후보가 matched-count random thinning보다 4Fold 중 최소 3Fold에서 평균 손익이 높고, worst-fold total이 나빠지지 않으며 MDD가 감소해야 한다 |
| entry-time 변수 | 기존 Family trigger boolean, 이전 trigger 상태, `종목코드`, `시분초`, `데이터길이`, 기존 가격·Flow·호가 entry snapshot |
| 데이터 필요량 | 기존 Event Gate의 candidate/fold/day/symbol/timestamp/triggered; 성과 없이 episode 수·기간·종목 분산만 계산 |
| 누수 위험 | 결과를 보고 reset 규칙·cooldown을 선택하는 것. 숫자 cooldown 금지, 상태 reset만 허용 |
| 비용 | feasibility는 기존 timestamp read-only 집계. 경제 G0는 5 Family 대표×4 Fold=20 jobs + matched-count control 20 jobs, 최대 40 |
| negative control | 같은 Family/Fold에서 동일 거래 수만큼 timestamp를 무작위 선택하는 matched-count thinning; seed 사전 고정 |
| G0 가능성 | 모든 Fold의 독립 episode 수가 RES-04에서 사전 봉인한 하한을 충족할 때 가능 |
| 정상 중지 | 4Fold 중 하나라도 필요한 독립 episode 하한을 못 넘거나 random thinning과 구분할 실행 설계가 없으면 `STOP_EPISODE_SAMPLE_INSUFFICIENT` |

### 6.2 왜 기존 G1 반복이 아닌가

G1은 조건 level에 확인 절을 추가했다. E1은 조건의 숫자나 절을 바꾸지 않고 “한 상태를 몇 개의 독립 의사결정으로 세는가”를 바꾼다. 표본을 단순히 적게 만드는 효과는 matched-count control로 분리한다.

## 7. H04_R1 — Cross-Family Conflict Router

### 7.1 구조

```text
현재
ABSORPTION / FAILED_BREAKOUT / COMPRESSION / FLOW / OPENING
각 Family가 서로를 모른 채 독립 발화

제안
동일 symbol·timestamp의 Family 발화 집합
        │
        ├── 단일 Family ........ canonical route
        ├── 호환 Family ........ predeclared consensus route
        └── 상충 Family ........ abstain
```

Family 우선순위를 과거 PnL로 정하지 않는다. 먼저 기존 outcome-free Event timestamp로 overlap·exclusive·conflict 빈도만 측정한다.

| 요구 항목 | 내용 |
|---|---|
| 설명하려는 실패 | 서로 다른 thesis가 같은 시점에 중복 발화하거나 방향이 충돌해 독립 Family 평균이 음수가 되는 구조 |
| 반증 가능한 예측 | predeclared exclusive/consensus route가 matched-count random Family route보다 최소 3/4 Fold에서 평균 손익 우위이고 worst-fold total이 악화되지 않아야 한다 |
| entry-time 변수 | 5개 Family trigger, `종목코드`, `시분초`, Family별 기존 entry snapshot; outcome 변수 없음 |
| 데이터 필요량 | Event Gate 160후보 또는 봉인 7후보의 timestamp 교집합, symbol/day별 동시발화 matrix |
| 누수 위험 | G0/G1 PnL로 Family 우선순위·호환쌍을 정하는 것. 호환성은 thesis 논리와 trigger polarity로 사전 고정 |
| 비용 | overlap census는 read-only 집계. 경제 G0는 router 1개+random router 1개×4 Fold=8 jobs, 필요 시 thesis-stratified report |
| negative control | Family label permutation, 동일 abstain 비율의 random router, 동일 거래 수 control |
| G0 가능성 | 모든 Fold에 exclusive와 conflict episode가 각각 사전등록 하한 이상 존재할 때 가능 |
| 정상 중지 | 중첩률이 너무 낮아 router가 기존 전략과 동일하거나 conflict 표본이 부족하면 `STOP_ROUTER_NO_IDENTIFIABLE_CONFLICT` |

### 7.2 주요 한계

현재 증거에는 Family timestamp overlap 표가 없다. 따라서 이 가설은 타당하다고 확정된 것이 아니라 “낮은 비용으로 반증 가능한 구조 질문”이다.

## 8. H04_X1 — Family Thesis Invalidation Exit

예:

```text

압축 → 확장 → 신고가/Flow

invalidation
확장 실패 + range 내부 복귀 + Flow 반전
```

| 요구 항목 | 내용 |
|---|---|
| 설명하려는 실패 | G1 confirmation이 손절과 익절을 함께 줄였고 generic exit 변경도 edge를 만들지 못한 entry/exit 의미 불일치 |
| 반증 가능한 예측 | Family-specific invalidation이 baseline exit보다 loss-tail·MDD를 줄이되 TAKE_PROFIT PnL 감소가 손절 감소보다 커서는 안 되며 Development 기준을 통과해야 한다 |
| entry-time 변수 | Family ID, 진입 당시 가격 위치, 변동성, 체결강도, 거래대금, 호가비율 snapshot |
| 데이터 필요량 | 공식 거래 episode와 post-entry tick path; 분할 체결은 공식 event ledger가 있을 때만 사용 |
| 누수 위험 | 손실 거래를 보고 invalidation을 설계하는 것. Family 사전 의미에서 1개 규칙만 도출하고 Fold 결과 전 봉인 |
| 비용 | 5 Family×baseline/invalidation×4 Fold=40 jobs. generic exit 반복 방지를 위한 높은 검토 비용 |
| negative control | Family exit를 다른 Family에 순환 배정한 permutation control; generic baseline 유지 |
| G0 가능성 | entry edge 또는 E1/R1의 구조 신호가 먼저 관측될 때만 가능 |

## 9. H04_C1 — Causal Cross-Sectional Rank

### 9.1 구조

Compression은 412거래·4Fold 모두 음수였다. 이는 절대 조건을 충족한다는 사실만으로는 기회 품질을 구분하지 못한다는 반례다. 같은 시각의 moneytop 모집단 안에서 상대적으로 가장 강한 가격 반응·Flow·유동성 결합을 선택하는 가설이다.

| 요구 항목 | 내용 |
|---|---|
| 설명하려는 실패 | 충분한 표본에도 지속 음수인 절대 threshold 구조 |
| 반증 가능한 예측 | 동시점 causal rank 상위 route가 동일 거래 수 random rank와 lagged-rank control보다 3/4 Fold 이상 우월해야 한다 |
| entry-time 변수 | `거래대금평균대비비율`, `체결강도평균대비비율`, `구간호가총잔량비율`, `변동성`, 가격 위치, moneytop membership의 동시점 rank |
| 데이터 필요량 | 같은 timestamp의 cross-sectional universe, 모든 구성 종목의 causal snapshot, 결측·지연 provenance |
| 누수 위험 | 장 종료 후 universe·최종 순위 사용, 미래 moneytop membership, 결과 기반 가중치 학습 |
| 비용 | cross-sectional dataset·runtime adapter가 필요해 높음; 공식 엔진과 실시간 parity 검증 선행 |
| negative control | random rank, 1-tick lagged rank, 순위 뒤집기, 동일 거래 수 control |
| G0 가능성 | 현재 낮음. STOM strategy DSL/engine이 동일 시각 cross-sectional rank를 causal하게 재현할 수 있을 때만 가능 |
| 정상 중지 | runtime parity 또는 timestamp completeness가 없으면 `BLOCKED_NO_CAUSAL_CROSS_SECTIONAL_RUNTIME` |

### 9.2 판정

연구 아이디어는 구조적으로 새롭지만 현재 runtime 계약을 넘어설 가능성이 있다. 구현 없이 G0를 약속하지 않는다.
