# 전체 단계 상세 재개 계획 — 문서만 작성, 실행은 다음 요청

## 1. 권장 순서와 단계 문턱

```text
현재 [문서 보존·정지]
    ↓ 다음 사용자 재개 요청
R0 실제 Git/자료/권한 재확인
    ↓
R1 B4b 종료 증거 정리 또는 고정 HEAD 재검증
    ↓
R2 문서·index 통합 / B5 브랜치 기준 동기화
    ↓
B5 비교 → 오버레이 → 포트폴리오 → UI → 독립검증
    ↓
SQ02 지표 정의 → ANA05 Bundle → ANA06 발견·별도 확인
    ↓
ANA07 비교/Fold → ANA08 지식·실험 연결 → UX06 전 페이지 수용
```

R0/R1/R2는 재개를 위한 복구 절차다. 새 개발 진척으로 집계하지 않는다. 기존 승인된 RES04P 정의를 다시 임의 작성하거나 순서를 건너뛰지 않는다.

## 2. 첫 재개 작업 R0~R2

| 단위 | 해야 할 일 | 완료 기준 | 중지·분기 |
|---|---|---|---|
| R0-1 | 모든 작업트리/branch/HEAD/dirty/common-dir 읽기 | 문서와 실제 상태 차이 분류 | 다른 사용자의 변경을 덮어써야 하면 중지 |
| R0-2 | 적용 AGENTS, 최신 핸드오프·JSON·B5계획 읽기 | 실제 권한·보호 자료 경계 확인 | 운영 DB/경제 실행 필요하면 별도 권한 |
| R1-1 | 기존 로그 hash와 실제 종료 영수증 탐색 | 로그 요약과 프로세스 exit를 별도 확보 | 과거 세션 Unknown이면 반복 polling 금지 |
| R1-2 | exit 영수증 없으면 고정 소스 재시험 | 두 실행의 로그·exit·HEAD·명령·환경 저장 | 실패/정지 시 PASS 아님; 조사/복구 |
| R1-3 | 별도 최종 TASK/JSON 영수증 | tested_commit 정확, 비교 기준 명시 | 이전 RUNNING 문서는 역사로 보존 |
| R2-1 | 문서 branch의 diff/ancestor 확인 후 통합 | 문서 범위만 no-ff 병합 | 이 작업은 다음 재개 요청 범위에서만 수행 |
| R2-2 | 통합 MD 기준 generated index 갱신 | index --check PASS | 봉인 파일 수정으로 지문을 맞추지 않음 |
| R2-3 | 기존 B5 branch 존재/dirty 확인 후 최신 정본 통합 | reset 없이 기준 commit 기록 | branch 덮어쓰기/force update 금지 |

## 3. B5 구현 — 하나의 검증 가능한 단위씩

| 순서 | 목적·대상 owner | Red 시험 | 최소 구현·Green 기준 |
|---|---|---|---|
| B5-1 | A/B 양측 source admission; backtest_api._compare_side/_compare_side_for_run/_compare_delta | job/gen 정상·error·partial·missing 조합, calculator 호출 감시 | 불량측 metrics/summary/equity null, 비교 불충족이면 delta 없음, 각 source 품질·SHA 유지 |
| B5-2 | overlay 선택집합 보존; _overlay_series/overlay_jobs | 2~4개·중복·일부실패·전부실패 | 부분 결과를 전체 성공으로 표시하지 않음; 표시 원본 집합과 요청 집합 설명 |
| B5-3 | portfolio 원자 admission; _portfolio_item_trades/portfolio_combine | 정상+불량, 무거래 문자열만 존재, missing CSV, job/gen 혼합 | 모든 입력 검증 후 기존 portfolio_analysis 호출; 하나 실패면 합산 안 함 |

| B5-5 | overlay/portfolio UI; BtOverlayPanel/BtPortfolioPanel | 선택삭제/비우기/실패HTTP200/늦은응답 | 현재 선택키에 맞는 envelope만 표시 |

공통 필수 시험: admission 후 파일 교체(no-reread), 예상행 불일치, NaN/inf, header만 정상 무거래와 자료누락 구분, source hash 누락, 원본 S_/R_ 보존, 기존 라우트/제한/정상 응답 하위호환. 기존 typed AnalysisSource와 CSV 품질 owner를 재사용하고 참조 parser를 통째로 복사하지 않는다.

B5 각 단위는 새 소스/시험/영수증을 명시 stage한다. 기존 B5 계획 branch를 버리지 않으며 필요하면 B5-1 등 child branch로 더 잘게 나눈다. 단위가 큰 legacy 모듈은 필요한 책임만 추출하고 무관한 대형 리팩터링은 분리한다. 실제 코드 변경에는 programming, UI에는 frontend-ui-ux, 유의미한 구현 후에는 review-work 지침을 적용한다. 스킬이 사용자 권한 경계를 바꾸지는 않는다.
