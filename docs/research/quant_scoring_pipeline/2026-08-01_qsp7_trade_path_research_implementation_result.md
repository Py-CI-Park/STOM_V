# QSP7 거래 경로·매도 연구 시스템 구현 결과

> 작성일: 2026-08-01
> 브랜치: `codex/qsp7-trade-episode-research`
> 설계 문서: [2026-08-01_qsp7_trade_episode_exit_research_system_design.md](./2026-08-01_qsp7_trade_episode_exit_research_system_design.md)
> 권위: 진단 시스템 구현 결과. 새로운 매도식의 수익 개선을 주장하는 공식 백테스트 결과가 아님.

---

## 1. 결론

사용자 제안은 구현 가능한 범위와 불가능한 범위를 구분하면 타당하다.

- 기존 결과 CSV의 실제 매도 뒤부터 해당 백테스트의 전체청산시점까지, 이미 존재하는 tick/min DB만 읽어 가격·수급 경로를 복원할 수 있다.
- 실제 매도 후 고정시간 손익, 전체청산 전 회복 여부, 추가 하락, 평가 불가 사유를 거래별로 만들 수 있다.
- 동일 진입을 고정한 매도 규칙 가상 재생으로 후보를 빠르게 줄일 수 있다.
- 그러나 이 결과만으로 변경 매도식의 최종 수익을 확정할 수는 없다. 매도시점 변경은 자금 점유·재진입·동시보유·다음 거래를 바꾸므로 공식 전체 재백테스트가 최종 권위를 가진다.
- 장 마감 강제청산은 유지했다. 강제청산 건수를 기계적으로 줄이는 대신 그 전에 이익권을 보전할 수 있는 조건을 연구 대상으로 만든다.
- 1~2분 거래를 일괄 제거하지 않는다. 매수 후 고정 판단시점의 관측 가능 변수로 `즉시 매도/추가 보유`를 구분하도록 설계했다.

따라서 시스템의 역할은 “미래 가격으로 답을 맞히는 모델”이 아니라, 사람이 하던 손익 종목 분석과 매수·매도 조건식 연구를 더 빠르고 재현 가능하게 만드는 것이다.

## 2. 구현 범위

| 단계 | 구현 내용 | 상태 | 권위 |
|---|---|---|---|
| P0 | 시간·경계·권위·거래키·비용 계약과 fixture | 완료 | 계약 |
| P1 | CSV+tick/min DB 거래 에피소드, 매도 후 잔여경로, 고정 horizon | 완료 | 진단 |
| P2 | Backtest 요약→cohort→거래→경로 drill-down | 완료 | 진단 |
| P3 | 제한 DSL, 최초 발동 순서, 고정 진입 매도 가상 재생 | 완료 | 자문 |
| P4 | 근거·반증·위험을 포함한 STOM 매도식 초안 제안 | 완료 | 자문 |
| P5 | 이미 실행된 공식 baseline/candidate CSV pair 전이 비교 | 완료 | 정본 |
| P6 | 실행된 job만 표시하는 buy×sell 매트릭스 API | 완료 | 정본 |
| P7 | History 원장, 안전 HTML 진단 보고서, Reports Wiki 연결 | 완료 | 혼합 |

P5와 P6의 “실행 인프라”는 완료했지만 이 구현 작업에서 새 조건식을 전략 DB에 저장하거나 새 공식 백테스트를 실행하지 않았다. 이는 누락이 아니라 다음 안전 경계를 지킨 결과다.

1. 후보 초안은 자동 저장하지 않는다.
2. 사용자가 의도와 조건식 diff를 확인한다.
3. 기존 Backtest 화면에서 명시적으로 공식 job을 실행한다.
4. 실행된 두 job만 정본 pair 또는 매트릭스로 비교한다.

## 3. 데이터·시간 계약

### 3.1 경계

- 관찰 시작: 매수시점
- 실제 매도 뒤 관찰: 실제 매도 직후부터 전체청산시점 이하
- 관찰 종료: 백테스트 전체청산시점
- 전체청산 이후: DB에 값이 존재해도 접근하지 않음
- 분봉의 초 단위 horizon: 같은 봉을 미래로 재사용하지 않고 다음 관측 봉으로 전진
- 관측값 부재: 0 또는 손실로 대체하지 않고 `market_point_missing`
- 경계 초과: `forced_liquidation_boundary`

### 3.2 비용

가상 손익은 기존 Kiwoom 계산과 같은 정수 절삭 규칙을 사용한다.

- 세금 0.18%
- 매수 수수료 0.015%, 10원 단위 절삭
- 매도 수수료 0.015%, 10원 단위 절삭
- 결과는 비용 후 원화 손익과 수익률

### 3.3 거래 식별

`run_id + 결과행 ID + 종목코드 + 매수시각 + 동일시각 진입순번`을 거래키로 사용한다. 동일 종목 반복진입과 동일시각 중복행을 이름만으로 합치지 않는다.

### 3.4 종목코드

- 현재 `code_info.db`에서 종목명→코드가 하나로 확정될 때만 사용한다.
- 다중 매칭은 `ambiguous_symbol`로 제외한다.
- 이름이 아니라 정확한 6자리 코드가 CSV에 직접 기록된 과거 종목은 해당 일자 시장 테이블 존재 여부로 확인한다.
- 신뢰할 수 없는 과거 상호·상장폐지 종목을 임의 매핑하지 않는다.

## 4. 실제 QSP7 데이터 검증

### 4.1 입력 정본

| 구간 | 공식 결과 CSV | SHA-256 |
|---|---|---|
| 설계 2년 | `stock_bt_QSP2ANCH_R8C2_B_20260731234533.csv` | `965201d78de71a142bc23705e649da4c39fcb536577cb235123a12a206cc6825` |
| 표본외 23개월 | `stock_bt_QSP2ANCH_R8C2_B_20260731235145.csv` | `c02b6578136d7d0bb524a175e5025c17f32c8a47b2442e42e8f11a1a07eb0882` |

두 입력은 기존 QSP6/QSP7 기준식 결과이며 변경된 매도식 결과가 아니다.

### 4.2 preflight

| 구간 | 거래 | 거래일 | DB 포함 거래일 | 범위 |
|---|---:|---:|---:|---|
| 설계 | 13,718 | 490 | 490 | 2022-04-01~2024-03-31 |
| 표본외 | 10,755 | 454 | 454 | 2024-04-01~2026-02-27 |

DB가 날짜를 포함한다는 사실과 모든 종목의 모든 시점이 분석 가능하다는 사실은 다르므로, 실제 거래별 제외 사유를 별도로 집계했다.

### 4.3 전체 진단 실행

| 구간 | 원 거래 | 분석 성공 | 제외 | 분석률 | 경계 전 손실회복 거래 | 검열 outcome | 분석 성공분 실제 손익 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 설계 | 13,718 | 13,573 | 145 | 98.94% | 4,800 | 21,000 | -83,417,877원 |
| 표본외 | 10,755 | 10,630 | 125 | 98.84% | 3,963 | 14,594 | -126,879,298원 |

해석 주의:

- `경계 전 손실회복 거래`는 실제 손실 거래가 설정된 잔여 horizon 중 하나에서 비용 후 0원 이상이 된 적이 있다는 진단값이다.
- 이는 그 시점에 체결할 수 있었다거나 전체 포트폴리오 수익이 그만큼 개선된다는 뜻이 아니다.
- `검열 outcome`은 거래 수가 아니라 여러 continuation horizon 중 전체청산 경계 또는 관측 부재 때문에 평가할 수 없었던 결과 수다.
- 제외 거래의 손익은 `분석 성공분 실제 손익`에 포함하지 않았다.

### 4.4 확인된 제한

설계 145건, 표본외 125건은 주로 현재 종목명 사전만으로 과거 명칭을 안전하게 단일 코드로 복원할 수 없는 행이다. 이들을 임의 코드에 붙이면 분석률은 높아져도 결과 신뢰성이 떨어진다. 향후 공식 결과에 종목코드를 함께 저장하는 것이 근본 해결책이다.

## 5. 백엔드 구성

### 5.1 핵심 모듈

- `trade_path_models.py`: 권위·원천·거래키·경로·판단시점·반사실 타입
- `trade_path_clock.py`: tick/min 시각 연산과 분봉 전진
- `market_path.py`: SQLite URI `mode=ro`, 일별 DB 우선·통합 DB 보조, LRU 경로 캐시
- `trade_episode.py`: 결과행을 거래 에피소드로 결합
- `continuation.py`: 고정시점·실제 매도 후 horizon·비용 후 손익
- `exit_counterfactual.py`: 허용 필드만 사용하는 최초 발동 매도 규칙 재생
- `exit_transition.py`: 공식 baseline/candidate의 매칭·신규·소실 거래와 매도사유 전이
- `sell_proposer.py`: 설명 가능한 한 의도 매도식 초안

### 5.2 API

| 메서드 | 경로 | 기능 |
|---|---|---|
| GET | `/bt/trade-path/preflight` | CSV·기간·DB coverage·경계 확인 |
| POST | `/bt/trade-path/jobs` | 단일 worker 분석 시작 |
| GET | `/bt/trade-path/jobs/{analysis_id}` | 진행률·완료·오류 조회 |
| POST | `/bt/trade-path/jobs/{analysis_id}/cancel` | 취소 요청 |
| GET | `/bt/trade-path/summary` | 해시·전체 요약·제외 사유 |
| GET | `/bt/trade-path/cohorts` | 매도사유 cohort 집계 |
| GET | `/bt/trade-path/trades` | 페이지형 거래 목록 |
| GET | `/bt/trade-path/trade/{trade_key}` | 선택 거래 경로만 재조회 |
| POST | `/bt/trade-path/counterfactual` | 고정 진입 가상 매도 재생 |
| GET | `/bt/trade-path/counterfactual/{analysis_id}` | 최근 자문 결과 |
| GET | `/bt/trade-path/transitions` | 실제→가상 매도사유 전이 |
| POST | `/bt/trade-path/proposals` | 근거형 매도 초안 생성, 저장 안 함 |
| POST | `/bt/trade-path/official-pair` | 공식 결과 두 개 비교 |
| POST | `/bt/trade-path/matrix` | 실행된 공식 job의 buy×sell 셀 조회 |
| GET | `/bt/trade-path/history` | 세션 상태+append-only 원장 |
| GET | `/bt/trade-path/report` | CSP 적용 읽기 전용 HTML 진단 보고서 |

### 5.3 작업·원장

- 전체 분석은 백그라운드 단일 worker로 실행해 디스크 난립을 막는다.
- 진행률과 취소 상태를 API로 노출한다.
- 전체 틱 경로는 메모리 결과에 복제하지 않고 거래 상세 요청 때 다시 읽는다.
- `ai_strategy_loop/state/trade_path_records.jsonl`은 분석 시작·성공/실패·가상재생·후보·공식 pair의 작은 요약만 append-only로 기록한다.
- 원장에는 authority와 CSV/전략 hash가 포함된다.
- 프로세스 재시작 뒤 원장 이력은 남지만, 거래 상세 경로를 다시 열려면 원본 job으로 분석을 재실행해야 한다.

## 6. UX/UI 결과

### 6.1 Backtest

기존 실행 워크벤치 아래에 `QSP7 · 거래 에피소드 / 매도 연구`를 배치했다.

1. 완료된 공식 job 선택
2. 사전 점검
3. 경로 분석 시작·진행률·취소
4. 요약·cohort·거래 목록
5. 선택 거래의 매수~전체청산 경로
6. 고정 진입 가상 매도
7. 근거형 조건식 초안
8. 공식 baseline/candidate pair

화면 전 구간에 `진단/자문/정본` 배지를 유지한다. 후보 코드는 복사만 가능하고 자동 저장 버튼은 없다.

### 6.2 Replay

Backtest에서 선택한 거래의 날짜·종목코드·timeframe·매수·실제 매도·전체청산을 기존 Replay로 넘긴다. Replay는 기록된 시장 경로를 읽는 용도이며 진단 결과를 매매 신호로 승격하지 않는다.

### 6.3 History

`근거 · 문서` 단계에 다음 세 영역을 추가했다.

- 현재 프로세스 진단 분석
- 정본 공식 pair
- 프로세스 재시작 뒤에도 남는 append-only 연구 이벤트

### 6.4 Reports

- 설계·구현 결과 문서를 `quant_scoring_pipeline` Wiki 루트에 포함했다.
- 완료 분석은 CSP가 적용된 동적 진단 HTML 보고서로 열 수 있다.
- 진단 보고서에는 전체청산 이후를 읽지 않았다는 제한과 정본 재백테스트 필요성을 고정 표시한다.

### 6.5 반응형·접근성

- 320×800에서 문서 폭과 화면 폭이 동일해 가로 넘침이 없었다.
- QSP7 패널은 모바일에서도 DOM과 화면에 유지됐다.
- Backtest·History·Reports 탭은 역할 기반으로 이동 가능했다.
- 브라우저 콘솔 오류는 0건이었다.

## 7. 안전·누수 방지

- 시장 DB는 read-only URI와 `PRAGMA query_only`로 연다.
- 전체청산 이후 index 접근을 쿼리·모델·테스트에서 차단한다.
- 반사실 DSL은 현재/과거 관측값만 허용하며 임의 Python을 실행하지 않는다.
- `F_*`, `R_*`, `S_*`, oracle, best-future 계열은 매도 후보 코드에 사용할 수 없다.
- 매수 조건 제안에는 결과변수를 전달하지 않는다.
- 분할매수 체결 원장이 없는 거래는 정밀 반사실 적격에서 제외한다.
- 가상 매도는 `ADVISORY`, 공식 결과 pair만 `OFFICIAL`이다.
- 운영 전략 DB, 실거래 주문, V3K 기능 플래그를 변경하지 않았다.

### 8.2 전체 저장소 suite 상태

`pytest tests/unit/ -q`는 6,710개 수집 후 16% 구간에서 다수의 장시간 제한 테스트가 이어져 중단했다. 중단 전 표시된 실패 2건은 fail-fast 재실행으로 분리했다.

1. 기존 `test_security_boundary`가 현재 정본 `v5.14.0` 대신 과거 `v5.13.4`를 기대하는 작업 트리 선행 불일치였다. 제품 버전을 되돌리지 않고 대시보드 전체 실행에서 이 1건만 제외했다.
2. 새 QSP7 POST 6개가 HTTP capability 표에 없던 실제 회귀였다. 모두 `SAFE_BACKTEST`로 분류하고 동적 cancel URL의 제한된 route-template 해석을 추가했다. 수정 후 집중 26개와 대시보드 938개가 통과했다.

저장소 전체 `git diff --check`는 사용자 소유의 접근 제한 상태인 `docs/research/condition_research/reports/`를 Git이 열지 못해 완료되지 않았다. 이 경로는 복원·수정하지 않았으며 QSP7 변경 파일을 명시한 diff check는 통과했다.

## 9. 다음 연구 실행 순서

구현 완료 다음 행동은 “손절식 하나를 지우는 것”이 아니다.

1. 설계/OOS 각각에서 손절 cohort의 회복·추가하락·검열 분포를 비교한다.
2. 매수 후 60·90·120초 고정 판단시점에서 당시 사용 가능 변수로 회복군과 악화군을 구분한다.
3. 단순 지연, 구조 이탈 확인, 이익권 조기 보전처럼 한 의도만 바꾼 매도 초안을 만든다.
4. 가상 재생은 후보 제거에만 사용한다.
5. 남은 후보를 같은 매수식과 공식 엔진으로 설계/OOS 재백테스트한다.
6. 매칭 거래 손익뿐 아니라 신규·소실 거래, MDD, 전체청산, 거래수, 시간대, 자금 점유를 비교한다.
7. 견고한 매도식에서 매수식 필터를 다시 연구해 한 매도식 종속을 줄인다.

새 후보의 개선 수치는 5단계 이후에만 보고한다.

## 10. 남은 제한과 보완 우선순위

| 우선순위 | 제한 | 보완 |
|---|---|---|
| 1 | 과거 결과가 종목명 중심이라 일부 코드가 안전하게 복원되지 않음 | 향후 공식 결과에 종목코드 저장 |
| 2 | 기존 분할매수 컬럼은 체결별 수량·가격 원장이 아님 | 체결 event ledger 추가 후 정밀 반사실 허용 |
| 3 | 기존 OOS를 반복 사용해 완전한 잠금 OOS가 아님 | 신규 잠금 구간 또는 전향 검증 |
| 4 | 가상 손익은 해당 시점 가격의 mark-to-market | 공식 엔진 체결·슬리피지 재검증 |
| 5 | 상세 에피소드는 프로세스 메모리에 유지 | 원본 hash가 같은 경우 재분석 캐시 추가 검토 |

이 제한 때문에 본 구현은 “다 됐으니 수익이 난다”는 결론을 내리지 않는다. 정확한 결론은 **기존 데이터로 가능한 진단·자문·공식 비교 경로가 연결되었고, 새로운 매도식의 수익성은 아직 공식 pair를 실행해 확인해야 한다**는 것이다.
