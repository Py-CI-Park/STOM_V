## 1. 🔑 엔진 창 함수 정의 — 정답지 대조로 역산 (영구 지식)

엔진 소스에 구현이 없었다(`back_code_test.py` 는 문법 검사용 스텁). 대신 엔진이 거래
CSV 에 기록해 둔 `B_*` 값을 **정답지**로 삼아 역산했다 — 체결 모델(매도호가1/매수호가1)을
역산했던 QA-1 과 같은 방법이다.

**엔진 기본 창(`평균값계산틱수`) = 60** (실측: 창 10~120 스캔에서 60에서만 100% 일치)

| 함수 | 확정 정의 | 일치율 | 표본 |
|---|---|---:|---|
| `체결강도평균(n)` | 최근 n틱 **평균** | **100%** | 22건 |
| `누적초당매수수량(n)` | 최근 n틱 **합** | **100%** | 22건 |
| `초당거래대금평균(n)` | **`round`(최근 n틱 평균)** — 엔진이 반올림한다 | **100%** | 41건 |
| `등락율각도(n)` | `deg(atan((r[t] − r[t−n]) / n × 5))` | **100%** | 31건 (3일) |
| `당일거래대금각도(n)` | **미확정** | — | 후보 3종 전부 불일치 → **추측으로 넣지 않고 제외** |

> 반올림을 놓쳤다면(원시 평균 9.2833 vs 엔진 9) 지도의 급증 배율이 엔진과 어긋나
> 후보가 전이되지 않았을 것이다. 정답지 대조가 아니었으면 발견 불가능했다.

## 4. 동일 파이프라인 재실행 — 파생 특징의 순수 기여 측정

QSP10 과 **파라미터를 하나도 바꾸지 않았다**(탐색 깊이 6·표본 하한 2,000·분위 격자 동일).
달라진 것은 **재료뿐**이므로 결과 차이 = 파생 특징의 기여다.

| 규칙 | 항목 | QSP10 (원값 19) | **QSP11 (원값+파생 30)** | 변화 |
|---|---|---:|---:|---|
| **TP+2/SL−1** | 승률 / 분기 | 39.2% / 40.3% (미달) | **40.4%** / 40.3% (**돌파**) | **+1.2%p** |
| | 기대값 | −0.0219% | **+0.0011%** | +0.0230%p |
| | 거래일 | 165일 | **326일** | **2배** |
| **TP+1/SL−1** | 승률 / 분기 | 53.9% / 60.5% | **56.0%** / 60.5% | +2.1%p |
| | 기대값 | −0.1416% | **−0.0910%** | +0.0506%p |
| | 거래일 | 298일 | 267일 | — |
| **TP+3/SL−1** | 승률 / 분기 | 29.2% / 30.2% | **29.8%** / 30.2% | +0.6%p |

| | 거래일 | 298일 | **326일** | +28일 |

### 관측 — 파생 특징은 **일관되게** 개선한다

3규칙 전부에서 승률·기대값이 개선됐다. 같은 알고리즘·같은 게이트에서 입력만 바꿨으므로
**재료 효과로 확정**할 수 있다. 특히:

- **편중 완화**: TP+2/SL−1 의 거래일이 165→**326일**. QSP10 의 최대 약점("소수 날에
  몰려 발화")이 크게 해소됐다 — 질적으로 중요한 개선이다.
- **폭은 아직 부족**: 손익분기를 넘긴 규칙(TP+2/SL−1)도 기대값이 사실상 0 이라
  일 검정(p)은 여전히 통과하지 못한다.

### 6규칙 최종 (게이트 **false** — 그러나 5/6 에서 개선)

| 규칙 | QSP10 승률/기대값/일수 | **QSP11 승률/기대값/일수** | 비고 |
|---|---|---|---|
| TP+2/SL−1 | 39.2% / −0.0219% / 165 | **40.4% / +0.0011% / 326** | 분기 돌파·**일수 2배** |
| TP+1/SL−1 | 53.9% / −0.1416% / 298 | **56.0% / −0.0910% / 267** | 개선, 분기(60.5%) 미달 |
| TP+3/SL−1 | 29.2% / +0.0119% / 298 | **29.8% / +0.0481% / 326** | 기대값 **4배** |
| TP+2/SL−2 | 67.6% / +0.0552% / 71 | **64.5% / +0.1201% / 64** | 기대값 2.2배·편중 잔존 |

| TP+5/SL−3 | 41.1% / +0.0196% / 226 | **70.2% / +0.1752% / 100** | 승률 **+29%p**·기대값 9배 |

### 🔬 관측 — 재료를 바꿔도 **목적 함수가 해를 고정한다**

TP+3/SL−2 는 파생 특징을 줬는데도 **소수점까지 같은 해**로 수렴했다. 즉 탐욕이
합계 기대값을 최대화하는 한, 더 좋은 재료가 있어도 **"며칠에 몰아 크게 버는 해"**를
계속 고른다. 6규칙 중 4개의 거래일이 64~100일에 머무는 것도 같은 이유다.

> 좋은 재료를 더 줘도 레시피가 같은 요리를 지정하면 같은 요리가 나온다.

### 🔧 그래서 교정 — 목적 함수와 판정 기준을 일치시켰다

| | 최적화 대상 | 판정 대상 |
|---|---|---|
| 기존 | **합계** 기대값(거래 몰린 날에 가중) | **일평균** |
| 교정 | `objective="day_mean"` — **일평균을 직접 최적화** | 동일 |

구현 시 성능 문제를 함께 해결했다: 후보마다 `subset`·`groupby` 를 만들면 실행이
불가능해(30변수×5분위×2방향×깊이) **행별 실현 수익률을 한 번만 만들고 위치 색인의
부분 집계**로 바꿨다. 채택된 절에서만 DataFrame 을 실체화한다.

검증: 테스트 59종 GREEN(일평균 목표가 매일 발생하는 신호를 골라 거래일이 더 많음을
합성 실증) + **실데이터 회귀 검증**(벡터화 전후 동일 결과 재현).

## 5. 🎯 일평균 목표 실행 — 편중은 사라졌고, 진실이 드러났다

같은 재료(v3)·같은 게이트, **목적 함수만** `pooled` → `day_mean`:

| 규칙 | pooled 목표 (일수 / 기대값) | **day_mean 목표 (일수 / 기대값)** |
|---|---|---|
| TP+2/SL−1 | 326일 / +0.0011% | **352일** / −0.0825% |
| TP+1/SL−1 | 267일 / −0.0910% | **350일** / −0.1842% |
| TP+3/SL−1 | 326일 / +0.0481% | **352일** / −0.0446% |
| TP+2/SL−2 | **64일** / +0.1201% | **257일** / −0.1584% |
| TP+3/SL−2 | **77일** / +0.4494% | **346일** / −0.1064% |
| TP+5/SL−3 | 100일 / +0.1752% | **319일** / −0.0739% |

### 5.1 두 가지가 동시에 확인됐다

1. **편중 문제는 완전히 해결됐다** — 거래일이 64~100일에서 **257~352일**(전체 355일의
   72~99%)로 올라갔다. 목적 함수를 판정 기준과 맞추자 탐욕이 즉시 "매일 작동하는 해"를
   골랐다. 교정이 의도대로 작동한 것이다.

2. **그러나 그 해들의 기대값은 전부 음수다.** 일평균을 **직접 최대화**했는데도
   p=1.0(일평균 ≤ 0)이다. 즉 **최선을 다해 고른 "매일 작동하는 조합"조차 보통의 날에는
   손실**이다.

### 5.2 이것이 닫는 질문

pooled 목표의 양수 기대값(+0.449% 등)은 **소수 날에 몰린 결과**였고, 그 편중을 제거하면
**양수가 남지 않는다.** 두 목적 함수가 정반대 방향에서 같은 결론에 도달했다:

> **현재 특징 집합(원값 19 + 파생 11 = 30종)과 ≤6절 조합으로는, 이 우주에서
> "보통의 날에 돈을 버는" 진입 규칙이 존재하지 않는다.**

파생 특징은 분명히 기여했다(5/6 규칙 개선, 승률 최대 +29%p). 그러나 **부호를 바꾸기엔
부족했다.**
