## 0. 결론

기존 프로그램의 가장 큰 성과는 실전 후보가 아니라 **실패 경계와 측정 규율**이다. 같은 역사 데이터와 같은 발견기를 확대하는 것은 답이 아니다. 신규 데이터도 알파를 만들어 주는 수단이 아니라, 연구가 만든 주장을 마지막으로 판정하는 미오염 표본일 뿐이다.

챔피언 `Tick_B/S_902_905`는 재사용된 세 구간에서는 양수였지만, 유일한 119일 최종 홀드아웃에서 총수익금 `-8,116원`, 건당 `-0.03%`, 양수 국면 `1/4`, MDD `12.91`이었다. 따라서 **실전 후보가 아니라 `SHADOW_BASELINE`과 엔진 양성 대조군**이다.

G1의 초소형 09:00~09:05 `lift 5.19`는 lookahead 전방 도달 라벨이며 실현 수익이 아니다. G2~G5의 6개 생성식은 손익 판정 전에 전부 미완주했다. 실패한 것은 현재의 채굴→조립→엔진 경로이며, 초소형 가설 자체의 수익성은 미측정이다.

기존 E2의 “17절 이분 탐색”은 절 상호작용이 비단조일 수 있어 원인 귀속에 부적합하다. 다음 첫 단계는 절 제거가 아니라 **E0 엔진 관측성 계약**이다.

## 6. 새로운 연구 방법

### 6.1 Bayesian

- 계층 Bayesian: 일자·국면·종목군별 효과 분포와 `P(순엣지 > 0)` 계산.
- ROPE: 경제적으로 의미 없는 0 주변 효과를 별도 판정.
- 순차 판정: 고정 20일 대신 거래 수·MDE·오류 예산으로 조회 시점 결정.
- Bayesian optimization: 엔진이 안정된 뒤 2~4개 연속 문턱의 저차원 탐색에만 사용.
- 기존 오염 구간을 새 OOS로 포장하지 않으며 prior·후보군·중단 규칙을 사전 등록한다.

### 6.2 Monte Carlo

기존 shuffle/bootstrap API와 팬 차트를 재사용하고 다음을 확장한다.

- moving-block/regime-block bootstrap
- 수수료·세금·슬리피지·지연·미체결 충격
- drawdown duration, time-to-ruin, Monte Carlo error
- 후보 순위 안정성 및 포트폴리오 MDD
- method·seed·n·block length·ruin threshold provenance

Monte Carlo는 새로운 증거를 만들지 않으며, 관측 결과의 순서·표본·비용 불확실성을 평가한다.

### 6.3 응답면·등고선·토폴로지

- 실측 셀과 보간 셀을 분리한다.
- 표본 수, CI/posterior, split, source hash를 겹쳐 표시한다.
- connected plateau, component size, boundary distance, ridge/valley, persistence를 계산한다.
- 비연속 AST 경계를 매끄러운 연속 함수로 가장하지 않는다.
- 국소 민감도는 OOS 판정이 아니다.

### 6.4 조건식 diffusion/denoising

현재 대형 U-Net/diffusion 학습은 성공 코퍼스와 신뢰 가능한 판별기가 부족해 주력으로 채택하지 않는다. 먼저 `D0` 음성대조를 수행한다.

1. STOM 조건식을 canonical AST로 변환한다.
2. 절 삭제·마스킹·순서 교환·임계값 교란을 노이즈 연산자로 정의한다.
3. 규칙 기반 또는 소형 이산 모델이 복원한다.
4. 구문 성공률, 정적 실행 가능성, fixture 완주율을 측정한다.
5. shuffled-label·시점 이동 대조와 외부 fold 부호 안정성을 검증한다.
6. 무작위보다 개선하지 못하면 diffusion 계열을 폐기한다.

## 9. Git·PR 계보

확인 상태:

- 현재 `research/program-reassessment-20260806` @ `f4c4c588`
- 부모 `loop/process-research-pipeline` @ `28d8b908`
- 현재 브랜치는 부모의 순수 후손이며 `0/133`
- 원격 연구 브랜치는 로컬보다 38커밋 뒤
- 대량 untracked 사용자 자료가 있으므로 clean/stash/reset 금지

통합 원칙:

1. 명시적 ref로 현재 연구 브랜치를 먼저 원격 백업한다.
2. 원격 HEAD가 로컬과 같은지 확인한다.
3. 연구 브랜치에서 부모 브랜치로 direct PR을 연다.
4. squash/rebase하지 않고 merge commit으로 topic merge 계보를 보존한다.
5. 현재 오염된 작업트리가 아닌 clean worktree/clone에서 통합 검증한다.
6. 후속 변경은 다음 PR로 분리한다.

| PR | 내용 |
|---|---|
| A | 연구 종결·정본·원장 교정 |
| B | 대시보드 정확성 결함 |
| C | ReviewContext와 UX 정보구조 |
| D | 엔진 heartbeat/watchdog/E0 |
| E | Bayesian·Monte Carlo 판정 계층 |
| F | AST·QMC·다목적 탐색 |
| G | denoising sandbox |

커밋은 파일을 명시적으로 stage하고 한국어 제목·한국어 markdown 본문을 사용한다.

## 11. 검증 계약

각 Phase는 별도 커밋으로 닫고 다음을 기록한다.

- 변경 파일과 source hash
- focused unit test
- dashboard bundle 재생성 여부
- 브라우저 또는 API 시나리오
- `git diff --check`
- 보호 경로 무변경 확인
