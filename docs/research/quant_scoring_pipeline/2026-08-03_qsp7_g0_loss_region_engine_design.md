### 1.1 현재 생성기(R2)의 표현력

### 1.2 사용자가 실제로 쓰는 문법 (직접 작성 `Tick_B_902_905_Study_2`, 128줄 전수 분석)

| # | 문법 | 실제 사용 예 | 현재 지원 |
|---:|---|---|---|
| 1 | 단측 임계 | `2 < 회전율` | ✅ |
| 2 | **양측 범위(유지)** | `1.0 < 등락율 <= 8.0`, `체결강도 >= 50 and 체결강도 <= 300` | ❌ |
| 3 | **변수 대 변수 배수** | `초당매수수량 > 매도총잔량 * 0.20` | ❌ |
| 4 | **양측 배수 범위** | `매도총잔량 > 매수총잔량 * 0.10 and 매도총잔량 < 매수총잔량 * 2.0` | ❌ |
| 5 | **비율(가속도)** | `초당거래대금 / 초당거래대금평균(30) > 3.0` | ❌ |
| 6 | **이전값 대비** | `초당거래대금 > 초당거래대금N(1) * 1.0` | ❌ |
| 7 | **일중 위치** | `현재가 > (고가 - (고가 - 저가) * 0.20)` | ❌ |
| 8 | **계층(시간밴드×시총)** | `시분초 < 90200` → `if 시가총액 < 3000:` | ❌ |
| — | 파생 인라인 | `시가등락율`, `초당순매수금액` 등 4종 | △ 카탈로그 15종만 |

**8종 중 1종만 생성 가능** = 손실 영역을 찾아도 **표현할 수 없다**.

### 1.3 세대 누적 부재

R1·R2 모두 "기준선 → 후보 1개 → 판정"에서 끝난다. 채택분을 다음 세대 기준선으로 삼는 루프가 없어, 사용자가 말한 **"크게 개선되다 수렴하는"** 곡선이 만들어지지 않는다.

### 2.3a 형태를 정확히 잡으면 효과가 2배 (실측 재검증)

| 제거 방식 | 설계 유지율 | 설계 개선 | 표본밖 유지율 | **표본밖 개선** |

| 골짜기만 제거 `not(78<x≤128)` | 50.0% | +321원 | 47.9% | +310원 |
| **다중 밴드 제거 `x≤64 or (78<x≤128)`** | 40.0% | +541원 | **36.4%** ⚠️ | **+682원** |

### 2.6.4 ⚠️ 연속 런의 대가 — 반드시 명시할 것

연속 런은 **자본이 이어진다**. 앞 구간(설계) 손익이 뒤 구간(홀드아웃) 자금 규모에 영향을 준다.

| | 분리 런(v1) | **연속 런(v2)** |
|---|---|---|
| 실전 유사성 | 낮음(구간마다 시드 리셋) | **높음** |
| 독립성 | 완전 독립 OOS | **약함** — 홀드아웃이 앞 구간에 의존 |
| 백테 비용 | 2배 | **절반** |

**대응 3종**
1. 명칭을 **"홀드아웃"**으로 통일한다(OOS 아님). 화면·문서·API 모두.
2. 판정은 **건당 손익 중심**으로 한다(총손익은 자본 규모에 민감, 건당은 덜 민감).
3. 최종 채택 직전에만 **별도 독립 OOS 런 1회**를 선택적으로 실행한다(4-job 모드 유지 이유).

> | 런 1회 | 기준값 | **11분** |
> | 세대 1회(후보 4개) | 11 × 4 | **44분** |
> | G-1(기준선 + 1세대) | 11 + 44 | **55분** |
> | 세대 루프 전체(G-1~G-4) | 55 + 44×3 | **약 3시간 7분** |
>
> **향후 최적화 후보(P-perf, 이번 범위 밖):** 한 엔진 세션에서 여러 후보를 연속 평가하면 기동·배포 비용(268초)을 후보마다 반복하지 않아도 된다. 후보 4개 기준 **약 13분 절감** 여지.

## 4. ⚙️ 엔진 사양

### 4.1 형태 인식 프로파일러 — `ai_strategy_loop/autopsy/loss_profile.py` (신규)

**입력**: 공식 CSV(설계) + 공식 CSV(홀드아웃), 변수 목록(B_* 및 파생)
**처리**:
1. 변수별 10분위 경계는 **설계에서만** 산출(누출 금지) → 홀드아웃에 같은 경계 적용
2. 분위별 `건수 / 총손익 / 건당손익` 계산
3. 최소 표본: 분위당 `max(100, 전체×0.5%)` 미달 분위는 `insufficient`로 표시하고 형태 판정에서 제외
4. **형태 분류**(설계 곡선 기준, 홀드아웃으로 검증):

| 형태 | 판정 규칙 |
|---|---|
| `monotone_up` | Spearman ρ ≥ +0.6 (분위 인덱스 vs 건당손익) |
| `monotone_down` | ρ ≤ −0.6 |
| `tail_high` | 상위 2분위 평균이 나머지 평균보다 1σ 이상 낮음, 중간 평탄 |
| `tail_low` | 하위 2분위가 동일 조건 |
| `multi_band` | **(우선 검사)** 전체 평균보다 나쁜 분위가 **2개 이상 비연속 구간**으로 분리 |
| `valley` | 최악 연속 구간이 **중앙부(D3~D8)** 하나뿐이고 **양끝 2분위 모두** 전체 평균보다 좋음 |
| `flat` | 위 어디에도 해당 없음(스프레드 < 전체 건당의 10%) → 후보 생성 제외 |

> **판정 순서가 중요하다:** `multi_band`를 `valley`보다 먼저 검사한다. 초안은 반대로 두어 체결강도를 valley로 오분류했고, 그 결과 표본밖 개선을 +682원 → +310원으로 **절반 이하로 놓칠 뻔했다**(§2.3a).

5. **홀드아웃 검증**: 설계에서 지목된 최악 구간이 홀드아웃에서도 하위 40% 안에 들어야 `confirmed`, 아니면 `unstable`(후보 제외)

**출력 스키마**
```json
{"variable":"B_체결강도","shape":"valley","confirmed":true,
 "edges":[64,78,88,97,106,116,128,146,180],
 "design":[{"bucket":1,"n":12011,"pnl":-68343000,"per_trade":-5689},...],
 "holdout":[...],
 "worst_span":{"from_bucket":3,"to_bucket":7,"low":78,"high":128,
               "design_per_trade":-5511,"holdout_per_trade":-5532,
               "design_share":0.503,"contiguous":true}}
```

### 4.2 패턴 카드 추출기 — `ai_strategy_loop/revision/pattern_cards.py` (신규)

**입력**: strategy DB의 사람 작성 조건식(기본: `Tick_B_902_905_Study_2`, `Min_B_Study_251227`, 그 외 사용자 지정)
**처리**: AST 순회 → 비교식을 **상수 마스킹 골격**으로 정규화 → 카드 등록

| 카드 ID | 골격 | 파라미터 | 원본 예 |
|---|---|---|---|
| `single_gt` | `A > ?` | A, t | `2 < 회전율` |
| `range_keep` | `?1 < A <= ?2` | A, lo, hi | `1.0 < 등락율 <= 8.0` |
| `range_drop` | `?1 < A <= ?2` (제거용) | A, lo, hi | (신규 — 골짜기 제거) |
| `ratio_gt` | `A / A평균(w) > ?` | A, w, k | `초당거래대금 / 초당거래대금평균(30) > 3.0` |
| `mult_gt` | `A > B * ?` | A, B, k | `초당매수수량 > 매도총잔량 * 0.20` |
| `mult_range` | `B*?1 < A < B*?2` | A, B, k1, k2 | `매도총잔량 > 매수총잔량*0.1 and < *2.0` |
| `prev_mult` | `A > AN(1) * ?` | A, k | `초당거래대금 > 초당거래대금N(1) * 1.0` |
| `position` | `A > (고가 - (고가-저가) * ?)` | k | `현재가 > (고가-(고가-저가)*0.20)` |
| `band_ctx` | `?1 <= 시분초 < ?2` (문맥) | lo, hi | `90200 <= 시분초 < 90500` |

**규율**: 임계값은 카드에 저장하지 않는다(사람 전략 복제 금지). **골격만** 가져오고 값은 데이터로 채운다.

### 4.3 문법 6종 생성기 — `ai_strategy_loop/revision/region_proposer.py` (신규)

형태 → 카드 → 절 생성 매핑:

| 형태 | 카드 | 생성 절 |
|---|---|---|
| monotone_up | `single_gt` | `elif 시가총액 <= 1247: 매수 = False` |
| monotone_down | `single_gt` | `elif 회전율 > 9.0: 매수 = False` |
| tail_high | `single_gt` | `elif 전일동시간비 > 2033: 매수 = False` |
| **valley** | **`range_drop`** | `elif 88 < 체결강도 <= 128: 매수 = False` |
| **양끝 나쁨** | **`range_keep`** | `elif not (1.0 < 등락율 <= 8.0): 매수 = False` |
| **multi_band** | 다중 | `elif 체결강도 <= 64 or (88 < 체결강도 <= 128): 매수 = False` |
| (2D) | 교차 | `elif (1 < 등락율 <= 2) and (88 < 체결강도 <= 128): 매수 = False` |
| (파생) | `ratio_gt`/`mult_gt`/`prev_mult`/`position` | 카탈로그 파생 + 인라인 정의 블록 동봉 |

**세대 후보 구성**: 한 세대 후보 = **제거 절 1~4개 묶음**(복합). 후보 간에는 축 조합이 서로 달라야 한다(중복 금지).

### 4.4 2D 손실 포켓 탐색기 — `loss_profile.py` 내 `pocket_scan()`

1. 상위 판별 변수 K개(기본 6) 중 **상관 |r| < 0.6** 쌍만 조합 → 최대 15쌍
2. 각 쌍 10×10 격자(100칸), 칸당 최소 표본 `max(50, 전체×0.05%)`
3. 설계·홀드아웃 동시 손실 + 건당손익이 전체 평균보다 나쁜 칸만 후보
4. **인접 연속 포켓 병합**(상하좌우 4-이웃) → 직사각형 근사로 절 생성
5. **다중비교 보정**: 칸별 **Welch t 검정**(귀무: 칸 건당손익 = 전체 건당손익)의 p값에 BH-FDR(q≤0.10) 적용, 통과 포켓만 노출
6. **직사각형 근사 손실 검사**: 병합된 포켓을 직사각형으로 근사할 때 포함되는 "나쁘지 않은 칸" 비율이 30%를 넘으면 후보에서 제외(과도 일반화 방지)

### 4.5 세대 러너 + 수렴 — `ai_strategy_loop/revision/generation_runner.py` (신규)

```
세대 g:
  1. 직전 세대 채택 조건식으로 공식 백테스트 → CSV_g (설계·홀드아웃)
  2. loss_profile(CSV_g) → 형태·포켓
  3. region_proposer → 후보 N개(각 1~4절 묶음, 누적 제거 예산 내)
  4. 각 후보 설계 pair(axis=buy) → 총손익·건당 엣지·유지율
  5. 통과 후보만 잠긴 OOS → promotion gate
  6. 최고 후보를 세대 g+1 기준선으로 확정, 원장 기록
수렴 판정:
  - 3세대 연속 홀드아웃 건당 개선 < ε(기본 50원) → converged
  - 누적 유지율 < 40% → budget_exhausted
  - 홀드아웃 2세대 연속 악화 → diverged (직전 세대로 롤백)
```

> ⚠️ 기록된 실패: **"깊이1.5 양측범위 → 표본외 −11%(부호 반전)"**(limitation_ledger 2026-07-31). 양측 범위는 강력한 만큼 위험하다.

| # | 방어 | 규칙 | 근거 |
|---:|---|---|---|
| 1 | 홀드아웃 동시 손실 | 설계·홀드아웃 양쪽 손실 구간만 | QSP3 규율 |
| 2 | 인접 연속성 | 고립 1칸 금지, 연속 2칸 이상 | 노이즈 차단 |
| 3 | 최소 표본 | 분위 100건·포켓 50건 이상 | 검출력 |
| 4 | FDR 보정 | 2D 100칸에 q≤0.10 | 다중비교 |
| 5 | 깊이 상한 | 세대당 절 4개, 2D는 2변수까지 | QSP6 전이율(얕은 37% vs 깊은 9%) |
| 6 | 제거 예산 | 누적 유지율 40% 하한 + 세대별 배분(§5.3) | 표본 붕괴 방지 |
| 7 | 건당 엣지 게이트 | 총손익만 개선하면 차단 | R2 실증(4건 차단) |
| 8 | 임계 경계는 분위 격자에서만 | 임의 미세조정 금지 | 선택 편의 차단 |

### 5.3 제거 예산 규칙 (자체 재검토로 신설)

체결강도 다중 밴드 하나만으로도 표본밖 유지율이 **36.4%까지 떨어져 하한을 위반**했다(§2.3a). 예산은 선택 사항이 아니라 **세대 수를 결정하는 제약**이다.

| 규칙 | 값 |
|---|---|
| 누적 유지율 하한 | **40%** (설계·표본밖 **둘 다**) |
| 세대별 최대 소모 | 1세대 ≤ 25%p · 2세대 이후 ≤ 12%p |
| 후보 자동 완화 | 예산 초과 시 구간을 **한 분위씩 좁혀** 재제안(강→완화 버전) |
| 예산 소진 시 | `budget_exhausted` 선언 후 세대 종료 — 억지로 더 자르지 않는다 |
| 표본밖 우선 | 설계·표본밖 유지율이 다르면 **낮은 쪽**으로 판정 |

| 세대 | 예상 표본밖 건당 | 누적 유지율(표본밖) | 예산 소모 | 비고 |
|---|---:|---:|---:|---|
| 0 (기준선) | −5,250원 | 100% | — | |
| 1 | −4,858원 (+392) | ~71% | 29%p | 단조 1축 (예산 한도 25%p 초과 → 완화 필요) |
| 2 | −4,594원 (+656) | ~52% | 19%p | +다중 밴드(완화 버전) |
| 3 | −4,450원 내외 | ~45% | 7%p | +2D 포켓 |
| 4 | — | — | — | **예산 소진 가능성 높음 → 3세대 수렴 예상** |

> **정직한 한계 4가지 (자체 재검토로 1건 추가)**
> 1. **흑자 전환 불가** — 3~4세대 후에도 건당 −4,400원대. 제거는 손실을 약 15% 줄일 뿐이다.
> 2. **예산이 세대 수를 결정한다** — 1세대 단조 컷만으로 29%p를 쓴다(한도 25%p 초과). 완화 적용이 필수이고, **4세대까지 못 갈 가능성이 높다**. 목표를 "4세대"가 아니라 **"예산 소진 또는 수렴까지"**로 잡는다.
> 3. **위 수치는 단측 4축 시뮬레이션의 외삽**이다. 다중 밴드·2D가 더 효율적일 것으로 보지만 보장은 아니다.
> 4. **시뮬레이터 추정은 재유입을 반영하지 않는다** — 실제 공식 결과는 거래 수가 늘어날 수 있어(R2 실측 100.7%) 추정과 체계적으로 다르다. 순위용으로만 쓴다.
