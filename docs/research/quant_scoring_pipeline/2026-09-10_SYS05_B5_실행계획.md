## 입력 계약과 하위호환

- 기존 selector와 HTTP 경로, overlay 2~4/portfolio 2~6 제한, 기존 계산기·원시 손익 의미는 유지한다.
- AnalysisOwners/AnalysisSource 및 typed 품질 결과를 재사용한다. 직접 loader를 다시 열지 않고 검증 snapshot의 동일 trades를 공급한다.
- 정상 결과의 기존 키는 유지하고 품질·source identity를 추가한다. 차단 시 null/명시 reason을 표시한다. no_trades는 유효한 공식 헤더·예상 행·실행 상태 근거까지 검증한다.
- 저장 metrics는 재계산 summary와 섞지 않고 unverified 저장 요약으로 구분한다. 경제 적격성·비교 가능성의 완전한 판정은 ANA07에 남긴다.
- 비교 날짜 정렬, 자본 정규화와 MDD 정의 변경은 같은 품질 패치에 끼우지 않는다. 기존 정규화가 원화 증분에100을 더하는 표현인 점은 SQ02/ANA07의 명시적 정의 검토 항목이다.

## 필수 회귀 행렬

job/job, generation/generation, job/generation × 정상/실행실패/부분파싱/누락/무거래/비유한/행수불일치. 불량 입력에 calculator spy가 호출되지 않는지 확인한다. admission 직후 파일 바꾸기로 no-reread를 검증한다. 다른 원본 SHA의 집합, 동일 source 중복, 전원 차단/일부 차단, 빈 정상 결과, 한쪽만 존재하는 비교를 각각 시험한다.

React에서는 URL/선택집합/A/B 교체, 늦은 응답, 화면 닫기·비우기, 실패HTTP200, 불완전 품질 envelope를 시험한다. 경제 우세·채택 문구를 새로 만들지 않는다.

## 중지·롤백·권한

연구 seed·비용·표본 기준·승인자를 만들지 않는다. 운영 DB write, 실제 연구/Stage F/G0/G2/Holdout/채택/주문/push는 범위 밖이다. CSV/전략 접근은 resolver/기존 readonly 경로를 유지한다. 새 DB/table이 필요해지면 별도 설계결정으로 분리한다.
전체 Gate 실패는 재현·원인 분류 후 최소 수정하며 통과로 기록하지 않는다. rollback은 신규 코드 역변경 commit. 사용자 WIP와 봉인 evidence는 그대로 보존한다.
