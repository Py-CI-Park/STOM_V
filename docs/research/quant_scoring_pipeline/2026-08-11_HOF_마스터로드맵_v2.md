## 2. 재검토 — 관찰 프로세스는 가능성이 있는가 (요구 ①)

### 2.1 권고안 수정 (재검토의 첫 산출)

| 관찰 대상 | 재검토 결과 | 처리 |
|---|---|---|
| C. 평가익 반납 → 출구 개선 | **등록부 충돌**: 출구축은 알파 B1·open30 R0·W4~W8 로 3회 연구됐고, 트레일링 설계 PASS 는 홀드아웃에서 죽었으며, 조기 청산은 닫힌 방향 3 이다. 가격 기반 출구의 고원은 이미 촘촘히 측정됨 | **후순위로 강등.** 관찰은 하되(관찰은 싸다) 후보화는 **가격 트레일링 계열 밖**(지표 기반 조건부 출구)일 때만 허용 |
| **A. 놓친 승자 (09:00~09:05)** | 진짜 미탐구: W7 은 기존 절 **제거**만 시도(6전 실패). "챔피언이 안 산 급등이 어떻게 생겼나"는 **한 번도 묻지 않았다.** 우주 파케이의 전방 라벨(trail_5_2)로 "놓친 승자"를 직접 계산 가능 | **1순위로 승격** |
| B. 손실 거래 | HOF2 가 이미 수행(단일 피처 문턱은 전멸). 남은 것은 **궤적** 관찰뿐 | A 의 부속으로만 |

### 2.2 왜 A 인가 — 산수

| 근거 | 값 |
|---|---|
| 챔피언의 창은 원재료가 양수인 유일한 창 | 고가붙음 +0.192% (다른 창은 전 자리 음수) |
| 밴드 1 은 밴드 2 보다 건당 2.5배 | +1.126 vs +0.453% |
| 챔피언의 선택은 극도로 좁다 | 3,095만 행 중 361건 = **8.5만분의 1** |
| 놓친 승자의 존재는 확실 | 361건이 전 급등을 다 잡았을 수는 없다 |
| 남는 질문 | 놓친 것들이 "잡을 수 있는 모양"인가 — **이것이 HOF4 의 질문** |

### 2.3 연구로서 값어치 — 실패해도 남는가 (요구 ①의 핵심)

| | HOF1~3 (기계적) | HOF4 (관찰) |
|---|---|---|
| 실패 시 남는 것 | "그 셀은 안 됐다" | **놓친 승자의 전수 지도 + 시각적 이해 + 관찰 인프라** |
| 다음 가설 | 안 나옴 (불임) | 이해에서 나옴 |
| 편의 예산 | 소모 | 관찰 자체는 소모 없음(시드 전용 규율) |
| 인간 프로세스와의 관계 | 절반(판정)만 | 관찰+판정 양쪽 — 인간 유사 + 전수·속도·규율은 AI 우위 |

**성공 확률은 낮아도 기대값이 양수인 이유**: 비용이 낮고(2~3일), 실패의 산출물이
다음 라운드의 입력이 되며, 성공 시 보상(밴드 1 품질 진입의 증분)이 크다.

### 2.4 전체 프로세스에 도움이 되는가

된다 — 세 가지가 프로그램 전체에 이월된다:
① 거래↔우주↔차트 연결 파이프라인(이번에 프로토타입 검증 완료),
② "서술 → 절 번역" 절차(주식 지식이 들어가는 표준 자리),
③ 자가 감사 프로토콜(모든 후속 라운드의 틀).

## 3. "물어봐야 오류가 나온다"의 구조적 해결 (요구 ②)

### 3.1 헌법 17항 (신설)

> **17. 라운드는 보고 전에 자가 감사를 통과해야 한다.**
> 사전 등록에 **등록부 대조**와 **예상 질문 5**를 의무 포함하고, 종료 시
> **체크리스트 10**과 **적대적 자가 리뷰**("사용자가 물으면 무너질 주장이
> 있는가")를 수행해 문서에 남긴다. 사용자 지적으로 발견되는 결함은
> **프로토콜 실패**로 등록부에 등재한다.

실행형: `ROUND_TEMPLATE.md`. 첫 적용 실적: 실수 #15(C 권고 중복)를 사용자
지적 **전에** 자가 발견.

### 3.2 왜 이것이 통하는가

사용자가 잡아낸 실수 4건(#11~14)의 공통 질문이 템플릿 §A-1 에 그대로 들어갔다:

| 사용자가 물었던 것 | 템플릿의 예상 질문 |
|---|---|
| "도구를 쓰고 있나" | Q2 왜 이 도구이고 안 쓰는 도구는 왜 안 쓰나 |
| "과거와 중복 아닌가" | Q1 과거 어떤 연구와 겹치는가 (등록부 대조 의무) |
| "측정을 어떻게 했길래" | Q5 보고에서 오해할 지점은 |
| "인간처럼 하고 있나" | Q4 실패하면 무엇이 남는가 (이해가 남는 실패인가) |

## 4. 미래 로드맵 — HOF4~HOF8 (요구 ③ · AI 실행 가능 수준)

### 4.0 전체 지도

| 라운드 | 질문 | 방법 | 산출 | 소요 |
|---|---|---|---|---|
| **HOF4** | 챔피언이 놓친 승자는 어떻게 생겼나 | 관찰(전수 추출→차트→서술→번역) | 절 후보 ≤10 + 이해 | 2~3일 |
| **HOF5** | 그 후보가 엔진에서 사는가 | 엔진 A/B (학습→검증) | 원장 판정 | 1일 |
| HOF6 | 생존 절의 문턱·조합은 어디가 고원인가 | 격자+wfo (1~3변수) / 소형 nCr | 정련 후보 ≤3 | 1~2일 |
| **HOF7** | 표본 밖에서 사는가 | **신규 축적 거래일**(약 20일 쌓일 때마다) | 유일한 무편의 판정 | 상시 |
| HOF8 | 실전에서 사는가 | 감독형 소액 실전 | 🔒 사람 | — |

순환 규칙: HOF5 전멸 → HOF4 의 이해로 돌아가 새 서술(같은 후보 재탕 금지·등록부 등재).
HOF7 전멸 → 그 계열을 닫고 HOF4 의 다른 관찰 대상으로.

### 4.1 HOF4 상세 — AI 에이전트 실행 절차

**단계 0. 사전 등록** (`2026-08-XX_HOF4_사전등록.md` 작성·커밋 후에만 실행)

| 항목 | 고정할 값 (제안 초안 — 사전 등록에서 확정) |
|---|---|
| 놓친 승자 정의 | 학습 구간(달력 411일) · 09:00~09:05 · `trail_5_2 >= 5.0`(전방 라벨) · 같은 종목·일자에서 60초 클러스터의 첫 초만(onset) · 챔피언 실거래와 ±60초 이내면 제외 |
| 매수 가능성 필터 | `flag_no_trade=0` · `flag_limit_up=0` · `flag_vi_near=0` · `1000<현재가<=50000` · `시가총액<3000` |
| 관찰 표본 | 전수 추출 후 층화 표집 **30건**(시총×시각 층) 차트 렌더 |
| 가설 예산 | 서술 ≤10 · 번역 절 ≤10 (헌법 15항) |
| 도구 | 우주 파케이(전방 라벨) + `backfinder_principle.py`(피처 분위) + matplotlib 궤적(프로토타입 검증 완료) |
| 편향 방어 | 전방 라벨 사용 = lookahead → **산출은 시드 전용**, 채택 판정은 엔진 A/B(HOF5)만 |
| 등록부 대조 | W7(절 제거)과의 차이: 제거가 아니라 **놓친 사례 관찰 기반 수정/추가**. 출구축 아님 |
| 중단 조건 | 놓친 승자 추출이 0건이거나 전부 매수 불가 사유면 → "챔피언이 이미 포화"로 기록하고 HOF7 대기 모드 |

**단계 1. 추출** — 러너 `run_missed_winners.py` (신규)

```
입력: design_v5 우주 parquet(학습 411일) + 챔피언 거래 테이블
처리: 정의·필터 적용 → 놓친 승자 onset 목록 (일자·종목코드·시분초·피처 스냅샷)
출력: _hof4_missed.json + 요약 표(총 몇 건·일평균·시총/시각 분포)
테스트: 정의 경계·클러스터 dedupe·챔피언 거래 제외 로직
```

**단계 2. 관찰** — 층화 30건 차트 렌더(궤적+매수가능구간+챔피언 거래 겹침) → **내가 실제로 보고**, 각 차트에 한 줄 관찰 기록

**단계 3. 서술** — 관찰을 인과 가설 ≤10 으로 (예: "시가 갭 X% 이상에서 첫 2분 고가 유지형은 챔피언 등락율 상한 8% 에 걸려 배제된다"). **여기가 주식 지식이 들어가는 자리다**

**단계 4. 대조** — 놓친 승자 전수 vs 챔피언 실거래 361건의 피처 분위 대조(backfinder 원리). 서술과 분포가 서로 지지하는지 확인 — 지지 없는 서술은 버린다

**단계 5. 번역·인계** — 생존 서술을 절 후보로 번역해 HOF5 사전 등록으로 인계. **HOF4 는 여기서 끝난다(판정하지 않는다)**

**단계 6. 종료 체크리스트 10 + 적대적 자가 리뷰** (ROUND_TEMPLATE §C·§D)

### 4.2 HOF5 상세 — 판정

```
사전 등록: 후보 <=10 · 게이트 = 학습 총수익금 > 챔피언 AND 후보 흑자 AND 자금 <= 2,000만
실행: 밴드 수정형이면 밴드 분리 측정(HOF3 기법 재사용: 코호트 A/B 불변 검사)
판정: 학습 통과 상위 <=2 만 검증 구간 → 검증 통과 시 PROMISING(진입 계열 상한) + 사람 보고
     · 확인 구간은 예약 · 실전 제안은 HOF7 통과 후에만
```

### 4.3 HOF7 상시 절차 — 유일한 무편의 심판

```
신규 거래일 약 20일 축적마다: 원장의 미결 후보 전부를 그 구간만으로 재판정
그 구간은 1회용(재사용 금지) · min 홀드아웃 58일은 잠금 유지(사용자 확정)
페이지 29 인프라 사용 · 결과는 원장 append
```

## 5. 성공 확률 — 솔직한 주관 추정 (근거 포함)

| 단계 | 성공 정의 | 추정 | 근거 |
|---|---|---:|---|
| HOF4 관찰 | 인과 서술 ≥5 산출 | ~90% | 관찰은 거의 항상 구조를 보여준다 (4장 표본에서도 나왔다) |
| HOF5 설계 구간 | 챔피언 초과 후보 ≥1 | ~30% | W7 절 제거 6전 실패 · 단 관찰 기반은 첫 시도 |
| HOF7 표본 밖 | 신규 데이터 생존 | **~10~15%** | 편의 0.54~0.62%p 실측 · 지금까지 표본 밖 생존 0건 |
| 인프라·이해 자산 | 관찰 파이프라인·놓친 승자 지도 확보 | ~100% | 이번 라운드의 **보장된** 산출 |

**정직한 결론**: 한 번의 HOF4→7 사이클로 실전 후보가 나올 확률은 낮다.
그러나 ① 사이클 비용이 낮고 ② 실패가 다음 사이클의 입력을 낳으며(불임 아님)
③ 신규 거래일이 쌓일수록 무편의 판정 기회가 늘어난다. **인간 명전도 같은 구조다
— 다수 시도, 소수 생존. 차이는 우리 실패가 이제 이해를 남긴다는 것이다.**
