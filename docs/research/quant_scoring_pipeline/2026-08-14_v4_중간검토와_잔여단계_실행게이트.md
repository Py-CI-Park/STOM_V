## 5. B0 Bayesian 순차 판정 계약

첫 구현은 백테스트 결과를 새 증거로 만드는 기능이 아니라 이항 성공/실패 관측의 의사결정 경계를 계산하는 순수 모듈이다.

- Beta-Binomial posterior를 사용한다.
- prior alpha/beta, ROPE 하한, 승인/기각 posterior 확률, 최대 표본을 명시한다.
- `APPROVE`, `REJECT`, `CONTINUE`, `MAX_SAMPLE`을 반환한다.
- optional stopping을 숨기지 않고 모든 look을 노출 원장으로 남길 수 있는 receipt를 반환한다.
- calibration test는 고정 seed 합성 자료에서 false approval과 stopping behavior를 측정한다.
- 실제 후보 자동 채택 권한은 없다.

## 6. F0 AST·Q0 탐색 계약

- STOM 조건식 원문을 줄/절 기반 canonical AST로 정규화한다.
- 주석·빈 줄·조건절·대입을 구분하고 원문 round-trip hash를 보존한다.
- 허용 함수·lookback·조건절 수·중첩·예상 작업량을 정적으로 검사한다.
- QMC는 후보 값을 생성할 뿐 성능을 주장하지 않는다.
- Pareto archive는 순수익 최대화 하나가 아니라 MDD·불확실성·상관·비용의 비지배 해를 보존한다.
- 엔진 실행과 최종 OOS 접촉은 이 단계 범위 밖이다.

## 7. D0 denoising 계약

- 노이즈: 절 마스킹, 임계값 교란, 순서 이동, 중복 절 삽입.
- 복원: 우선 규칙 기반 deterministic repair.
- 평가: syntax validity, canonical equality, complexity, static executability.
- 음성대조: shuffled target과 무작위 repair보다 개선하지 못하면 기각.
- 미래 수익·lookahead label을 repair target으로 사용하지 않는다.
- D0 성공 전 U-Net/대형 diffusion 모델을 도입하지 않는다.

## 8. Git 통합 계약

1. `research/program-reassessment-20260806`의 명시 ref만 push한다.
2. force push를 사용하지 않는다.
3. 원격 HEAD가 로컬과 같은지 fetch 후 확인한다.
4. 부모 `loop/process-research-pipeline`에는 squash/rebase 없이 PR merge commit을 사용한다.
5. 대량 untracked 자료가 있는 현재 작업트리에서는 브랜치 checkout·stash·clean을 하지 않는다.
6. PR 검증이나 merge가 현재 환경에서 불가능하면 원격 브랜치와 정확한 compare URL까지 남기고 차단 사유를 보고한다.
