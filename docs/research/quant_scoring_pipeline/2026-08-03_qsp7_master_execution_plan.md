## 2. 🖥️ 전체 페이지 세부 설계 (14개)

> 각 페이지: 목적 → 진입 조건 → 화면 세부 구성 → API → 상태 처리 → 레인 동작 → 완료 기준.
> 공통 규칙: ① 모든 화면 우상단 **레인 배지**(tick=주황 / min=청록) + **권위 배지** ② 로딩·빈·오류 3상태 필수 ③ 오류는 한국어 조치 안내 ④ 사후정보(R_*·매도 후 값)는 매수 연구 입력 금지.

### 페이지 0 — 레인·단계 셸 (신설 골격, P1·P5)

| 항목 | 내용 |
|---|---|
| 목적 | 레인 선택과 단계 진행을 한 골격에서 관리 — 사용자가 순서를 외우지 않게 |
| 세부 구성 | ① 레인 스위치(tick/min, 전환 시 확인 대화) ② 단계 스테퍼(14단계, 완료✓/현재●/잠금🔒) ③ 현재 레인 manifest 요약 바(기준선·설계/OOS 기간·경계) ④ "다음 조건" 안내 문구 영역 |
| API | `GET /bt/trade-path/lane-manifest?lane=` (P6 신설) |
| 상태 처리 | manifest 없으면 스테퍼 잠금 + "P6 manifest 확정 필요" 안내 |
| 레인 동작 | 전환 시 하위 전 페이지 상태 초기화(교차 오염 방지), 미완료 분석 있으면 경고 |
| 완료 기준 | 레인 전환 후 잘못된 레인 job 선택 **불가능**(차단 테스트) |

| 항목 | 내용 |
|---|---|
| 목적 | "이 성적표가 진짜 그 성적표인가" — 연구 입력의 신원 보증 |

| 상태 처리 | job 미완료→"완료된 백테스트가 필요합니다", CSV 소실→경로 안내, 경계 legacy→노란 경고 "공식 경계가 아닌 추정값입니다" |
| 레인 동작 | job timeframe ≠ 현재 레인 → 선택 차단 |
| 완료 기준 | 데이터 없는 날짜가 있으면 **반드시 경고 표시**(회귀 테스트), manifest 불일치 시 다음 단계 잠금 |

> 58점은 "절반짜리 시스템"이 아니라 **"분석실은 준공됐고, 처방 파이프와 성과 증명이 남은 상태"**다. 85점(플랫폼 완성)까지는 실행의 문제이고 확률 95%로 도달 가능하다. 85→95는 시장이 답을 주는 영역이라 확률 60~65%로 정직하게 낮춰 잡는다 — 대신 실패해도 그 기록 자체가 다음 축 결정의 자산이 되도록 원장이 설계돼 있다.
