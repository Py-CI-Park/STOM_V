## 판정 계약

VALID/NO_TRADES/MISSING_ARTIFACT/INVALID_SCHEMA/ROW_PARSE_PARTIAL/ROW_COUNT_MISMATCH/NONFINITE_VALUE/IDENTITY_MISMATCH를 구분한다. I/O·encoding·resource 오류도 명시한다. 여러 문제는 issues에 보존하고 진단 행번호를 표시한다. 실행 status는 자료 품질과 별개다. ERROR terminal에 정상 CSV가 있어도 분석 준비 통과로 표시하지 않는다.

원본·정상·거부 행 수는 완전 파싱 여부와 함께 표시하며, 파일을 읽지 못한 경우 null이다. 예상 row count/hash는 제공된 경우만 대조하고 임의의 기준을 만들지 않는다. 일부 정상행이 있어도 전체 품질을 VALID로 올리지 않는다. 품질 통과는 경제·실행 승인이 아니다.

## 하위호환·권한·롤백

기존 data-contract available은 profile 열람 가능 의미로 유지하고 신규 quality/analysis_ready 축을 추가한다. 기존 TradeArtifactContract schema 필드를 몰래 바꾸지 않고 같은 snapshot에서 기존 contract를 만드는 adapter를 추가한다. 품질은 별도 envelope다. 기존 원본/봉인 보고서·DB·6table·Bundle namespace 변경 없음.

입력 상한과 행별 오류 표시 상한을 명시하고 초과는 진단 실패로 반환한다. 실제 시장 연구/StageF/G0/G2/Holdout/자동채택/실주문/운영DB쓰기/merge/push 금지. UI 확인은 격리된 합성 입력 환경에서 수행한다.

롤백은 신규 quality adapter와 UI 연결만 되돌린다. 원본 evidence나 사용자 tmap WIP는 stage하지 않는다. 기존 API와 목록 loader 호환 회귀를 유지한다.

## 전체 진행률 관리

14화면군의 완료는 구현(I)·실제 연결(C)·검증(V) 세 조건을 모두 만족할 때만 센다. 개별 기반 코드 추가는 페이지 완료가 아니다. 이번 목표는 P03 및 P05 데이터 계약 부분 경로의 I/C/V를 확보하는 것이며 P03 전체·14페이지 전체 완료를 주장하지 않는다. 총량을 임의 백분율로 환산하지 않고 완료 Gate/화면군 수와 남은 범위를 기록한다.
