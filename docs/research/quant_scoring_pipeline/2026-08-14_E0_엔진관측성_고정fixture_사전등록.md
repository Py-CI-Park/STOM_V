## 1. 질문

동일한 짧은 기간·엔진 수에서 챔피언과 기존 G2 생성식의 첫 MQ 도달 여부와 마지막 protocol stage 차이가 반복되는가?

## 2. 고정 fixture

| 항목 | 값 |

| lane | tick |

전략 원문·DB·기간·엔진 수는 반복 사이에 변경하지 않는다.

## 3. 기록 필드

- run index, arm, job id, terminal status, elapsed seconds
- 마지막 job message와 idle time
- 결과 status와 metrics 존재 여부
- `/bt/result.process_diagnostics`의 event count, last checkpoint, last-by-source
- timeout/cancel 여부

대형 payload·거래 원문은 결과 문서에 복사하지 않는다.

> 실행 중 계약 명칭 교정: CLI 내부 `backtest_process_diagnostics`는 dashboard job
> record에서 canonical `process_diagnostics`로 정규화한다. E0 실행기는 API 정본 키만 읽는다.

## 4. 판정

| 판정 | 기준 |
|---|---|
| `REPRODUCED` | 같은 arm 3회가 first-MQ 도달 여부와 마지막 checkpoint에서 일치하고 두 arm 사이 차이가 존재 |
| `NO_DIFFERENCE` | 두 arm이 모두 같은 경로·상태로 종료 |
| `UNSTABLE` | 같은 arm 3회 결과가 불일치 |
| `BLOCKED_ENVIRONMENT` | 전략/서버/진단 응답을 고정할 수 없거나 안전 취소 실패 |

수익금·거래 수는 참고로도 후보 채택에 사용하지 않는다. 미완주 경과시간의 상대 비교로 조건식 품질을 주장하지 않는다.

## 5. 중지 조건

- 첫 job 취소가 실패해 프로세스가 남으면 즉시 전체 중지한다.
- 서버 build 또는 전략 존재 여부가 반복 중 달라지면 중지한다.
- 보호 DB를 직접 수정해야만 fixture를 복구할 수 있으면 실행하지 않는다.
- 본 사전등록을 바꾸려면 실행 전에 별도 정정 커밋을 만든다.
