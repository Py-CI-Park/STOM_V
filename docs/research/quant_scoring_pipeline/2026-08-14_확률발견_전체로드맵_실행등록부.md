## 3. E1 사전등록

### 3.1 고정 fixture

| 항목 | 값 |
|---|---|
| 기준선 | `Tick_B_902_905` + `Tick_S_902_905` |
| 생성식 | `G2_B_SEG_ONLY` + `Tick_S_902_905` |
| 기간 | `20231114~20231121` |
| 시간 | `090000~152900` |
| timeframe | tick |
| engines | 16 |
| 반복 | arm별 3회 |
| job timeout | 240초 |
| poll timeout | 300초 |

### 3.2 기록 필드

- worker source `BackEngine:{id}`
- 마지막 checkpoint
- 처리 tick 수와 code 수
- 마지막 code/index
- worker elapsed
- parent first-MQ checkpoint
- terminal status

원문 tick, 거래 payload, 전략 평가점수는 E1 증거에 복제하지 않는다.

### 3.3 판정

| 판정 | 조건 |
|---|---|
| `WORKER_BOTTLENECK_LOCALIZED` | 기준선 success 3/3, 생성식 timeout 3/3, 모든 생성 worker가 `engine_strategy_progress`에서 종료 |
| `WORKER_STAGE_MIXED` | 3×3 상태는 재현되지만 worker 마지막 stage가 혼합 |
| `UNSTABLE` | arm 내부 terminal status 불일치 |
| `BLOCKED_ENVIRONMENT` | 6행 미완성 또는 worker 증거 누락 |

E1은 수익 판정이 아니다. `WORKER_BOTTLENECK_LOCALIZED`여도 어떤 절이 원인이라는 인과 주장을 하지 않고, E2 비용·delta 실험만 허용한다.

## 4. 조건식 생성 성공 정의

| 수준 | 성공 정의 |
|---|---|
| 생성 성공 | canonical AST·정적 제한·비용 상한을 만족하는 새 소스가 생성됨 |
| 실행 성공 | 공식 엔진이 예산 안에 terminal 결과를 냄 |
| 연구 성공 | 외부 fold에서 ROPE·MDE·비용 스트레스 기준을 통과 |
| 최종 성공 | 미사용 전진 표본 단발 판정을 통과 |
| 실전 성공 | 별도 사람 승인 후 shadow/실거래 증거 확보 |

앞 단계 성공을 뒤 단계 성공으로 표현하지 않는다.
