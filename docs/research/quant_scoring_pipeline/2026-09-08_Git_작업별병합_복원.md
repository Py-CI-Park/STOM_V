## 새 관리 규칙

```text
loop 정본 ──┬────────── merge ──┬────────── merge
            └─ codex/작업A ────┘            │
                               └─ codex/작업B ────┘
```

1. 최신 로컬 loop에서 원자 작업 branch를 생성한다.
2. 구현·회귀·독립 검토·TASK_RECEIPT를 그 branch에 commit한다.
3. 깨끗한 통합 worktree의 loop에서 `git merge --no-ff <작업branch>`로 병합한다.
4. 병합과 코드 내용 검증, 통합 unit Gate를 기록한다. 검증 실패는 숨기지 않는다.
5. 다음 작업은 최신 loop에서 분기한다. 미완료 branch를 길게 이어 쌓지 않는다.
6. 한국어 commit 제목/본문, 명시적 파일 staging을 유지한다. push/강제 push/태그/원격 PR은 별도 요청 전 수행하지 않는다.

이전 구현 commit은 과거 부모 계보를 보존하므로 새 merge들의 second-parent에 기존 stack이 보인다. first-parent는 작업별 통합 흐름으로 정리된다. 기존 SHA 보존과 완전히 재작성한 그래프는 동시에 얻을 수 없으므로, 검증 식별자 보존을 우선했다.

## worktree와 검증

- 통합: C:/System_Trading/STOM/STOM_V.wt-pipeline-integration → loop/process-research-pipeline.
- 구현: C:/System_Trading/STOM/STOM_V.wt-process-research-restart → 원자 codex branch.

- 전체 검증 결과는 후속 TASK_RECEIPT에 최종 출력·exit code로 기록한다. 현재 이 문서 자체는 full unit PASS를 주장하지 않는다.
