## 2. 좋은 프로세스를 막는 5가지 (실측)

| # | 문제 | 증거 | 결과 |
|---:|---|---|---|
| 1 | **사람 검토 단계 부재** | analysis_card → dashboard 소비자 0 | AI 혼자 카드→프롬프트→생성 폐쇄 루프. 사람은 최종 성적만 봄 — 902/905 를 만든 "사람의 판단"이 루프에서 배제됨 |
| 2 | **루프 안에 표본 밖 검증 없음** | hypothesis 판정 = in-sample 델타 · holdout 슬라이스 세대별 재사용 | 세대를 거듭할수록 설계 구간에 과적합 — QSP13 이 측정한 선택 편의가 여기서도 축적 |
| 3 | **최상급 프롬프트 미배선** | p5_*.md 헤더: "기본 OFF — 어떤 경로에도 자동 주입되지 않는다" | 생성 품질이 구식 프롬프트/템플릿 변이 수준에 머묾 |
| 4 | **뇌(LLM) 불안정** | provider=batch 퇴화 · GPT OAuth 전멸 이력 | 조건식이 "논리 없이" 만들어짐 — 탐색과 같은 함정으로 회귀 |
| 5 | **두 시스템 분열** | QSP 지도 레인(라벨 v3·진입단위·워크포워드·편의 예산)과 brain 레인이 상호 미참조 | 각자 반쪽: 지도는 생성이 없고, 생성은 검증 규율이 없다 |

## 3. 배선 계획 (W1~W4) — 새로 만드는 게 아니라 잇는 것

| # | 배선 | 내용 | 대응 문제 |
|---:|---|---|---|
| **W1** | 카드 → 화면 | Analysis Card v2 를 대시보드 페이지로 (root_cause·mutation_axis·손실 거래 리플레이 링크). **사람이 mutation_axis 를 승인/수정하는 체크포인트** 신설 | 1 |
| **W2** | 프롬프트 교체 | p5 구조가설·단일변경 프롬프트 배선 + provider 를 안정 LLM 으로. 승인된 mutation_axis 만 {autopsy_summary} 로 주입 | 3, 4 |
| **W3** | 루프 내 워크포워드 | hypothesis 채택/기각을 walkforward.py 폴드 델타로. holdout 재사용 금지 | 2 |
| **W4** | 레인 통합 | 부검이 라벨 v3(봉투·도달시각)·진입 단위 교정·편의 예산(수정 횟수 원장)을 소비 | 5 |

## 4. 완성형 루프 (재평가 문서 §7 의 절차와 결합)

```
아이디어(사람) → 가설 문장 → 완성 조건식(매수절+매도규칙군, 절마다 이유)
   → 엔진 백테 → 부검(카드) → [W1: 사람+AI 공동 검토 화면 — 승인] 
   → [W2: 단일 변경 프롬프트] → 수정 1절(원장 기록, 상한 ~15회)
   → 재백테 → … → [W3: 워크포워드 게이트] → 감독 소액 실전
```

핵심: 사람은 매 세대 "무엇을 고칠지"의 승인자로 루프 안에 들어오고,
AI 는 부검 숫자와 프롬프트로 그 판단을 보좌하며, 표본 밖 게이트가 과적합 축적을 차단한다.
