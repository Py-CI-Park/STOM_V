## 2. 시가총액 분할 아이디어 판정

### 2.1 타당성

시가총액 분할 연구는 **타당하다**. STOM의 `시가총액` 단위는 억이며, Tick runtime과 매수시점 `B_시가총액`이 존재한다. 기존 코드에도 시간×시가총액 분석, 시총 band compiler, 초기 `<1000 / 1000~5000 / >=5000` 분류가 있다.

시총별로 다음이 구조적으로 달라질 수 있다.

- 체결 빈도와 호가 깊이
- 동일 거래대금 충격의 가격 탄력성
- VI·라운드피겨·갭 반응
- 돌파 유지시간
- 손절·익절·최대 보유시간
- 관심종목 편입 빈도와 표본 수

따라서 모든 종목에 같은 threshold를 적용하는 것보다 한 시총 층만 고정해 가설·변수·Exit를 연구하면 이질성이 줄고 원인 해석이 쉬워진다.

### 2.2 그대로 실행하면 생기는 위험

| 위험 | 설명 | 통제 |
|---|---|---|
| 표본 불균형 | 특정 band의 종목·거래일·신호가 부족할 수 있음 | 전략 생성 전 DB census |
| 경계 사후조정 | 성과를 보고 3000·5000·10000을 이동하면 과적합 | 경계 사전 봉인 |
| 다중검정 | 4 band×4 family×후보가 급증 | Family/band별 BH-FDR·trial ledger |
| 시총 변화 | 동일 종목이 날짜별로 다른 band가 될 수 있음 | 매수시점 `B_시가총액`으로 분류 |
| 유동성 혼입 | 시총 효과가 거래대금 효과일 수 있음 | Band 내부 유동성 기술통계·고정 gate |
| 생존편향 | 관심종목/DB 포함 종목만 존재 | Coverage 한계 표시, 전체시장 주장 금지 |
| 매우 큰 종목 희소성 | `>=10000`에서 opening signal이 적을 수 있음 | 최소 표본 미달 시 병합하지 않고 `INSUFFICIENT` |

### 2.3 사전등록할 Band

| Band ID | 시가총액(억) | 사용자 해석 | 경계 규칙 |
|---|---:|---|---|
| `MCAP_A_LT3000` | `< 3000` | 3000억 이하 | `시가총액 < 3000` |
| `MCAP_B_3000_5000` | `3000 <= x < 5000` | 3000~5000억 | 하한 포함·상한 제외 |
| `MCAP_C_5000_10000` | `5000 <= x < 10000` | 5000억~1조 | 하한 포함·상한 제외 |
| `MCAP_D_GE10000` | `>= 10000` | 1조 이상 | `시가총액 >= 10000` |

경계 누락·중복은 허용하지 않는다. Census에서 표본 부족이 확인돼도 성과를 본 뒤 경계를 이동하지 않는다. 해당 band는 `INSUFFICIENT_SAMPLE`로 남긴다.

| Gate | 최소 기준 |
|---|---:|

## 7. D3 — 시총별 Opening State Machine

### 7.1 기존 연구와 차이

기존 방식:

```text
현재값 threshold A AND B AND C → 즉시 진입
```

D3 방식:

```text
상태 진입 → 최소 지속 → 사건 발생 → 확인 → 제한시간 내 진입
```

### 7.2 Family

| Family ID | 상태전이 가설 | 최대 차원 |
|---|---|---:|
| `ABSORPTION_REVERSAL` | 매도/매수압력 증가에도 가격 진행 제한→반대 Flow 전환 | 4 |
| `FAILED_BREAKOUT_RETURN` | Range 돌파→유지 실패→Range 복귀→반대 확인 | 4 |
| `COMPRESSION_CONFIRMED_BREAKOUT` | 변동성 압축 지속→확장→돌파 유지→확인 | 4 |
| `FLOW_PRICE_DIVERGENCE` | 체결 Flow와 가격반응 불일치 지속→해소 방향 진입 | 3 |
| `OPENING_OVERREACTION_MEAN_REVERT` | 시초 과잉변동→거래대금 둔화→극값 미갱신→중앙 회귀 | 4 |

모든 Family는 4개 시총 band 중 하나만 선택해 별도 전략으로 생성한다. 한 전략에 여러 band branch를 넣지 않는다. 이로써 어떤 band의 Edge인지 직접 식별한다.

### 7.3 Band별 가설 조정 원칙

| Band | 연구 초점 | 금지 |
|---|---|---|
| `<3000` | VI·급격한 Flow·짧은 유지 확인 | 단순 고체결강도 추격 |
| `3000~5000` | 돌파 유지·호가압력 전환 | `<3000` threshold 복사 |
| `5000~10000` | 압축·완만한 Flow 지속·실패 돌파 | 소형주 거래대금 배수 복사 |
| `>=10000` | 낮은 탄력성·흡수·Flow/가격 괴리 | 희소 신호를 성공으로 과장 |

이는 방향 가설이며 임계값은 Census 분위수에서 사전 산출한다.

Budget 숫자는 Census와 estimator 결과에 따라 **감소만** 가능하다. 성과를 보고 증가시키지 않는다.

## 9. Negative Controls

각 Family×Band에 동일한 거래 기회를 가진 대조군을 둔다.

| Control | 목적 |
|---|---|
| Timestamp shuffle | 시간 순서 우연성 검사 |
| Symbol shuffle | 종목 선택 우연성 검사 |
| Direction inversion | 방향 가설 검증 |
| Event-offset random entry | 동일 이벤트 수의 무작위 진입 |
| Parameter-random baseline | QMC 후보 우위 확인 |

후보가 대조군의 median·상위 분위수를 넘지 못하면 공식엔진 확대를 중지한다.

## 10. 개발 Fold 설계

현재 존재하는 DB만 사용하며 모든 구간을 development로 명명한다.

### 10.1 Nested 구조

| 역할 | 목적 |
|---|---|
| Inner discovery folds | QMC ranking·top-k 선택 |
| Outer confirmation folds | 선택된 후보의 시기 이동 확인 |
| Stress folds | 월별 급등락·저유동성 구간 진단 |

구체적 날짜는 C0에서 band별 coverage를 계산한 뒤, 성과를 보지 않고 달력·표본 수 기준으로 봉인한다. D1/D2/Paired에 이미 사용한 월은 provenance에 표시하고 새 OOS로 부르지 않는다.

### 10.2 Fold 성공 기준

- official engine `success`
- source snapshot match
- 거래 20건 이상
- 평균수익률 > 0
- 총수익률 > 0
- MDD <= 15%
- Negative control 대비 우위
- Family×Band 다중검정 FDR 통과 또는 Bayesian `APPROVE`

### 10.3 Family×Band 최종 판정

| 판정 | 조건 |
|---|---|
| `INSUFFICIENT_SAMPLE` | Census/event/trade 하한 미달 |
| `DEVELOPMENT_REJECT` | Rule 기준 실패 |
| `DEVELOPMENT_RULE_PASS` | deterministic 기준 통과, posterior 미승인 |
| `BAYESIAN_APPROVE` | posterior 기준까지 통과 |
| `BO_ELIGIBLE` | Rule+posterior+control 모두 통과 |

## 11. D4 — 저차원 Bayesian Optimization

BO는 `BO_ELIGIBLE` Family×Band cell에만 적용한다.

| 항목 | 제한 |
|---|---|
| 변수 | 최대 3개 |
| Trial | 최대 8 |
| 초기 관측 | 사전등록 QMC 결과 |
| Acquisition | Expected Improvement |
| 평가 | 동일 outer folds |
