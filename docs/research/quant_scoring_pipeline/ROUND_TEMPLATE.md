# 라운드 표준 템플릿 — 자가 감사 프로토콜 (헌법 17항의 실행형)

> 신설 2026-08-11. **모든 라운드는 이 템플릿을 따른다.**
> 목적: "사용자가 물어봐야 오류가 나오는" 상태를 끝낸다.
> 사용자 지적으로 발견되는 결함은 **프로토콜 실패**로 PROGRAM_LEDGER 에 남긴다.

---

## 왜 이 템플릿인가 — 실수 유형 분석 (2026-08-11)

지금까지의 실수를 발견자별로 나누면 패턴이 있다:

| 발견자 | 실수 유형 | 예 |
|---|---|---|
| 자가·테스트 | **구현 수준** 결함 | 코호트 하한 누락, 분할 기준 오류, 단위 오류 |
| **사용자** | **프로세스 수준** 공백 | 도구 미사용, 관찰 단계 부재, 자산 누락, 오해 소지 보고 |

구현 결함은 테스트가 잡는다. **프로세스 공백은 묻지 않으면 안 보였다.**
이 템플릿의 §A(예상 질문)가 그 물음을 라운드마다 강제로 먼저 묻는 장치다.

## A. 사전 등록 문서에 반드시 넣을 것 (실행 전 커밋)

1. **가설** — 왜 통해야 하는가를 글로. 반대 가설도 함께.
2. **등록부 대조** — `PROGRAM_LEDGER.md` §1(계보)·§2(중복)·§3(닫힌 방향)과
   대조한 결과를 명시. "이 라운드는 X 와 어떻게 다른가"를 쓴다.
   겹치면 라운드를 열지 않는다.
3. **도구 선택 근거** — STOM/자체 도구 중 무엇을 왜 쓰고, 무엇을 왜 안 쓰는가.
   각 도구의 **고유 편향**(lookahead·생존·선택)과 이 라운드에서의 방어를 명시.
4. **합격선·격자·예산** — 사후 조정 금지. 절대 조건(후보 흑자) 포함(헌법 12항).
5. **판정 규칙** — 통과/부분/실패 각각의 다음 행동을 미리 정한다.
6. **예상 수치** — 실행 후 대조할 예측을 미리 적는다.

### A-1. 예상 질문 5 (사전 등록의 의무 섹션)

사용자가 물을 것을 먼저 묻고 먼저 답한다:

| # | 질문 | 답이 없으면 |
|---:|---|---|
| 1 | 이 라운드는 과거 어떤 연구와 겹치는가? | 라운드를 열지 않는다 |
| 2 | 왜 이 도구이고, 안 쓰는 도구는 왜 안 쓰는가? | §3 을 다시 쓴다 |
| 3 | 무엇이 잘못될 수 있고, 그것을 **어떻게 알아차리는가**? | 중단 조건을 정의한다 |
| 4 | 이 라운드가 실패하면 무엇이 남는가? | "이해가 남는 실패"가 아니면 재설계 |
| 4b | **"막혔다"고 보고하려면: 대안 자산을 실측했는가?** | 실측 없이 병목을 단정하지 않는다 (2026-08-12 실패: min 레인 가용성을 재지 않고 데이터 수집 재개를 병목으로 단정) |
| 5 | 이 결과를 사람에게 보고할 때 오해할 지점은? | 보고 문안에 선제 명시 |

## B. 실행 중 지킬 것

- **라운드 시작 시 대시보드를 재기동**하고 쓰는 엔드포인트를 확인한다
  (2026-08-12: 낡은 인스턴스가 페이지 31~34 를 404 로 서빙하고 있었다 — 코드는 정상).

- 학습/검증/확인 분할은 **거래일 달력**(`calendar_days`) 기준. 발굴·탐색은 학습만.
- 산출 아티팩트는 매 단계 저장(중단 대비). 엔진 실행은 백그라운드 + 로그.
- 예상과 다른 값이 나오면 **멈추고 원인 파악** — 좋은 쪽 서프라이즈도 의심한다.
