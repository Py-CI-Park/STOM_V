# 분석→수정 방법론 (v2 증보 초안 G1)

> 세그먼트 잔차표(백테 결과의 퀀트 분석)를 받았을 때 조건식을 고치는 **고정 절차**.
> 이 절차 밖의 임의 수정은 금지한다.

## 입력 계약

수정 요청은 반드시 다음 구조의 **수정 명세(revision spec)** 로 온다:

```yaml
target: QSP1_T_HIER_900_920_B          # 대상 조건식
leaf: [B3_5到10분, 중형_5000_10000]     # 리프 좌표(시간밴드 × 시총단계). 전역 수정이면 common
evidence:                               # 잔차 근거(세그먼트 분석 출력 그대로)
  n: 142                                # 표본 수
  avg_return: -0.31                     # 리프 평균 수익률
  vs_overall: -0.42                     # 전체 평균 대비
  threshold_hint: {var: 시가대비등락율, op: ">=", value: 2.0, pvalue: 0.011}
action: tighten                         # tighten(경계 조임) | loosen | drop_leaf | add_clause
change: "시가대비등락율 하한 0.0 → 2.0"   # 사람이 읽는 한 줄
```

## 수정 규칙

1. **명세에 적힌 리프만 수정한다.** 다른 리프·공통 그물·매도식은 글자 하나도 바꾸지 않는다.
2. 경계값은 threshold_hint(데이터구동 임계값)를 그대로 쓰거나, 분위수 경계로 반올림한다.
   임의의 "예쁜 숫자" 발명 금지.
3. 표본 부족 리프(n < 최소표본)는 수정하지 않는다 — evidence.n 을 반드시 확인한다.
4. drop_leaf 는 해당 리프의 진입을 `매수 = False` 로 막는 것이며 골격(분기 구조)은 남긴다
   (다음 라운드에서 되살릴 수 있어야 한다).
5. 한 라운드에 한 조건식당 수정 리프 수 ≤ 3 (변화 원인 추적 가능성 유지).
6. 수정 후 반드시 self_review_checklist.md 를 수행하고 diff 요약을 함께 출력한다.

## 출력 계약

```
[REVISION] target=... leaf=... action=... change=...
<수정된 전체 코드>
[DIFF-SUMMARY] 변경 절: N개 · 변경 리프: [...] · 골격 변경: 없음
```
