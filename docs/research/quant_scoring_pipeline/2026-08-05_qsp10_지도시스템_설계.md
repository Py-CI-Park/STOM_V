## 1. 라벨 v2 명세 — "도달 지도"

### 1.1 왜 터치 여부(이진)로는 부족한가 (사용자 지적의 수학적 근거)

이진 터치는 **크기 정보를 버린다**. +2% 터치 여부만 알면 +2.1%로 끝난 진입과 +8%로 간
진입이 같은 점수다. 손익비 거래의 기대값은:

```
기대값 = P(익절 먼저) × (TP − 비용) − P(손절 먼저) × (SL + 비용) + P(시간종료) × E[시간종료 수익]
```

이걸 **임의의 TP·SL·시간 T** 에 대해 계산하려면 세 가지가 필요하다:

| 필요량 | 라벨 |
|---|---|
| P(익절 먼저), P(손절 먼저) | **배리어 도달 시각** (먼저 닿은 쪽이 승자 — 순서 미상 소멸) |
| E[시간종료 수익] | **고정 h 수익률** (도달 없던 행만 걸러 평균 — 이미 보유) |
| 어느 TP 가 유리한가 | **다지평 MFE/MAE 봉투** (얼마나 올랐는지의 분포) |

### 1.2 라벨 v2 스키마 (기존 유지 + 신규)

| 구분 | 항목 | 명세 |
|---|---|---|
| 유지 | frA/frB 고정 h | tick {30,60,120,300,+**600**초, close} · min {5,10,30,60분, close} |
| **신규 ①** | **MFE/MAE 봉투** | 같은 체크포인트마다 그때까지의 최대상승·최대하락 — "30초까지 얼마, 1분까지 얼마, …" (사용자 제안 그대로) |
| **신규 ②** | **배리어 도달 시각** | 진입가(A기준: 매도호가1) 대비 **bid 경로**가 {+1, +2, +3, +5, −1, −2, −3}% 에 처음 닿은 시각(초). 미도달 = 상한값. **실현 가능 기준**(체결 가격)으로 기록 |
| 유지 | 스냅샷 변수·플래그·경과 | 그대로 |

용량: 신규 ~24열 × 26M행 × 4B ≈ +2.5GB (총 ~5GB). 처리 시간: 봉투는 이미 계산 중인
역방향 rolling 의 체크포인트 확장(저렴), 도달 시각은 그리드 위 searchsorted (저렴).
**전체 재빌드 tick ~30분 + min ~7분.**

### 1.3 이것으로 무엇이 되나 — 청산 규칙의 탁상 평가

배리어 도달 시각이 있으면 다음이 전부 **테이블 연산 1초**가 된다 (엔진 불필요):

- 임의의 (TP, SL, T) 조합의 승률·기대값·손익비 — **순서 미상 없이 정확히**
- 트레일링 근사: MFE 봉투로 "x% 도달 후 y% 반납" 정책의 상한 평가
- 시간대·변수 조건별 위 전부의 교차 분석

엔진은 **최종 확인**에만 쓴다 (전이 정합은 QA-1 로 이미 검증).

## 2. 지도 시스템 — 4계층 아키텍처

```
L0 라벨 원본   : 일별 parquet (레인별) — 라벨 v2. QA 스탬프·버전 태그
L1 집행 우주 뷰 : 표준 필터(관심종목·워밍업·가격밴드) 적용본 — 모든 분석의 유일한 입구
L2 통계 큐브   : 사전 집계 — (변수 분위 × 시간대 × 배리어/지평) 별 표본수·승률·기대값·봉투 분위
L3 조회 계층   : API + UI — 슬라이더 탐색(1초)·지형도 파셋·후보 저장·엔진 검증 연계
```

### 계층별 규율

| 계층 | 규율 |
|---|---|
| L0 | 홀드아웃 봉인(L2 규율) · 스키마 변경은 버전 태그(labels_v2) · QA 3종 통과 스탬프 필수 |
| L1 | **모든 분석은 L1 을 통해서만** — 집행 우주 미적용 분석 금지(신기루 방지, C1 교훈의 기계화) |
| L2 | 모든 칸에 표본수 병기 · FDR 문맥 표시 · 설계 구간만 |
| L3 | 화면 기본값 = **전 지평·전 배리어 패널** (단일 렌즈 분석이 구조적으로 불가능하게 — 이번 오류의 재발 방지 장치) · 후보 저장 시 근거(어느 칸) 자동 기록(계보) |

### 슬라이더 실시간 백테스트 (사용자 아이디어)

L1 이 메모리에 오르면(수 GB, 문제없음) 조건 필터링 = numpy 마스크 **0.3~1초**.
슬라이더 → 즉시 {표본수, 하루 기회, TP/SL 승률, 기대값, 손익비, 시간대 분포} 갱신.
"조건식 생성→백테스트 대기" 병목이 **최종 확인 1회**로 줄어든다.

## 3. 왜 이것이 조건식 개발 시스템에 도움이 되는가

| # | 효과 | 정량 |
|---:|---|---|
| 1 | **탐색 속도** | 조건 1개 평가 7~10분(엔진) → **1초** (탐색 단계) |
| 2 | **렌즈 오류 구조적 방지** | 전 지평·전 배리어가 기본 화면 — "5분 하나로 판정" 이 불가능해짐 |
| 3 | **손익비 설계 직접 지원** | TP/SL 조합의 기대값을 진입 조건과 **동시에** 탐색 — 매수/매도를 따로 연구하던 구조적 한계 해소 |
| 4 | **수렴 루프의 연료** | "필터 쌓기 25.9→37.0%" 같은 탐색을 사람+AI 가 실시간 반복 |
| 5 | **지식 축적** | 큐브·계보가 남아 다음 연구가 이전 지도 위에서 시작 (매번 처음부터 금지) |

## 4. ⚠️ 한계와 리스크 (정직)

| 리스크 | 대응 |
|---|---|
| 지도 ≠ 엔진 (동시보유·자본·체결 잔량) | 엔진 = 최종 심판 불변. 지도는 스크리닝 (전이 정합 QA-1 검증 완료) |
| 탐색 자유도 ↑ = 과최적 위험 ↑ | 설계 구간만 노출 · 홀드아웃 봉인 · 후보는 검증 사다리(고원·국면 절단) 통과 필수 · 표본수 상시 병기 |
| 배리어는 bid 경로 기준 근사 | 엔진 검증에서 잔차 실측 (QA-1 방식 재사용) |
| 슬라이더 과신 | 화면에 "탐색용 — 공식 아님" 권위 배지 상시 |

## 5. 구축 계획

| # | 마일스톤 | 내용 | 예상 |
|---:|---|---|---|
| 1 | 라벨 v2 | 봉투 체크포인트 + 배리어 도달 시각 — label_factory 확장(TDD) + 양 레인 재빌드 + QA 재실행 | 1세션 |
| 2 | L1/L2 | 집행 우주 뷰 표준화 + 통계 큐브 생성기 | 0.5세션 |
| 3 | 도달 지도 재판독 | 새 목표 함수(TP/SL 기대값)로 랭킹·포켓·수렴 탐색 — **손익분기 돌파 조합 탐색** | 1세션 |
| 4 | L3 슬라이더 UI | API + 페이지(전 지평 패널·표본수 병기·후보 저장) | 1~2세션 |
| 5 | 엔진 검증 | 상위 조합 → 배리어 매도식 렌더 → 공식 런 → 사다리 | 0.5세션+런 |
