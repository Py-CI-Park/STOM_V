## L-2026-08-12B — min 레인 3년치 침묵 실패 (시각 단위 결함 · 교정 완료)

**결함**: `_run_arm` 이 min 세션 시각을 lane 스펙 그대로 HHMM(900/1528)으로 CLI 에
넘겼다. CLI·엔진 계약은 tick/min 모두 **HHMMSS**(90000/152800)이고, min 쿼리가
내부에서 /100 한다(`GetBackloadCodeQuery`). 그 결과 `int(900/100)=9` →
`YYYYMMDD0009~0015` 라는 존재하지 않는 시각대를 질의했고, 종목 로더는 0건을
**조용히** 넘겼으며(`len(df)>0` 검사만), 잡은 "전략이 매수 신호를 내지 않음"
(no_trades)으로 위장됐다. **전략 5종 × 어떤 조합도 min 에서 돌 수 없는 상태**였다.

**은폐 기전 3겹**: ① 우리 배선의 단위 오류 ② 엔진의 침묵 빈 로딩(예외 아님)
③ back_count=0 을 오류가 아니라 no_trades 로 분류하는 CLI 메시지.
moneytop 질의는 스칼라 범위라 중간 날짜를 우연히 통과해(1,520행) 의심을 피해 갔다.

**교정**: `_session_hhmmss()` 경계 변환 + 회귀 테스트 6종
(`test_hof6_min_wiring.py` — HHMM 재유입 시 빈 구간이 되는 것 자체를 문서화 테스트로 고정).
교정 직후 진단 전략 109건 체결 확인.

**개선 제안(미실행·핵심 아님)**: back_count==0 은 no_trades 가 아니라 설정 오류로
분류돼야 한다 — STOM 코어 수정이라 별도 결정 사항으로 남긴다.

**확정 지식**: min 기준선(`Min_B/S_Study_251227`)은 설계 구간에서 **총 −37,544,661원·
승률 25%** 다. min 레인에 흑자 챔피언은 없다 — 탐색 전에 생성이 필요하다(W5 경고 재확인).

## L-2026-08-13 — 선택도(신호 밀도)는 독립적인 실행 가능성 제약이다

**발견**: G2~G4 에서 새 골격 3셀이 전부 엔진 타임아웃(챔피언 215초 vs 상한 9,060초
초과, 최narrow 변형 IQR 도 완주 추정 29시간). 원인은 수익성이 아니라 **신호 밀도**다.

| | 신호 밀도 | 비고 |
|---|---:|---|
| G2 골격(초소형 09:00~09:15) | **3,212초/일** | 하루 고유 종목 6 · 초당 동시 3 |
| 챔피언 | **0.43건/일** | 3,095만 행 중 361건 |
| 격차 | **약 7,469배** | |

**교훈 1 — 성곽 재해석**: HOF4 가 "성곽 구조"(실패 절 중앙값 6~7)라 부른 챔피언의
17절은 과최적의 흔적이 아니라 **거래 가능한 밀도로 좁히는 장치**였다. 절을 푸는 방향의
연구가 전부 실패한 것과 정합한다(닫힌 방향 11·12).

**교훈 2 — 채굴의 한계**: lift 는 **어디를 팔지**만 알려 주고 **얼마나 좁힐지**는
알려 주지 않는다. 생성 레인은 채굴(방향) + **선택 기구(밀도)** 둘 다 필요하다.

**한계 — 이번에 측정하지 못한 것**: 타임아웃 때문에 비용·체결·수익을 **하나도 재지
못했다**. "초소형 세그먼트가 실제로 수익이 나는가"는 여전히 미측정이다. 밀도를 낮춘
뒤에야 답할 수 있다.

**내 예측 오류**: 사전 등록 §7 에서 거래 수를 800~2,500 으로 예상했는데, 그 산수는
**동시보유 1~2**라는 챔피언의 성질을 무의식적으로 일반화한 것이었다. 광폭 조건에서는
동시보유가 폭발한다. 다음 사전 등록의 예상 수치에는 **동시보유 추정을 명시**한다.

**운영**: 완주 불가가 산술로 확정된 잡(진행률 5%/87분 → 29h)은 상한까지 기다리지 않고
중단하고 그 사실을 기록한다. 사후 완화가 아니라 같은 결과의 조기 확정이다.

## L-2026-08-13B — 타임아웃 팔이 원장을 오염시켰다 (자가 발견·정정 완료)

**무엇이 일어났나**: `run_g2_assemble.sync_ledger` 가 **완주 여부를 보지 않고**
게이트 결과만으로 적재해, 엔진 타임아웃 3팔이 지표 전부 결측(`None`)인 `REJECT`
3행으로 원장에 들어갔다(row 68~70). 원장이 **"측정해서 실패한 후보"와 "측정조차
못 한 후보"를 구별하지 못하게** 됐다 — 원장의 핵심 가치(무엇을 이미 해 봤는가)를
훼손하는 오염이다.

**같은 실행에서 나온 2차 결함**: 요약 출력이 `None` 포맷으로 크래시해
(`TypeError: unsupported format string passed to NoneType.__format__`)
배치가 exit 1 로 끝났다. 산출 JSON·원장은 이미 저장된 뒤였다.

**어떻게 발견했나**: 배치 실패 알림을 보고 로그를 확인하다 "원장 3행"이라는
출력과 내 결과 문서의 "원장 적재 없음" 기술이 **어긋난 것**을 발견했다.
프로토콜 체크리스트(원장 확인)가 아니라 **실패 알림 추적**이 잡았다 —
체크리스트가 "적재 없음"을 사실 확인 없이 통과시켰다는 뜻이다.

**정정**: ① 러너에 `status != "success"` 면 적재하지 않는 가드 + 회귀 테스트 3종
(timeout·error·cancelled) ② 포맷 방어(`or 0`) + 상태 열 출력 ③ append-only 원칙대로
원행을 남기고 정정 행 3건(row 71~73)을 덧붙임 ④ 결과 문서 §4 에 정정 표시.

**교훈 — 체크리스트 강화**: 종료 체크리스트 5(원장)는 "적재했는가"만 물었다.
**"문서에 쓴 원장 상태가 실제 원장과 일치하는가"** 를 묻도록 바꾼다.
문서와 DB 를 대조하지 않으면 기록이 조용히 갈라진다.
