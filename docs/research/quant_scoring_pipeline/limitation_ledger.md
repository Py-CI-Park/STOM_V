## L-2026-08-07 · 줄바꿈 변환이 무결성 표시를 조용히 깨뜨린다

**증상 2건 (같은 원인)**

1. 보고서 매니페스트(`qsp_report_manifest.json`)가 SHA256·바이트를 핀하는데,
   `core.autocrlf=true` 체크아웃이 HTML 을 CRLF 로 바꾸면 바이트가 벌어져
   대시보드가 조용히 `unverified` 로 표시한다(실측: 11,596B → 11,794B).
2. 연구 문서 사이드카(`research_docs_index.json`)도 문서 바이트로 지문을 만들어서,
   브랜치 전환·병합 뒤 `.md` 가 CRLF 로 되돌아오면 지문이 어긋난다.

**교정(부분)**

- 보고서 HTML·매니페스트는 `.gitattributes` 에 `eol=lf` 로 고정하고 전량 LF 정규화.
  회귀 테스트 6종(`test_qsp_report_manifest_integrity.py`)으로 재발을 막는다.
- 사이드카는 체크아웃 뒤 재생성한다(`python scripts/build_research_docs_index.py`).

**남은 한계**

연구 `.md` 문서 약 1,000건은 줄바꿈을 고정하지 않았다. 따라서 `core.autocrlf` 설정이
다른 머신·워크트리 사이에서 사이드카 지문이 어긋날 수 있고, 그때마다 재생성이
필요하다. 전 문서를 `eol=lf` 로 옮기는 것이 근본 해법이지만 약 1,000건의 해시가
한꺼번에 바뀌므로 별도 라운드로 다룬다.

**규칙**: 브랜치 전환·병합 직후에는 사이드카 검사를 돌리고, 어긋나면 재생성한다.
