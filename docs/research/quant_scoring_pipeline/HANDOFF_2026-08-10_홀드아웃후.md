## 2. ⬅ 다음 — 탐색이 아니라 설계

사전 등록(`361e6c78`) §4.2 가 정한 대로 **후보를 더 찾지 않는다.**

### 2.1 왜 더 찾으면 안 되는가 (산수)

```
설계 구간 최고 우위        +0.37%p
선택 편의                 −0.54 ~ −0.62%p
────────────────────────────────────
표본 밖 기대값             음수
```

같은 방식으로 후보를 더 찾으면 설계 성적만 오르고 편의도 함께 오른다.
**넘으려면 설계 우위가 +0.7%p 이상이어야 한다.** 지금까지 최고가 +0.37%p 다.

### 2.2 남은 길 — A + C 를 권고

| 방향 | 내용 | 상태 |
|---|---|---|
| **A. 탐색 폭 축소** | 라운드당 사전 등록 격자 **≤ 10셀** · 워크포워드 내장 · 판정 시 편의 차감 | 설계 필요 |
| B. 효과 크기 키우기 | 구조가 다른 개선(진입 우주 교체·다중 시간대) | QSP1~13·W4~W9 전부 실패한 방향 |
| **C. 시간을 데이터로** | 신규 거래일 상시 축적 → **매번 새 표본**으로 검증 | 인프라 있음(페이지 29) |

**C 가 유일하게 편의가 쌓일 수 없는 구조다.** 인간 트레이더가 이기는 이유이기도 하다
(작은 가설 공간 × 항상 새로운 표본).

### 2.3 A 를 설계할 때 넣을 것

```
라운드 시작
  1. 가설을 글로 쓴다(왜 이것이 통해야 하는가)
  2. 격자를 ≤ 10셀로 사전 등록·커밋
  3. 설계 구간을 3분할해 롤링 워크포워드로 잰다 ← 편의를 라운드 안에서 측정
  4. 판정 = 워크포워드 표본밖 평균 (설계 최고값이 아니다)
  5. 원장 등재. 표본밖 평균이 음수면 그 방향은 닫는다
```

### 2.4 C 를 켤 때 넣을 것

- 신규 거래일이 N일 쌓일 때마다 **기존 후보 전부를 그 N일로만** 재판정
- 그 N일은 한 번 쓰면 소진 — 다음 검증은 그다음 N일
- 페이지 29(상설화)가 이미 백필·재검증 계획을 표시한다
