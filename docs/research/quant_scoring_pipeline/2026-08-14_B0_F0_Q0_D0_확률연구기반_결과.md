## 2. 실제 G2 조건식 실API 확인

`G2_B_SEG_ONLY`를 DB에서 읽거나 수정하지 않고 기존 G1 seed로 다시 렌더해 입력했다.

| 도구 | 결과 | 해석 |
|---|---|---|
| Bayesian | API `ok=true`, posterior와 receipt 반환 | 통계 경계 계산만 가능 |

## 3. 적대적 감사와 교정

### 통계 기반

| 지적 | 교정 |
|---|---|
| ROPE 경계의 false approval 누락 | `true_rate <= rope_lower`로 교정 |
| 극단 QMC 범위가 비유한/정밀도 초과 값을 만들 수 있음 | 사전 span·사후 finite/bounds 검증과 명시 오류 추가 |

### AST·D0

| 지적 | 교정 |
|---|---|
| `else`를 unknown 처리 | 명시 clause로 지원 |
| 변수 lookback이 제한을 우회 | 단순 상수 해석, 표현식은 unresolved 위반 |
| 다중행 guard 일부만 복제 | 들여쓰기 sibling/dedent 전체 범위 사용 |
| shuffle이 실제로 안 바뀌어도 성공 | source/canonical/hash 변화 없으면 실패 |
| 실제 `pass`, indented `self.Buy()`가 unknown | 안전 statement로 분류하고 function whitelist 적용 |

### UX/API

| 지적 | 교정 |
|---|---|
| 네 POST body가 strict backend schema와 불일치 | counts/limits/kind/budget/operator shape 통일 |
| posterior/Pareto 응답 경로 불일치 | `posterior.*`, `pareto.entries` 사용 |
| Bayesian 기본 threshold 합이 유효 gap을 만들지 못함 | approve 0.95, reject 0.10으로 교정 |

## 4. 기능 경계

완료된 것은 **연구 기반과 수동 UX**다. 다음을 의미하지 않는다.

- 새 조건식이 수익을 낸다는 증거
- QMC 후보가 엔진에서 실행 가능하다는 증거
- Bayesian `APPROVE`가 전략 승인이라는 의미
- D0가 diffusion 모델이라는 주장
- 최종 OOS나 실전 적격성

Bayesian optimization의 엔진 목적함수 연결, MAP-Elites 실제 fitness 평가, 신경망 diffusion은 E0 실행 경계와 새 판정 표본이 확보되기 전까지 차단한다.
