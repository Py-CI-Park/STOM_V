## 1. 한 문장 판정

### S2. 결과 진실성과 권위 경계가 강하다

- 현재 G0/G1 판정은 Platform 28/28와 Development 0/7을 분리한다.

- Analysis Card v2/V3

- Counterfactual·recovery insight

### S4. 통계 안전판이 일부 잘 설계됐다

```text
AND CI가 0을 포함하지 않음
AND prereg axis 또는 BH-FDR q<=alpha
```

validation/OOS 결과는 actionable directive가 될 수 없고 descriptive로만 남는다.

### S5. UI 기본 품질은 높다

- Truth Bar와 Mission Control이 실행 성공과 경제 실패를 분리한다.
- Current/Historical 권위가 분리됐다.
- Result 화면은 source capability를 명시한다.
- 빈 상태·오류·NO_TRADES를 구분한다.
- 실제 브라우저 console warn/error 0이었다.
- 키보드/반응형 검증 기록도 존재한다.

## 6. 핵심 결함·부족한 부분

### P0-01. AnalysisBundle이 “단일 결과 정본” 역할을 아직 완수하지 못한다

현재 bundle에서 다음은 항상 비어 있다.

```text
preregistration = NOT_OBSERVED
parent_id       = null
git_commit      = null
episodes        = NOT_RUN
counterfactual  = NOT_RUN
robustness      = NOT_RUN
persistence     = none
```

`full_analysis`가 계산한 `stats`도 bundle attribution에 포함되지 않는다. Monte Carlo는 별도 endpoint라 bundle robustness에 들어가지 않는다. TradePath 분석과 AnalysisCardV3도 bundle에 연결되지 않는다.

영향: 한 결과를 다시 열었을 때 “무엇을 계산했고 무엇을 계산하지 않았는가”를 한 객체로 증명할 수 없다.

### P0-02. CSV 데이터 품질 오류가 일반 결과 화면에서는 빈 결과로 흡수될 수 있다

`load_trades_csv`는 다음을 모두 `[]`로 반환한다.

- 파일 없음
- 필수 컬럼 없음
- 인코딩/IO 오류
- 전체 행 파싱 실패
- 실제 거래 0건

별도 `TradeArtifactContract`는 54/37/custom schema와 B/S/R 컬럼 availability를 잘 진단하지만 `/bt/result`와 `full_analysis`의 선행 Gate가 아니다.

영향: malformed artifact와 진짜 NO_TRADES가 일부 소비 경로에서 같은 빈 분석으로 보일 수 있다. 데이터마이닝에서 가장 위험한 silent failure다.

### P0-03. 성공 결과 Golden E2E가 현재 설치에서 재현되지 않는다

현재 webbt job 35개는 전부 cancelled이고 CSV는 0개다. 성공 결과 fixture endpoint는 있으나 V4 UI가 사용자가 선택할 수 있는 immutable golden result로 노출하지 않는다.

영향: 백테스트를 오래 실행하지 않고는 Result→Bundle→Card→Episode→Hypothesis UI를 종단 검증할 수 없다. 분석 코드의 회귀가 unit test 사이에서만 검출된다.

### P0-04. `holdout` 용어와 권위가 충돌한다

현재 프로젝트에는 최소 세 의미가 공존한다.

| 이름 | 실제 의미 |
|---|---|
| Frozen Holdout | 현재 연구에서 `SEALED_NOT_TOUCHED` |
| graduation holdout | 자율 루프 토글 기반 최근 기간 분할 |
| loss-region holdout | 연속 1회 run을 split한 내부 검증 구간, 독립 OOS 아님 |

실제 백테스트 화면은 `홀드아웃 20251201~20260227`을 표시하면서 Mission Control은 Holdout 차단을 표시한다. 주석에는 독립 OOS가 아니라고 적혀 있지만 UI 용어는 같다.

영향: 사용자가 내부 validation split을 Frozen Holdout 또는 OOS 증거로 오해할 수 있다.

### P1-05. Analysis Card v2와 v3가 다른 세계에 있다

| 소비자 | 실제 계약 |
|---|---|
| Dashboard 페이지 25 | Analysis Card v2 API |
| 자동 루프 feedback | AnalysisCardV3 in-memory 객체 |
| 문서 renderer | v3 Markdown helper |
| v3 durable API/store | 없음 |

v3는 코드 주석에서 “영속 카드”라고 불리지만 `card_v3_to_json`의 실제 persistence consumer가 없다. Dashboard는 v2를 보여주므로 사용자가 자동 루프가 읽은 정확한 v3 content hash와 directive를 볼 수 없다.

### P1-06. `analysis_snapshot` persistence가 고립돼 있다

`persist_analysis_bundle`은 SQLite `analysis_snapshots/analysis_rows`를 만들 수 있지만 API route는 의도적으로 `persisted=false`만 반환한다. 별도 조회 API·catalog·AnalysisBundle 연결이 없다.

영향: correlation/edge/feature importance 결과를 누적·비교·재현하는 데이터마트가 실사용되지 않는다.

### P1-07. 프로그램 단위 Fold/Control 분석이 범용화되지 않았다

RES-02/03의 7후보×4Fold 분석은 매우 잘 수행됐지만 전용 스크립트와 전용 JSON schema다. 일반 job bundle을 입력으로 다음을 만드는 범용 aggregator가 없다.

- candidate×Fold matrix
- paired parent/child delta
- negative controls
- multiplicity family
- FDR/posterior
- power/sample sufficiency
- stop/adoption decision

새 연구마다 집계 스크립트와 문서를 다시 만드는 구조다.

### P1-08. Research Tools는 수동 계산기이며 파이프라인이 아니다

Bayesian·AST·QMC·denoise 4개 도구는 모두:

```text
manual_only = true
persistence = none
authority = no_adoption
```

도구의 계산은 좋지만 어떤 AnalysisBundle·Hypothesis·Preregistration에 사용됐는지 연결되지 않는다.

### P1-09. 통계 계약이 분석 계층마다 다르다

- `full_analysis` 통계 검정은 요일/30분 slot Welch + BH-FDR에 한정된다.
- insights는 효과크기·CI 없이 규칙 문장으로 생성되는 항목이 많다.
- AnalysisCardV3는 더 엄격한 sample/CI/FDR Gate를 쓴다.
- Loss pocket은 별도의 FDR 계약을 쓴다.
- 프로그램 Fold 분석은 전용 Development Rule을 쓴다.

영향: 같은 결과가 어느 화면/도구를 거치느냐에 따라 “actionable” 기준이 달라진다.

### P1-10. 분석→가설→다음 실험 연결이 옵트인·분절 상태다

기본 autopsy feedback은 ON이지만 다음은 전역 기본 OFF다.

- segment feedback
- feature importance feedback
- hypothesis tracking
- AnalysisCardV3
- typed feedback v2

연구 preset은 주요 feedback과 card v3를 켜지만 typed feedback v2는 포함하지 않아 legacy free-text directive 경로를 사용한다. 실패는 대부분 로그 후 흡수되며 Dashboard에서 “이번 세대에 어떤 분석이 실제 소비됐는가”를 완전하게 증명하기 어렵다.

### P1-11. UX가 기능 중심으로 분산돼 있다

분석 관련 화면이 다음에 흩어져 있다.

```text
Backtest Result
QSP7 Trade Path
Analysis Card 페이지 25
Research Live / 채점·부검
Program Cockpit
Family Fold Heatmap
Research Tools
History
Reports
Replay
```

한 사용자가 “이 결과에서 무엇을 배웠고, 어떤 가설을 만들며, 다음 실험은 무엇인가”를 한 흐름으로 따라가기 어렵다.

### P1-12. 최신 연구와 과거 프로그램이 같은 Live 화면에서 병렬 노출된다

Mission Control은 최신 `<3000>` G0/G1 0/7 STOP을 표시하지만 아래 Program Cockpit은 과거 D1/D2/PAIRED 프로그램을 동시에 표시한다. 둘 다 정직한 과거 자료지만 현재 프로그램 선택·supersedes 관계가 충분히 강하지 않다.
