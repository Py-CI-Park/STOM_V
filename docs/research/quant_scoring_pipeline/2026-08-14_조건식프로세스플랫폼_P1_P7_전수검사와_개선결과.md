## 2. P1 Source·runtime provenance

### 발견

1. 생성 source hash와 실제 mutable strategy name이 약하게 연결됨
2. Tick 후보 catalog에 minute-only `분봉*` 표현이 노출될 수 있음
3. Job submit 뒤 strategy DB가 바뀌면 다른 source가 실행될 수 있음

### 개선

- Tick/min catalog와 B_* runtime expression을 lane별 분리
- Tick에서 `분봉시가/고가/저가` fail-closed
- Job submit 즉시 per-job immutable strategy DB 생성
- Buy/sell exact source를 snapshot row에 다시 삽입
- UTF-8 SHA-256 검증 후에만 subprocess 시작
- Missing source는 name-only fallback 없이 거부

## 3. P2 Data·artifact

### 발견

1. 14자리 tick index를 minute divisor로 정규화해 hour-suffixed 날짜 표시
2. 일부 relative CSV가 openable 판정과 실제 reader에서 다르게 해석됨
3. Missing CSV를 zero-PnL portfolio 입력으로 처리 가능

### 개선

- 12/14자리 index 모두 앞 8자리 YYYYMMDD로 정규화
- 모든 job/gen CSV read를 safe artifact resolver로 통일
- Missing/unreadable CSV는 index·reason과 함께 전체 portfolio 실패
- 명시적 `no_trades` terminal만 typed empty input 허용

## 6. P5 Statistics

### 발견

1. 4/6 fold rule-pass가 Bayesian approve처럼 보일 수 있음
2. Weekday/slot 다중 p-value를 raw p<0.05로 표시
3. Bayesian client/backend 최대 표본 경계 불일치

### 개선

- 4/6을 `DEVELOPMENT_RULE_PASS`로 명명하고 posterior underpowered 분리
- Weekday/slot에 Benjamini-Hochberg q-value·`fdr_pass` 추가
- UI insight는 raw p가 아닌 FDR만 사용
- Bayesian 합산 observations·max_sample 100,000 경계 통일

## 7. P6 UX/API read integrity

## 8. P7 Authority·process

### 발견

1. Decision write가 historical P5 fallback 후보를 기록할 수 있음
2. V4 final approval이 candidate identity를 전송하지 않음
3. Promotion gate probe가 official history를 오염
4. Legacy shell에 obsolete final approval payload 잔존

### 개선

- 모든 decision/final approval에 current candidate identity 의무화

- Historical P5 fallback 제거
- V4 payload에 `approvalBinding.candidate_identity`
- Promotion probe는 pure compare, explicit POST persistence만 aggregate 1건
- Legacy final approval affordance 제거
- 자동채택·실거래 권한은 추가하지 않음
