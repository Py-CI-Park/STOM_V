## 2. Phase A — 연구 종결과 증거 교정

### 변경

- 챔피언을 실전 후보에서 `SHADOW_BASELINE`과 엔진 양성 대조군으로 강등했다.
- 유일한 119일 홀드아웃의 `-8,116원`, 건당 `-0.03%`, 양수 국면 `1/4`, MDD `12.91`을 최상위 증거로 고정했다.
- 선택 편의를 “해결”이 아니라 “일부 검출·완화”로 교정했다.
- 비단조 절 상호작용에 부적합한 E2 이분 탐색을 중지했다.
- G1 lift는 lookahead 라벨이고 G2~G5는 손익 판정 전 미완주였음을 분리했다.
- INDEX와 PROGRAM_LEDGER의 다음 단계를 `E0 엔진 관측성`으로 통일했다.

### 결과

같은 역사 데이터 대규모 탐색, 챔피언 자본 투입, G 레인 반복이 현행 계획에서 차단됐다. 신규 데이터는 발견 수단이 아니라 최종 판정 자원으로만 분류됐다.

## 3. Phase B — 대시보드 정확성

### 변경

1. V4 셸에서 선택한 `baseUrl`을 페이지 25~34에 전파했다.
2. 각 패널의 root-relative fetch를 선택 backend 기반 URL로 통일했다.
3. 페이지 29의 `design_v4` 강제를 제거하고 controller의 `design_v5` 정본 기본값을 사용했다.
4. `claude_direct`를 무조건 connected/effective로 표시하지 않게 했다. 실제 runtime evidence가 없으면 unknown/not effective다.
5. 페이지 32를 OOS 생존 화면이 아닌 `국소 파라미터 민감도`로 교정했다.
6. study/source/split/window/hash/created_at provenance를 존재할 때만 표시하고, 명시적 OOS verdict 없이는 채택 문구를 내보내지 않는다.
7. JSX 변경 후 정본 bundle과 manifest를 재생성했다.

### 결과

하나의 화면이 서로 다른 backend·artifact의 데이터를 섞거나 국소 민감도를 OOS 증거로 과장하던 P0 결함이 제거됐다.

## 4. Phase D — E0 엔진 관측성

### 변경

- 기본 진단 OFF에서는 기존 `tq.get()` blocking 계약을 그대로 유지한다.
- `STOM_CLI_BACKTEST_PROTOCOL_DIAG=1`에서만 첫 MQ 대기 중 5초 주기 heartbeat를 발생시킨다.
- heartbeat는 elapsed time, engine/subtotal 수, 입력 행·거래일 수, avgtime, 전략 식별자를 scalar로 기록한다.
- 첫 메시지 수신 시 대형 payload 대신 bounded `message_kind`만 기록한다.
- 기존 checkpoint 이름과 queue tuple shape를 유지했다.

### 결과

생성식 정지를 특정 절의 의미 문제로 추측하지 않고, 엔진 단계·입력 작업량·첫 MQ 도달 여부로 관측할 수 있게 됐다. 실제 E0 대조 실행은 사전등록된 fixture와 엔진 환경이 준비된 별도 라운드에서 수행하며, 본 변경은 관측 계약까지다.

## 5. Phase E — 확률적 판정 기반

### 5.1 이동 블록 Monte Carlo

기존 shuffle과 iid bootstrap을 보존하면서 `moving_block`을 추가했다.

| 방법 | 질문 | 최종손익 |
|---|---|---|
| shuffle | 같은 날의 순서가 달랐다면 MDD는? | 항상 동일 |
| bootstrap | 같은 일별 분포에서 다시 뽑았다면? | 분포 |
| moving_block | 연속 거래일 의존성과 국면 군집을 보존했다면? | 분포 |

응답과 UI에 method, seed, n, block length, ruin threshold를 표시한다. `block_length=1`은 동일 seed에서 기존 bootstrap과 정합한다. 미지원 method와 1 미만 block length는 명시적으로 거부한다.

### 5.2 공통 ReviewContext

원장 행을 선택하면 다음 식별자를 보존한다.

```text
candidate_id, baseline_id, artifact_id, study_id,
lane, split, source_hash
```

이 컨텍스트를 검정력, 국소 민감도, 조건식 비교, 거래짝 패널에 전달한다. 값이 없는 필드는 만들지 않는다. 조건식 이름 목록에 실제 candidate/baseline이 있을 때만 diff 기본값으로 사용한다.

## 7. Git 계보

현재 연구 브랜치는 `loop/process-research-pipeline`의 순수 후손이다. squash/rebase하지 않고 다음 순서를 사용한다.

1. 현재 연구 브랜치 ref를 원격에 게시한다.
2. 원격 HEAD와 로컬 HEAD 일치를 확인한다.
3. 연구 브랜치에서 `loop/process-research-pipeline`로 direct PR을 연다.
4. merge commit으로 기존 topic branch 선을 보존한다.
5. 통합 검증은 대량 untracked 사용자 자료가 없는 clean worktree/clone에서 수행한다.

현재 작업트리의 `.omo/`, `.gjc/`, `artifacts/` 등 기존 untracked 자료는 수정·삭제·stash하지 않았다.
