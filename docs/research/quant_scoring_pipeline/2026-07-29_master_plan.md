## 1. 핵심 연구 4체인 (사용자 강조 — 이 연구의 몸통)

> 체인 하나라도 약하면 솔버 전체가 약하다. 각 체인을 **독립 연구 질문(RQ)·측정 지표·개선 방법**으로
> 관리하고, 페이즈 리뷰마다 체인별 상태를 갱신한다.

### C1. 백테스트를 "잘" 실행한다

- **정의**: 조건식 쌍을 넣으면 정지·왜곡 없이, 예측 가능한 시간에, 재현 가능하게 완주.
- **현재**: 결함 A/B/C/E/F 수정으로 안정화. 잔여 리스크 = min 풀세션(09:00~15:19) 장기간
  실행의 소요시간·메모리 미실측.
- **RQ-C1**: ① min 풀세션 11개월의 쌍당 소요시간은? ② wide-net(거래 수천 건)에서
  엔진 병목이 생기는가? ③ 동일 쌍 재실행 재현성(바이트 동일)?
- **지표**: 쌍당 wall-clock · 완주율 100% · 재실행 diff 0.
- **개선 후보**: 엔진수 조정(32↔16) · 기간 분할 실행 · prepare 캐시 재사용.

### C2. 결과를 "잘" 내준다 (라벨 데이터 품질)

- **정의**: 거래 1건 = 라벨(수익률) 1개 + 설명변수(매수시점 상태) 벡터. 분석이 요구하는
  변수가 결측·왜곡 없이 담겨야 한다.
- **현재**: 원시 B_\*14. 보유시간 단위 결함은 v5.13.2에서 교정.
- **RQ-C2**: ① 원시 14개로 재구성 가능한 파생변수는 몇 개이고 무엇이 불가능한가?
  ② 백테 중 산출(엔진 결과부 컬럼 추가)이 성능에 주는 부담은? ③ 파생변수의 결측률은?
- **지표**: 파생변수 수(목표 +15~20) · 결측률 <5% · 컬럼 추가 후 기존 소비자 회귀 0.
- **개선 방법**: 2계층 — ⓐ 재구성 가능분은 분석기에서 오프라인 파생(엔진 무수정)
  ⓑ 불가능분(누적 수급·호가 심도 등)만 엔진 결과부 additive 컬럼. 회귀 테스트 필수.

### C3. 결과를 바탕으로 퀀트 분석을 "잘" 한다

- **정의**: 라벨 데이터에서 "어느 리프(시간×시총×변수구간)가 손실을 만드는가"를
  통계적으로 신뢰 가능하게, 조건식 수정으로 번역 가능한 형태로 뽑는다.
- **현재**: segment.py가 cross-tab·분위수·t검정(FDR) 보유. 배치 미연결·컬럼 고정.
- **RQ-C3**: ① 표본 몇 건부터 리프 판정을 신뢰할 수 있나(현 min_samples=5는 과소?)
  ② 다중비교 보정 후에도 살아남는 변별 변수는? ③ 리프 간 상호작용(시간×시총 교차)을
  어디까지 봐야 하나? ④ 분석 출력→절 수정의 번역 규칙은 무엇인가?
- **지표**: 손실 세그먼트 검출의 재현성(부트스트랩) · 제안 절의 재백테 개선 적중률 >50%.
- **개선 방법**: 배치 채점기에 세그먼트 부검 연결 · 신규 컬럼 자동 편입 · 리프 최소표본
  기준 연구 · "리프→절" 번역기.

### C4. 조건식을 "잘" 생성한다

- **정의**: 분석 결과(+규칙 SSOT+이전 조건식+예제)를 받아 **요청된 수정만** 정확히 반영된
  후보를, 서로 다른 가설로 N개 생성하고, 스스로 검토해 확실한 것만 내보낸다.
- **현재**: 프롬프트 SSOT 8파일(1,321줄)에 분석→수정 방법론·자가검토·다후보 규약·계층
  보존 규칙 부재. 의도-일치 게이트 없음.
- **RQ-C4**: ① 의도-일치를 기계 판정할 수 있는 diff 규약은?(예: "리프 (B3,중형)의
  시가대비등락율 하한만 변경" → AST diff로 검증) ② 다후보의 가설 다양성을 어떻게
  강제하나? ③ 생성 주체(agent/LLM)별 품질 차이는?
- **지표**: 의도-불일치 검출률(주입 실험) · 후보 preflight 통과율 100% · 세대당 개선 기여.
- **개선 방법**: 프롬프트 증보 4종 · 의도-일치 게이트(요청 명세 ↔ AST diff 대조) ·
  `generated_by` 원장 기록 · agent provider 정식화.

## 2. 수렴 규격 (솔버 허용오차)

| 항목 | 정의 |
|---|---|
| 잔차 | Σ(손실 세그먼트 손익) ÷ Σ\|전체 손익\| |
| 목적함수 | `calmar × uptrend_r2 × gate` (인간 벤치마크 지향: 우상향·저MDD·수익) |
| 수렴 | 3라운드 연속 개선 <2% **AND** 홀드아웃 동반 개선 |
| 발산 경보 | 거래수 시드 대비 70%↓ · 성능 진동 · 설계↑/홀드아웃↓ 괴리 |
| 정지 | 수렴 or 발산 or 라운드 예산 소진 — 어느 쪽이든 **이유와 함께 답 제출** |
| "답" 규격 | 최종 조건식 + 리프별 수정 근거(세그먼트 통계) + 검증 성적 + 한계 |

## 3. 페이즈 계획 (각 페이즈 = 개발 + UX/UI + **검토 게이트**)

> 게이트마다 스코어카드(기능30·검증25·UI20·신뢰15·문서10) 작성, **90점 미만 진행 금지**.
> 발견한 문제·한계는 즉시 `limitation_ledger.md`에 기록 — 원장이 곧 개선 백로그다.

### P0-a. 시드 스모크 (C1 실측)

- 작업: 4쌍 × 설계 구간(20250407~20260227) 배치. tick(90000~93000)·min(풀세션 151900) 분리 config.
- 산출: run 2개(`*_tick_qsp1-smoke-r0`, `*_min_qsp1-smoke-r0`) · 쌍별 거래수/소요시간/라벨 분포.
- **R0 리뷰 질문**: HIER가 CSS보다 유의미하게 많이 거래하는가(그물 설계 검증)? min 풀세션
  소요는 감내 가능한가? 라벨 분포에 즉시 보이는 왜곡은?
- UX/UI: 결과 라이브러리에서 QSP1 run 4쌍 열람 확인.

### P0-b. 생성 프롬프트 감사·증보 (C4 기반)

- 작업: SSOT 8파일 전수 감사 → 증보 4종 초안(분석→수정 방법론 / 자가검토 체크리스트 /
  다후보 규약 / 계층 보존 규칙) → v2 디렉토리로 버전링(v1 불변).
- **게이트**: 증보 전/후 동일 과제 생성 비교 1회(구조 보존·의도 반영 여부).

### P1. 라벨 데이터셋 강화 (C2·C3)

- 작업: ⓐ 오프라인 파생 계산기(재구성 가능분: 총호가매수비율·전일종가·순매수금액·폭발배수 등)
  ⓑ 엔진 결과부 additive 컬럼(불가능분 — 회귀 테스트 동반) ⓒ segment.py 컬럼 자동 편입
  ⓓ 배치 채점기에 세그먼트 부검 연결(쌍마다 잔차 리포트).
- 산출: 표준 라벨셋(거래×변수 행렬) + 리프 잔차표.
- **R1 리뷰**: 파생변수 변별력 실측(Cohen's d·t검정) — 안 가르는 변수는 교체. 최소표본 기준 결정.
- UX/UI: **라벨셋 탐색기** — 리프(시간×시총) 히트맵, 셀 클릭→거래 목록→변수 분포.

### P2. 분석→수정 번역 + 검증 게이트 (C3→C4)

- 작업: ⓐ "리프→절 제안" 번역기(잔차표 상위 리프 → 경계 수정안) ⓑ **의도-일치 게이트**
  (수정 명세 ↔ 생성물 AST diff 대조 → preflight → 재백테 필수) ⓒ agent provider 정식화
  (`generated_by` 기록·개입 가이드라인 문서·설정 UI).
- **R2 리뷰**: 오류 주입 실험(엉뚱한 수정 N건)으로 게이트 검출률 측정. 제안 적중률 실측.
- UX/UI: 제안 카드(리프→절→예상효과) + 적용 diff 뷰 + 설정 탭 생성 주체 카드.

### P3. 다후보 라운드 + 수렴 판정기

- 작업: 라운드당 N후보(서로 다른 가설 강제) → 배치 평가 → 전원 세그먼트 분석 →
  베스트 선택+교훈 합성 → 수렴/발산 판정(§2 규격 구현).
- **R3 리뷰**: 수렴 속도·발산 오경보율 → ε·경보 임계 튜닝.
- UX/UI: 라운드 보드(후보 N개 성적 나란히) + 수렴 상태 배지.

### P4. 시각화 고도화

- 작업: **잔차 감소 곡선**(구조해석 residual plot) · 사이클 애니메이션(생성→백테→분석→
  제안→적용이 도는 벨트) · 리프 히트맵의 라운드 간 비교.
- **R4 리뷰**: "화면만 보고 수렴 중인지 아는가" 사용성 검사(실브라우저).

### P5. 수렴 캠페인 + 최종 보고서

- 작업: 4시드 각각 수렴/발산/예산까지 완주 → 시드별 "답" 제출.
- **최종 보고서 규격**: ① 4체인별 연구 결과(RQ 답변) ② 시드별 수렴 곡선과 답
  ③ 한계 원장 총정리 ④ 파이프라인이 답을 "내는/못 내는" 조건 ⑤ QSP2 제언.
  자가완결 HTML 병행(디자인 정본 준수).

## 4. 운영 규칙

- **한계 원장**: `limitation_ledger.md` — 게이트마다 [날짜·체인·증상·증거·처방·상태] 행 추가.

- **재현**: 모든 라운드는 pairs/config JSON + run_id를 본 디렉토리에 커밋.
