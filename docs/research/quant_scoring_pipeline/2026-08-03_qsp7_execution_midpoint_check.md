## 3. 🔬 이어서 실행하는 다음 행동 (이 문서 작성 직후 개시)

| 순서 | 작업 | 방법 | 예상 |
|---:|---|---|---|
| A | min 설계 control | 대시보드 `/bt/run` — manifest 기간(20250407~20251128)·기준선 자동 | ~6~12분 |
| B | min OOS control | 〃 (20251201~20260227) | ~3~5분 |
| C | **R1 첫 연구 라운드(min)** | 경로 분석 → 회복 판별 → 데이터 구동 후보 → 후보 전수 설계 pair → 개선분만 잠긴 OOS → promotion gate | 반나절 내 |
| D | P0-8 tick modern control 재발급 | 설계(2022-04-01~2024-03-31)·표본밖(2024-04-01~2026-02-27) 각 1회 | 각 ~30~60분 |
| E | min 분할안 A **최종 확정** | manifest decision_status 갱신 (사용자 "전체 진행" 지시로 확정) | 즉시 |

- 잡 큐는 **동시 1개 FIFO** — A→B→C(후보 N개)→D 순서로 직렬 실행된다.
- 원격 push/PR 은 이번 범위에서 **보류**: 로컬 `loop/process-research-pipeline` 이 origin 대비 62커밋 앞서 있어(이전 미push 연구 50 포함) PR 범위가 과대해진다 — 사용자 확인 후 진행.
- R1 의 채택/기각 **최종 승인은 사람** — 이 실행은 gate 판정까지만 간다.
