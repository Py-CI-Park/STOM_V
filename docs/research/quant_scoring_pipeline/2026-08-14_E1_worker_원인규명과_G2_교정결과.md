## 1. 결론

E0에서 `waiting_mq_first` timeout으로 보였던 현상은 느린 조건식이나 queue deadlock이 아니었다.

`G2_B_SEG_ONLY`가 `VI아래5호가`를 사용하면서 다음 파생변수 선언을 빠뜨렸다.

```python
VI아래5호가 = VI가격 - VI호가단위 * 5
```

모든 5개 실제 worker가 첫 매수전략 실행에서 동일한 `NameError`를 냈지만, 기존 `BackStop(3)`가 parent `tq`에 중지 신호를 보내지 않아 parent가 첫 MQ를 계속 기다렸다. 따라서 하나의 생성기 결함과 하나의 오류전파 결함이 결합해 timeout으로 위장됐다.

## 3. 코드 교정

| 결함 | 교정 |
|---|---|
| G2 파생변수 미정의 | renderer가 `VI가격 - VI호가단위 * 5`를 먼저 선언 |
| worker 예외가 parent에 미전파 | `BackStop(3)`에서 `tq.put('백테중지')` |
| traceback 소실 | worker ID·code·index·마지막 오류줄을 128자로 봉인 |
| 운영 strategy.db 재사용 위험 | 명시 env 전용 연구 sidecar DB override |
| timeout/예외 혼동 | `STRATEGY_EXCEPTION_LOCALIZED` 별도 판정 |

운영 strategy.db는 수정하지 않았다. 교정식은 `ai_strategy_loop/state/e1_strategy.db` sidecar에만 materialize했다.

## 6. 연구 유효성

이 연구는 의미가 있었다.

1. timeout을 성능 문제로 오진하던 상태에서 정확한 NameError를 특정했다.
2. 생성기가 실제 STOM runtime symbol 계약을 검증해야 함을 확인했다.
3. worker 오류가 parent timeout으로 위장되는 엔진 결함을 제거했다.
4. 교정 후 공식 엔진 3/3 실행으로 인과관계를 재현했다.
5. 실행 성공과 수익 성공을 분리해 과장을 막았다.

## 7. 다음 허용 단계

E2는 대규모 비용 모델이 아니라 다음 최소 계약부터 수행한다.

1. canonical AST의 undefined runtime symbol 검사
2. 요청 engines와 실제 worker 수 분리
3. 생성 후보의 파생변수 정의·allowed symbol·작업량 상한
4. 이 정적 계약을 통과한 후보만 QMC/저차원 Bayesian/Pareto 제안으로 전달

현재 G2의 경제적 실패를 개선하기 위해 동일 SEG_ONLY를 반복하지 않는다. 다음 후보는 선택도를 높이는 독립 구조 가족이어야 한다.
