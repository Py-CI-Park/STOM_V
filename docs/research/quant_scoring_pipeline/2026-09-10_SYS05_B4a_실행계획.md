## 범위와 순서

1. 기존10개 scalar(summary/equity/distribution/heatmap/underwater/insights/mae_mfe/exit_reasons/orderflow/gui_parity)와 MC 직접 API의 실패재현.
2. 기존 manager/read-only generation/resolver를 주입하는 작은 admission 모듈로 입력 판정을 분리한다. 같은 TradeQualityResult를 필터와 기존 계산 함수에 전달하며 legacy CSV 재읽기를 금지한다.
3. 계산 dispatch와 JSON 응답을 작은 모듈로 분리한다. 기존 route/함수명과 결과 field는 유지하며 차단 시 해당field=null, analysis_ready=false 및 품질/실행 메타를 추가한다. 정상0행과 미확보 자료는 구분한다.
4. MC의 n상한/seed/method/block_length/기간 필터를 유지한다. generation writer-ok는 PARTIAL/실행미검증이며 손실·gateFalse는 진단 허용한다.
5. 실제 V4 소비자인 BtResultArea에 MC 품질 응답을 보존하고, 응답 지연/자료 교체/차단 전환 시 오래된 MC가 남지 않도록 회귀와 실사용 검증한다. frontend-ui-ux 방향은 기존 절제된 연구 대시보드와 품질 카드 재사용이며 전역 디자인 교체는 하지 않는다.
6. 집중 회귀/타입/lint/번들/합성 브라우저/독립5영역→receipt/원장→명시 commit→loop no-ff merge→Fast/Slow Gate.

## Codemap·검증

기존 backtest_api의 거대 파일을 전부 이관하지 않는다. 이번 단위의 입력 판정과 연산 dispatch를 각각 별도 소유 모듈로 이동하고 facade는 짧게 유지한다. LSP 도구가 현재 노출되지 않아 rg/타입 검사/실제 API 회귀로 영향 범위를 확인한다. refactor 스킬의5개 읽기 전용 탐색으로 대상·소비자·기존 패턴·시험·계획을 분리 검토했다.

- Job admission: 기존 inspect_job_result_source와 status=success 정책.
- Generation admission: 기존 generation_policy; 임의 rc=0/승인자 생성 금지.
- 실패재현: 잘못된 schema/부분파싱/불일치/누락/오류/취소에서 연산 미호출; 정상 입력은 같은 snapshot으로 실제 계산.
- 기존 MC/orderflow fixture의15자리 날짜·축약 header는 공식 입력으로 교정하되 기존 수치/n상한 assertion 유지.
- 비교/overlay/portfolio 및 raw 피처 분석은 B4b/B5까지 기존 경로를 유지한다. 기존 지표 정의 변경은 SQ02로 남긴다.

기존 정상 데이터의 계산식은 바꾸지 않는다. rollback은 해당 feature 역변경 commit이며 원본 DB/evidence/dirty wt-dev/tmap을 되돌리지 않는다. 운영 DB write, 실제 연구, StageF/G0/G2/Holdout/자동채택/주문/push는 금지한다.
