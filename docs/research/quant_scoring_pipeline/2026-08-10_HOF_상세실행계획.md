## 2. HOF2 — 넓은 창 거래 부검·절 후보 발굴 (백파인더 정신)

### 2.1 왜 STOM 백파인더 원본도, 알파 채굴 재실행도 아닌가 (중복 회피)

| 경로 | 왜 안 쓰나 |
|---|---|
| 백파인더 원본 | GUI 전용 + **신호 시점** 지표만 수집. 우리는 더 좋은 것을 갖고 있다 — **실현 손익이 붙은 엔진 체결 기록** |
| 알파 채굴 재실행 | 이미 한 번 돈 프로그램(승격 0)이다. 같은 질문(무조건부 리프 × 고정 지평 라벨)을 다시 물으면 등록부 §2 의 4번째 중복이 된다 |

### 2.2 HOF2 의 질문은 다르다 — 챔피언-조건부·엔진-실현 분석

> **"HOF1 후보(09:00~09:20)의 실거래 약 1,300건 중, 손실 거래를 골라내는
> 피처는 무엇인가?"** — 라벨이 가상 수익(고정 지평)이 아니라 **챔피언 매도로
> 실현된 손익**이고, 표본이 임의 시점이 아니라 **챔피언 절을 전부 통과한 진입**이다.
> 이 조합은 어떤 이전 프로그램도 묻지 않았다.

### 2.3 실행 단계

| 단계 | 내용 | 산출 |
|---:|---|---|
| 0 | **피처 원천 실사**: alpha_lab npz 샤드(25피처)와 design_v5 우주의 (a) 설계 구간 커버리지 (b) 시각 정렬(매수시간과 초 단위 일치 여부) 를 확인하고 하나를 고른다. 근거를 문서로 | 원천 결정 메모 |
| 1 | HOF1 후보 팔의 개별 거래(결과 DB)를 `매수시간`·`종목명` 키로 피처와 조인 | 거래×피처 테이블 |
| 2 | **분위 대조**: 수익 vs 손실 거래의 피처 분포 (전체 + 시간대 코호트 3개: ~09:02 / 09:02~09:05 / **09:05~09:20**) | 분포 표·차트 |
| 3 | 시간대 코호트 간 비교 — HOF1 판정이 REJECT 라면 "09:05 이후 신호는 무엇이 다른가"가 **핵심 질문**이 된다 | 코호트 진단 |
| 4 | 절 후보 도출 (**상한 10 — 가설 예산, 헌법 15항**). 각 후보에: 걸렀을 때 빠지는 손실 거래 수·살아남는 수익 거래 수·순효과 추정 표 첨부 | 절 후보 목록 |
| 5 | 통계 규율: 후보별 효과를 **일 블록 부트스트랩**으로 재표집(알파 도구 재사용) — 다중 비교는 BH-FDR | 신뢰 구간 |
| 6 | 문서 + 사람 보고. **발굴이지 판정이 아니다** — 어떤 후보도 이 단계에서 채택되지 않는다 | `2026-08-XX_hof2_거래부검.md` |

## 3. HOF3 — 문턱 최적화 (넓은 범위 · 수치해석식)

### 3.1 구간 3분할 (실행 전 사전 등록에 고정할 값)

833 거래일(20220323~20250822)을 **시간 순서대로** 2:1:1 로 나눈다.

| 구간 | 몫 | 용도 | 접촉 규칙 |
|---|---|---|---|
| 학습(TRAIN) | 앞 ~417일 | 탐색 — trial 마음껏 | 무제한 |
| 검증(VALID) | 중간 ~208일 | 학습 승자 상위 소수(≤10) 선별 | 후보당 1회 |
| 확인(TEST) | 뒤 ~208일 | **최종 ≤3개만** 접촉 (헌법 14항) | 라운드당 ≤3회 |

경계 오염 방지: 구간 사이 **purge 5거래일** (`cli/wfo.py` 의 purge 개념 재사용).
정확한 날짜는 HOF3 사전 등록 문서에서 거래일 달력으로 확정한다.

### 3.2 탐색 방법 (사용자 확정: trial 예산 1차 100 · 최대 300)

| 선택 | 방법 | 이유 |
|---|---|---|
| 1차 | **엔진 직접 + coarse 격자** (`/bt/run` 반복, TRAIN 구간만) | 배선 완비·결과 신뢰. 절 후보당 문턱 5~10점 × 후보 ≤10 = ≤100 run |
| 2차(필요 시) | coarse 승자 주변 fine 격자 (남은 예산 ≤200) | 수치해석식 조임 |
| 예비 | `cli/optimizer.py` Random / STOM 옵튜나 배선 | 격자가 부족하다고 **측정으로** 판명될 때만 |

**시간 산수**: TRAIN 417일 run ≈ 전 구간 15분 × 0.5 ≈ 7분 → 100 run ≈ 12시간
= **야간 배치 1회**. 동시 실행은 엔진 큐가 허용하는 만큼(실사 후 사전 등록에 기재).

### 3.3 판정 (사전 등록에 고정)

- 순위 척도: **총수익금** (자본 정책 `limit` 2,000만원 · 사용자 확정)
- 학습 최고가 아니라 **검증 구간 성적**으로 상위 ≤3 선별
- 확인 구간에서 셋 다 음수면 그 절 후보는 닫는다(등록부 §3 등재)
- 응답면 전셀 보고(헌법 5항) — 고원/절벽을 페이지 32 형식으로 기록

예상 소요: 사전 등록 0.5일 + 야간 배치 1~2회 + 판독 0.5일 = **약 2~3일**

## 4. HOF4 — 절 조합 (소형 nCr)

- HOF3 생존 절 k개 (예상 k ≤ 5) → 부분집합 2^k ≤ 32 조합
- **조합 수 상한 32 를 사전 등록** 후 TRAIN 구간 엔진 실행, 검증 선별·확인 ≤3 접촉 (HOF3 과 같은 3분할)
- STOM 조건최적화(GUI)는 쓰지 않는다 — 32 조합은 자체 소형 러너로 충분
- 진입 절 결합의 함정(QSP3 실측: 구간함수 필터는 설계 구간 과최적)을 사전 등록에 명기

예상 소요: **약 1~2일** (야간 배치 1회 포함)
