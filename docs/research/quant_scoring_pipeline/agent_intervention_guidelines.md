> 좋으니 가이드라인이 있었으면 좋겠습니다."*
> 이 문서가 그 규약의 정본이다. 설정 탭 [AI 개입 규약] 카드가 이 문서를 요약 표시한다.

## 1. 생성 주체 정책

| 상태 | 생성 주체 | 근거 |
|---|---|---|
| LLM provider 정상(gpt_auth 로그인 유효) | **LLM 루프** (공식 경로) | 기본값 |
| LLM 불가(만료/고장/미로그인) | **AI 에이전트(Claude) 대행** | 사용자 승인 — 연구 무중단 |
| 결정적 제안 경로(P2 proposer) | 에이전트/LLM 무관 — **코드가 생성** | 잔차표→명세→적용은 결정적 |

## 2. 에이전트가 개입할 수 있는 단계

| 단계 | 허용 | 조건 |
|---|---|---|
| 조건식 생성/수정 | ✅ | 수정 명세(revision spec) 기반. prompt v2 규약(자가검토·계층 보존) 준수 |
| 배치 백테 실행 | ✅ | 공식 배치 러너만 사용(`claude_candidate_batch_eval`) — 사설 채점 금지 |
| 결과 분석·제안 | ✅ | label_dataset/proposer 산출물 근거 필수(감이 아니라 잔차표) |
| DB 등록 | ✅ | `loop_strategies.db` INSERT-only · 이름 규약 `QSP*` · preflight 통과 후 |
| **게이트 자체 판정** | ⚠️ | 의도-일치 게이트(intent_gate)는 **코드 판정** — 에이전트가 결과를 뒤집을 수 없다 |
| 원본 시드/GUI DB 수정 | ❌ | `_database/strategy.db` 읽기 전용 · 시드 골격 변경은 새 버전 제안으로만 |
| 엔진 로직 수정 | ❌ | additive(결과 기록 컬럼)만 허용 — 체결/채점 로직은 사용자 게이트 |
| 실거래 반영 | ❌ | 항상 사용자 결정 |

## 3. 흔적(감사 가능성) 의무

- 모든 세대/배치의 `strategy_gist` 또는 pairs label 에 생성 경위를 남긴다.
  에이전트 생성물은 run 문서(round_reviews)에 **명세→생성물→게이트 판정**을 기록한다.
- 수정은 반드시 [수정 명세 → apply/생성 → intent_gate → 재백테] 순서를 밟는다.
  게이트 FAIL 생성물은 등록 금지(재생성).
- 라운드마다 한계 원장(limitation_ledger)에 발견을 누적한다.

## 4. LLM 복귀 시

- 로그인 복구 즉시 provider=gpt_auth 스모크 1회 → 품질 확인 후 생성 주체 전환.
- 에이전트 경로는 폴백으로 유지(동일 규약·동일 게이트 — 주체만 교체 가능하도록
  게이트가 주체 무관 설계인 이유).
