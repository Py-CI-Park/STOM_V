## 3. 사용자 제안 시스템: 반복 필터링 루프

### 3.1 시스템 개요

```
[Step 1] 초기 백테스트 실행
    → 확장된 결과 CSV (B_*/S_* 포함, ~80컬럼)

[Step 2] 데이터 분석 (자동)
    → 시가총액 구간별 분류
    → 시간대별 분류 (장초반/오전/점심/오후)
    → 각 B_* 변수의 범위 vs 수익률 상관관계 분석
    → 수익률을 낮추는 변수 범위 식별

[Step 3] 필터 조건 생성 (자동)
    → "이 범위에서 매수하지 않으면 수익률이 올라간다" → 매수 제외 조건 생성
    → 새로운 조건식 코드 자동 생성

[Step 4] 재백테스트
    → 새 조건식으로 백테스트 재실행
    → 결과 비교 (수익률 / MDD / 승률 / 거래횟수)

[Step 5] 반복 또는 종료
    → 개선 없으면 종료. 개선 있으면 Step 2로 루프
```

### 3.2 Step 2 상세: 통계 분석 알고리즘

#### 3.2.1 시가총액 구간 분류

```python
# 시가총액 구간 (원 단위)
구간 = {
    '소형주': (0, 3_000억),
    '중형주': (3_000억, 1_조),
    '대형주': (1_조, 5_조),
    '초대형주': (5_조, inf)
}
# 구간별로 승률, 평균수익률, MDD 계산
# 특정 구간의 성과가 현저히 낮으면 해당 구간 제외 조건 생성
```

#### 3.2.2 시간대별 분류

```python
시간대 = {
    '장초반': (90000, 93000),   # 09:00~09:30
    '오전': (93000, 113000),    # 09:30~11:30
    '점심': (113000, 130000),   # 11:30~13:00
    '오후': (130000, 153000),   # 13:00~15:30
}
# B_시분초를 기준으로 분류
# 시간대별 승률 차이가 통계적으로 유의미하면 제외 조건 생성
```

#### 3.2.3 변수별 수익률 상관관계 분석

**방법 1: 분위수(Quantile) 기반 필터링**
```python
for col in B_variables:
    # B_* 변수를 10분위로 나눔
    quantiles = df[col].quantile([0.1, 0.2, ..., 0.9])
    for q_low, q_high in zip(quantiles, quantiles[1:]):
        mask = (df[col] >= q_low) & (df[col] < q_high)
        avg_return = df.loc[mask, '수익률'].mean()
        win_rate = (df.loc[mask, '수익률'] > 0).mean()
        # avg_return이 전체 평균보다 현저히 낮으면 → 제외 조건 후보
```

**방법 2: 정보 이득(Information Gain) 기반**
```python
# 수익률 > 0 = 클래스 1, 수익률 <= 0 = 클래스 0
# 각 B_* 변수의 분류력(Information Gain 또는 Gini Impurity) 계산
# 분류력이 높은 변수 = 조건 필터링에 유용한 변수
from sklearn.ensemble import GradientBoostingClassifier
model = GradientBoostingClassifier()
model.fit(df[B_variables], df['수익여부'])
feature_importance = pd.Series(model.feature_importances_, index=B_variables)
```

**방법 3: t-test 기반 유의성 검정**
```python
# 각 변수를 중앙값으로 이분
for col in B_variables:
    high_group = df[df[col] > df[col].median()]['수익률']
    low_group = df[df[col] <= df[col].median()]['수익률']
    t_stat, p_value = scipy.stats.ttest_ind(high_group, low_group)
    if p_value < 0.05:  # 통계적으로 유의미한 차이
        # 낮은 그룹이 더 나쁘면 → "col > median" 조건 추가 후보
```

### 3.3 Step 3 상세: 조건식 자동 생성

```python
# 분석 결과 예시:
# - B_등락율 < 2.0 구간에서 승률이 35%로 전체 평균 52%보다 낮음
# - B_시가총액 < 500억 구간에서 MDD가 2배 높음
# - B_시분초 < 93000 (장초반) 구간에서 손실 비율 높음

# 자동 생성 조건식 (추가 필터):
새_매수조건 = """
# 자동 생성 필터 - v1 (2026-03-10)
# 근거: 백테스트 결과 통계 분석
if B_등락율 < 2.0: 매수 = False   # 등락율 2% 미만 제외
if B_시가총액 < 500_0000_0000: 매수 = False  # 500억 미만 소형주 제외
if B_시분초 < 93000: 매수 = False  # 장초반 제외
"""
```

### 3.4 핵심 한계 인식 (사용자가 언급한 문제)

> *"매수시점에 매수가 안되도록 조건식을 만들어도 그 종목이 시간이 지난 뒤 다시 매수 되고 또 수익이 날지 안날지는 모르기 때문입니다"*

이것은 **과최적화(Overfitting) / 데이터 스누핑(Data Snooping)** 문제입니다.

**발생 이유:**
- 학습 데이터(과거 백테스트)에서 찾은 패턴이 미래에 재현되지 않을 수 있음
- 필터를 추가할수록 거래 횟수가 줄어들어 통계적 신뢰성이 떨어짐
- "이 조건에서 나쁜 거래를 제외했다"는 것이 미래에도 나쁜 거래인지는 보장 없음

**대응 방법:**
```
1. Walk-Forward 검증
   - 학습 기간: 2024-01 ~ 2024-09 (9개월)
   - 검증 기간: 2024-10 ~ 2024-12 (3개월)
   - 학습에서 찾은 필터가 검증 기간에도 유효한지 확인

2. 샘플 외 검증 (Out-of-Sample)
   - 최적화에 사용하지 않은 데이터로 반드시 검증
   - 원칙: 최적화 기간 ≥ 검증 기간 × 3

3. 거래 횟수 최소 기준
   - 필터 적용 후 거래 횟수 < 30건이면 통계적 의미 없음
   - 최소 100건 이상 유지

4. 단순화 원칙 (Occam's Razor)
   - 필터를 추가할수록 과최적화 위험 증가
   - 추가할 조건은 경제적 근거가 있는 것만 (예: 소형주 제외 = 유동성 리스크)
```

## 4. 퀀트 전문가 관점 추가 방법론

### 4.1 방법론 1: 유전 알고리즘 (Genetic Algorithm, GA)

**원리:** 생물의 진화를 모방. 조건식을 "유전자"로 표현하고 수익률이 높은 조건식을 교배/돌연변이시켜 점진적으로 최적 조건을 탐색.

**STOM 적용 방안:**
```
조건식 표현: 트리 구조
  AND(
    GT(_등락율N(0), 3.0),       # 등락율 > 3%
    LT(_체결강도N(0), 120.0),    # 체결강도 < 120
    GT(_분당거래대금N(0), 50억)  # 분당거래대금 > 50억
  )

적합도 함수 (Fitness):
  수익금합계 × 승률 / max(MDD, 0.01)   # 수익성 × 안정성

진화 과정:
  1. 랜덤 조건식 집단 100개 생성
  2. 각각 백테스트 실행 → 적합도 계산
  3. 상위 20개 부모로 선택
  4. 교배(Crossover): 부모 두 개의 조건식 서브트리 교환
  5. 돌연변이(Mutation): 임계값 ±5%, 조건 추가/제거
  6. 세대 반복 (보통 50~200세대)
```

**장점:** 광범위한 탐색 공간 커버, 복잡한 비선형 조건도 발견 가능
**단점:** 계산 비용 매우 높음 (100종목 × 100개 × 200세대 = 2,000,000 백테스트), 과최적화 위험

**STOM CLI 연계 방안:**
```bash
python stom_backtest.py --buy {GA_생성_전략} --sell Min_S_Study --format json
# CLI의 JSON 출력을 적합도 함수 입력으로 사용
```

### 4.2 방법론 2: 랜덤 포레스트 / 그래디언트 부스팅 (ML 기반)

**원리:** 매수 시점의 B_* 변수 → 수익/손실 이진 분류기 학습.

```python
# 학습 데이터 준비
X = df[[B_* 변수들]]  # 약 80개 피처
y = (df['수익률'] > 0).astype(int)  # 수익 = 1, 손실 = 0

# 모델 학습
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.model_selection import TimeSeriesSplit

# 시계열 교차검증 (일반 K-Fold 사용 금지 — 미래 정보 누출)
tscv = TimeSeriesSplit(n_splits=5)
for train, test in tscv.split(X):
    model.fit(X.iloc[train], y.iloc[train])
    score = model.score(X.iloc[test], y.iloc[test])

# 피처 중요도 추출
importance = pd.Series(model.feature_importances_, index=X.columns)
top_features = importance.nlargest(10)
# → 수익률을 가장 잘 예측하는 B_* 변수 10개 식별

# 예측 점수로 매수 필터링
threshold = 0.6  # 60% 이상 확률일 때만 매수
df['매수확률'] = model.predict_proba(X)[:, 1]
df_filtered = df[df['매수확률'] > threshold]
```

**피처 중요도로 조건식 자동 생성:**
```
Top 피처 예시:
  1. B_분당매수금액 (중요도 0.18) → 임계값: 3억원 이상
  2. B_체결강도 (0.14) → 임계값: 100 이상
  3. B_저가대비고가등락율 (0.11) → 임계값: 5% 이하
  4. B_당일거래대금 (0.09) → 임계값: 100억 이상
  → 자동 생성 조건: "분당매수금액 >= 3억 and 체결강도 >= 100 and 저가대비고가등락율 <= 5"
```

**주의사항:**
- 반드시 Time-aware 교차검증 사용 (과거 → 미래 방향)
- SHAP 값으로 피처 기여도 해석 가능 (XAI)
- 클래스 불균형 처리 필요 (손실 거래 != 수익 거래 수)

### 4.3 방법론 3: Walk-Forward Optimization (WFO)

**업계 표준 방법론.** 과최적화를 방지하는 가장 확실한 방법.

```
전체 데이터: 2023-01 ~ 2025-12 (3년)

구간 분할 (롤링 윈도우):
  Round 1: 학습 2023-01~09 / 검증 2023-10~12
  Round 2: 학습 2023-04~12 / 검증 2024-01~03
  Round 3: 학습 2023-07~2024-03 / 검증 2024-04~06
  ...총 9라운드...

각 라운드에서:
  1. 학습 기간으로 조건식 최적화 (GA 또는 Grid Search)
  2. 최적 조건식을 검증 기간에 적용
  3. 검증 기간 성과 기록

최종 평가:
  → 9개 검증 기간의 누적 성과로 전략 평가
  → 과최적화된 전략은 검증 기간에서 성과 급락
  → 진짜 알파(Alpha)를 가진 전략만 검증 기간에서도 일관성 유지
```

**STOM CLI 연계:**
```bash
# 각 라운드마다 CLI 자동 실행
for round in rounds:
    python stom_backtest.py \
        --buy {round.optimized_buy} \
        --sell {round.optimized_sell} \
        --start {round.val_start} \
        --end {round.val_end} \
        --format json > {round.result_file}
```

### 4.4 방법론 4: 정보 계수(IC, Information Coefficient) 기반 팩터 분석

**원리:** 각 B_* 변수(팩터)와 미래 수익률의 스피어만 상관계수로 팩터 유효성 측정.

```python
import scipy.stats as stats

for col in B_variables:
    # IC = spearman(B_변수, 미래수익률)
    ic, p_value = stats.spearmanr(df[col], df['수익률'])
    icir = ic / df[col].rolling(20).apply(
        lambda x: stats.spearmanr(x, df['수익률'].iloc[x.index])[0]
    ).std()  # IC / IC 표준편차 = ICIR (정보 계수 비율)

# ICIR > 0.5 이상인 팩터만 유효한 신호로 간주
유효_팩터 = [col for col in B_variables if icir[col] > 0.5]
```

**해석:**
- IC > 0.05 (절대값): 팩터가 수익률을 약하게 예측
- IC > 0.1: 매우 강한 팩터 (실제 퀀트 투자에서 귀함)
- ICIR > 0.5: 안정적으로 유효한 팩터

### 4.5 방법론 5: 강화학습 (Reinforcement Learning)

**원리:** 에이전트가 매수/보유/매도 액션을 선택하고, 수익률을 보상으로 받아 최적 정책을 학습.

```
상태(State): 현재 틱의 B_* 변수 전체 (약 80차원 벡터)
액션(Action): 매수 / 매수 안함
보상(Reward): 매수 후 매도까지의 수익률
에이전트: PPO (Proximal Policy Optimization) 또는 DQN

장점:
  - 조건식을 명시적으로 정의할 필요 없음
  - 복잡한 시장 상황에 동적으로 적응

단점:
  - 학습 데이터 매우 많이 필요 (수만 거래 이상)
  - 블랙박스 — 왜 매수하는지 설명 불가
  - 금융 시계열에서 안정적 학습 어려움
  - STOM 전략 코드로 변환 불가 (별도 추론 서버 필요)
```

**STOM 적용 현실적 방안:**
- RL로 찾은 매수 패턴을 rule extraction으로 조건식 근사
- 실시간 추론 서버 → CLI → 매수 신호 전달

### 4.6 방법론 6: 파라미터 민감도 분석 (Robustness Testing)

단순하지만 매우 실용적인 방법. 조건식의 임계값이 조금 바뀌어도 성과가 유지되는지 확인.

```python
# 예: 체결강도 >= 100 조건
base_threshold = 100
for delta in [-20, -10, -5, +5, +10, +20]:
    threshold = base_threshold + delta
    # 해당 임계값으로 재백테스트
    result = run_backtest(condition=f"체결강도 >= {threshold}")
    print(f"체결강도 >= {threshold}: 수익률={result.return_pct:.1f}%, 승률={result.win_rate:.1f}%")

# 결과 예시:
# 체결강도 >= 80:  수익률=+12.3%, 승률=53%  ← 파라미터 변화에 민감
# 체결강도 >= 90:  수익률=+15.1%, 승률=55%
# 체결강도 >= 100: 수익률=+18.7%, 승률=58%  ← 최적화한 값
# 체결강도 >= 110: 수익률=+16.2%, 승률=57%
# 체결강도 >= 120: 수익률=+8.4%,  승률=52%  ← 급락 = 불안정한 조건

# "최적 주변에서 완만한 곡선을 그리는 조건만 채택"
```

## 6. 기대 효과 및 한계

### 기대 효과

1. **탐색 시간 단축**: 수동으로 찾던 조건식 최적화를 수십 배 빠르게
2. **데이터 기반 의사결정**: 직관 대신 통계적 근거로 조건 채택/기각
3. **재현 가능성**: 조건식 생성 과정을 문서화하여 다른 전략에 재적용
4. **숨겨진 패턴 발견**: 사람이 직접 보기 어려운 고차원 상관관계 자동 발견

### 현실적 한계

1. **과최적화 위험**: WFO와 샘플 외 검증 없이는 실전에서 실패 가능
2. **시장 구조 변화**: 과거에 유효했던 패턴이 시장 변화로 무효화될 수 있음
3. **거래 횟수 감소**: 필터를 추가할수록 거래 기회 감소 → 전략 무력화 가능
4. **계산 비용**: GA + WFO 조합 시 수천 번의 백테스트 필요 → 서버급 자원
5. **설명 불가능성**: ML/RL 기반은 "왜 이 조건인가"를 설명하기 어려움

### 권고사항

**1단계**: Phase 1(데이터 확장 + CSV)만 먼저 구현. 데이터를 직접 보면서 인사이트 도출.

**2단계**: 간단한 분위수 분석(방법론 없이 pandas만으로)으로 명확한 패턴이 있는지 확인.

**3단계**: 패턴이 발견되면 WFO로 검증 후 조건식 추가.

**핵심 원칙**: *"조건을 추가하는 것은 쉽지만, 그 조건이 미래에도 유효한지 증명하는 것이 어렵다."*
