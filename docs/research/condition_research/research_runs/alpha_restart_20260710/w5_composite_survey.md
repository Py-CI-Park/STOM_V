## 0. 결론 먼저 (TL;DR)

1. **병합 재료가 생각보다 없다.** W2 상위권 중 strategy.db에 **원문이 실존하고 현행 API인 전략은 ALP_V4 계열뿐**이다. 902905 계보 top-40(TMAP/GATE/THETA/R2R3/R5C)은 **원문이 DB에 없다**(원장 결과로만 존재) → 병합 재료로 재구성 불가. 그 **조상 시드 `Tick_B_902_905` 계열(21개)**만이 현행 API 원문으로 남아 있다.
2. **RR8 3형제는 사실상 세쌍둥이.** RR8_0/12/21은 절 50개·유형분포가 **완전히 동일한 한 템플릿의 파라미터 변주**다. 신호도 거의 겹친다 — 근접(±60초) 중복율 **73~100%**.
3. **근친 병합은 분산 착시.** RR8 3형제를 OR로 합쳐도 거래는 단순합 765 → **병합 301건(60.7% 흡수)**. 그런데 **RR8_12 혼자 이미 298건** → 나머지 둘의 순증분은 **+3건(+1%)**. 세 전략을 섞었다는 착각만 줄 뿐 신규 신호는 사실상 0.
4. **매도식은 진입 출처를 모른다.** 병합 매도식은 "902로 샀는지 905로 샀는지" 구분할 변수가 없어서, **모든 포지션에 적용되는 단일 통합 우선순위 체인 하나**로만 만들 수 있다. → 병합의 최대 성능 누수 지점.
5. **백테는 슬롯 무제한**이라 병합 총수익이 부풀어 보이지만, 신호가 늘면 **필요자금이 함께 팽창**하고 라이브에선 슬롯 경합으로 초과분이 드롭된다.

## 2. 병합 의미론 검증 (Merge Semantics)

### 쉬운 설명
매수식을 합치는 데는 두 가지 문법이 있다. 원래 STOM 방식인 **"매수=False 체인"은 모든 검문소를 다 통과해야(AND)** 사는 것이고, 우리가 원하는 **OR 병합은 "여러 문 중 하나만 열려도 통과"**다. 그런데 이 두 개는 문법이 완전히 다르다. 그리고 팔 때가 진짜 문제인데, **매도식은 "이 종목을 902 전략으로 샀는지 905로 샀는지"를 알 방법이 없다.** 응급실 의사가 환자가 어느 문으로 들어왔는지 모른 채 똑같은 프로토콜로 치료하는 것과 같다.

### 2.1 컴파일 경로 (back_static.py:144-199)
| 함수 | 역할 | OR 병합 |
|---|---|---|
| `GetBuyStg` (freeform) | buytxt 전체를 그대로 compile→exec. `#`주석행 제거, `self.indicator`행만 indistg로 분리 | **✅ OR은 이 경로로만 가능** |
| `GetBuyConds` (list) | 리스트를 `if not(C1): 매수=False elif not(C2): …`로 join → **논리 AND** | ❌ 단독 OR 불가 |
| `GetSellConds` (list) | `if not(C1): 매도=True elif …` join. SetSellCond가 `매도=True` 직전 주석을 조건명으로 기록 | — |

### 2.2 거래당 betting 전액 문제 (backengine_base.py:821-847)
- `SetBuyCount → GetOrderCount = int(betting / 현재가)` — **슬롯 하나당 betting 전액**을 투입한다. 병합으로 신호가 늘면 그만큼 **전액 포지션이 추가로** 생긴다.
- **같은 종목 재진입 차단**: `curr_trade_info`는 종목별이고, 보유중이면 매수 브랜치를 아예 평가하지 않는다(엔진 강제). → 같은 종목에 동시 신호가 여러 개 떠도 **1포지션으로 합쳐진다(이중 베팅 없음)**.

### 2.3 최대매수종목수 슬롯 경합
- **백테(backtest.py): 슬롯 상한 없음.** 각 종목을 독립 시뮬하고 전액 베팅한다. `적정최대보유종목수`(mhct)와 `필요자금`(seed)은 **캡이 아니라 결과로 산출되는 파생지표**(백테기간 중 동시보유 피크). → 백테에서 OR 병합 = **거래의 합집합, 단 필요자금이 함께 팽창**.
- **라이브: 운영금·최대보유종목수 고정** → 슬롯 경합 실재. 만석이면 초과 신호는 드롭(OMS 순서 의존).
- **함의**: 백테 총수익은 무제한 자본을 가정하므로 슬롯 유한한 라이브와 괴리한다. 병합 검정 시 **"필요자금 팽창"과 "슬롯당 성과"를 반드시 병기**해야 한다.

### 2.4 병합 매도식의 절 우선순위 + 진입 출처 분기 불가
- **우선순위 = 위→아래 첫 True 절.** 그 절이 매도조건명으로 기록된다(back_static.py:202).
- **결정적 제약**: 매도 스코프에는 **진입 출처를 알려주는 변수가 없다.** 보유맥락 변수는 `보유중/매수가/보유수량/최고수익률/최저수익률/수익률/보유시간`뿐(ground_grammar_map `tick_sell_only_vars`). → **출처별 매도 분기 불가**. 병합 매도식은 모든 포지션에 적용되는 **단일 통합 우선순위 체인**이어야 한다.
- **RR8 실측**: RR8_0/12/21 매도식은 **트레일링 기브백 계수(`최고수익률*0.6` vs `0.7`) 하나만 다르고 나머지 바이트 동일**. 우선순위: (1) `등락율>29.5` 상한가직전 → (2) 약시가+`수익률<=-2%`+신저가 → (3) `보유>60s`+신저가 시간스톱 → (4) 09:30전: 하드 TP/SL(`수익률>=9 or <=-5`) → 트레일링 기브백 → `시총<1e4` 등락율각도 그레이드 역추세 → 이평이탈.

### 2.5 매수=False 체인 vs OR 블록 — 올바른 문법 (컴파일 규약 근거 예시)
back_static.py:144-163(GetBuyStg freeform)으로 컴파일되는 형태. **`매수=False` 나열은 AND라 OR 불가** → 각 출처의 AND-절연쇄를 **괄호 불리언 하나로 축약**한 뒤 `(Ablk or Bblk)`로 합친다.

```python
# 공통 파생지표: 단 한 번만 선언 (중복 금지)
전일종가       = 현재가 / (1 + 등락율 / 100)
시가등락율     = (시가 - 전일종가) / 전일종가 * 100
시가대비등락율 = (현재가 - 시가) / 시가 * 100
초당순매수금액 = (초당매수수량 - 초당매도수량) * 현재가 / 1_000_000
VI아래5호가    = VI가격 - VI호가단위 * 5

# 출처 A: 시간-분리 902 슬라이스 (AND 절연쇄를 불리언으로 축약)
Ablk = (관심종목 == 1 and 시분초 < 90200 and 시가총액 < 2500
        and 1000 < 현재가 <= 50000 and 1.0 < 등락율 <= 8.0
        and 고저평균대비등락율 > 0 and 현재가 < VI아래5호가
        and not 라운드피겨위5호가이내 and 2 < 회전율
        and 초당거래대금 / 초당거래대금평균(30) > 2.5
        and 초당매수수량 > 매도총잔량 * 0.20
        and 70 <= 체결강도 <= 300)

# 출처 B: 시간-분리 905 슬라이스 (또는 다른 검증 전략)
Bblk = (관심종목 == 1 and 90200 <= 시분초 < 90700
        and 1000 < 현재가 <= 30000 and 2.0 < 등락율 <= 15.0
        and 고저평균대비등락율 > 0 and 현재가 < VI아래5호가
        and not 라운드피겨위5호가이내
        and 초당거래대금 > 초당거래대금N(1) * 1.0
        and 초당매수수량 > 매도총잔량 * 0.30
        and 70 <= 체결강도 <= 300)

# OR 병합: 화이트리스트 필터 1개
매수 = True
if not (Ablk or Bblk):
    매수 = False
if 매수:
    self.Buy()
# 주의: 예시일 뿐 — 등록/실행하지 않음(엔진 확인은 별도 승인).
```

**문법 규칙 요약**
- 가드 절 변환: 원본 `elif 라운드피겨위5호가이내: 매수=False`(참일 때 매수금지)는 불리언에서 `and not 라운드피겨위5호가이내`.
- 공통 파생변수는 최상단 **단 한 번** 선언(중복·상충 정의 금지).
- **시간-분리** 출처(902 vs 905)는 `elif 시분초슬라이스:` 브랜치 디스패치로도 OR 성립(한 틱은 한 슬라이스만 → first-match-wins 안전). RR8이 이 방식이다.
- **시간-중첩** 출처(같은 시간대·다른 임계)는 **elif 디스패치 금지** — 첫 매칭 브랜치만 평가되어 둘째 출처 고유신호가 드롭된다. 반드시 `(Ablk or Bblk)` 명시적 불리언 합집합.
- AI 게이트(variable_scope.py/forbidden.md)는 `def/클래스/import/exec/eval/__` 차단 → **함수 선언 없이 불리언 축약만**.

## 3. 신호 중복율 실측 (Signal Overlap)

### 쉬운 설명
세쌍둥이에게 각각 투표권을 준다고 의견이 3배 다양해지지 않는다. 셋이 거의 같은 판단을 하기 때문이다. RR8 3형제가 딱 그렇다.

### 원장 필터 명기
- 파일: `backtest/csv/stock_bt_ALP_V4_*.csv`
- **필터: 매수일 ≤ 2023-12-31**. 각 전략은 2022-2024 파일 + 2025-2026 파일 2개가 있는데, 필터가 2025+ 파일을 통째로 0행으로 만든다.
- 창: **2022-03-23 ~ 2023-12-31** (관측 거래일 388일 / 영업일 463일). 필터 후 거래수: **RR8_0=221, RR8_12=298, RR8_21=246**.

### 3.1 쌍별 중복율 (같은 날·같은 종목·근접 ±60초)
| 전략쌍 | A→B 중복 | B→A 중복 | Jaccard | 같은날·같은종목 |
|---|--:|--:|--:|--:|
| RR8_0 vs RR8_12 | **98.6%** | 73.5% | 72.4% | 210 |
| RR8_0 vs RR8_21 | **100.0%** | 89.8% | 89.8% | 210 |
| RR8_12 vs RR8_21 | 80.9% | **97.6%** | 78.9% | 232 |

→ **RR8_0 ⊂ RR8_21 ⊂ RR8_12** 근사 관계. RR8_0(가장 타이트, 시총<2500)의 신호는 100%가 RR8_21에, 98.6%가 RR8_12에 이미 포함된다. RR8_12가 가장 완화되어(회전율>1.5) 신호가 가장 많다.

### 3.2 병합 시 예상 일 거래수 (단순 합 − 중복)
| 지표 | 값 |
|---|--:|
| 단순합 (RR8_0+12+21) | 765건 |
| **병합 합집합 (60초 dedup)** | **301건** |

→ **3전략 병합 ≈ 가장 완화된 단일 멤버(RR8_12).** 분산 효과 사실상 0.

### 3.3 GPTAUTH 자문용 참고 (병합 대상 아님)
- GPTAUTH_G8은 **발견창이 2025**(known)라 청정 후보가 아니다. 다만 2022-2024 백테 파일에 ≤2023 거래 893건이 있어 참고만 한다.

## 4. Composite 후보 설계 원칙 (초안)

### 4.1 병합 후보 모집단 (필터 통과 후)
| 상태 | 전략 |
|---|---|
| ✅ 검증·원문실존·현행API | ALP_V4_RR8_0, RR8_12, RR8_21 |
| ✅ 시드 조상 (현행API) | Tick_B_902_905 계열 21개 (902905 혈통의 유일한 병합가능 원문) |
| ❌ 발견창 2025 | ALP_V4_GPTAUTH_G8 (자문용만) |
| ❌ 구식 7인자 API | ALP_V4_TICK902U3 |

### 4.2 후보 선정 기준
1. **원문 실존(strategy.db) + 현행 API** — 하드 게이트.
2. **발견창 청정(≤2023-12-31 검증 가능)** — known-2025 발견 전략 배제.
3. **쌍별 근접(±60초) 중복율 < ~40%** 인 쌍만 병합(진짜 상보). RR8끼리는 73-100%로 **실격**.
4. **시간대·트리거 상보성**(902 vs 905 vs 09:05-10 vs 이평돌파) — 절 유형분포가 겹치지 않을수록 이득.
5. **검증 등급**: 각 출처가 독립적으로 OOS·슬리피지 tick2 게이트 통과.

### 4.3 병합 매도식 구성 전략
- **출처별 분기 불가**(진입 출처 변수 없음) → **단일 통합 우선순위 체인 1개**.
- **"가장 보수적 절 우선"**: 하드 손절(`수익률<=-5`)·시간스톱(`보유>60s`+신저가)·트레일링 기브백을 상단, 출처 고유의 완화 익절은 하단.
- RR8류 병합 시 매도식은 사실상 동일(기브백 0.6 vs 0.7만) → **0.6이 더 빨리 청산(방어적)** 이므로 통합 시 0.6 채택 권장.
- **위험**: 서로 다른 매도 로직을 가진 전략을 병합하면, 한쪽에 최적이던 매도가 다른 쪽 진입에는 조기/지연 청산이 되어 개별 성과를 재현 못한다. **매도식 = 병합의 최대 성능 누수 지점.**

### 4.4 이후 검정 경로 (엔진 확인은 별도 승인)
1. **사전등록**: 병합 후보쌍·병합 매수식(freeform)·통합 매도식·기대 일거래수·필요자금 팽창 예측을 원장에 봉인.
2. **엔진 확인(별도 승인 필요)**: `stom_backtest.py --buy <병합식> --sell <통합매도> --timeframe tick`, 발견창 ≤2023-12-31, 슬리피지 tick2 하드게이트.
3. **판정**: 병합 총수익이 **"최완화 단일 멤버"를 유의하게 초과**하는가 + **필요자금·슬롯당 성과 병기** + OOS(2024) 재현.
4. 감독형 소액 실전은 그 이후 별도 관문.

## 5. Composite의 가장 큰 함정 (단일)

> **상관 높은 근친(near-clone) 병합의 "분산 착시".**
> OR로 합쳐도 합집합 ≈ 가장 완화된 단일 멤버다. RR8 3형제 실측 — 단순합 765 → 병합 301(60.7% 흡수), 그중 **RR8_12 단독이 이미 298** → 나머지 둘의 순증분 **+3(+1%)**. 세 전략을 섞었다는 착각만 줄 뿐 실제 분산·신규신호는 사실상 0. 게다가 백테는 슬롯 무제한이라 병합 총수익이 부풀어 보이지만 **필요자금도 함께 팽창**한다.
> **처방**: 병합의 전제조건은 "낮은 중복율"이며, 이는 **병합 전에 반드시 원장으로 실측**해야 한다(본 W5가 그 절차). 진짜 상보성은 **시간대·트리거가 분리된 출처**(예: 09:00-07 RR8 vs 09:05-10 GPTAUTH류 vs 이평돌파)에서만 나온다.
