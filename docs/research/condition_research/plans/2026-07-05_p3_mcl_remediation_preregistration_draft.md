## 3. 보수 (a) — 절단 라벨: 교체안 vs 복원안

### 3.1 절단의 조작적 정의 (실측 요약)

R_MFE/MAE는 세 겹의 정책·설정 의존을 갖는다:

1. **관측 창 절단**: `[매수시간, 매도시간]` — 우측 끝이 현직 매도식(및 force_exit)에 의해 결정(§2.1). 조기 청산 정책일수록 MFE가 하방 편향, MAE는 SL 정책 임계에서 좌측 절단.
2. **평가 단위**: 현재가 기반 평가 수익률(`GetKiwoomPgSgSp`) — 체결 가능 가격(매수호가1) 기준이 아니며 tick2 불리체결 미반영.
3. **시작점**: 매수가 = 챔피언 런의 실제 체결가 — 당시 런의 슬리피지 설정에 의존.

### 3.2 A안 (권고) — 라벨 교체: `alpha_lab.dataset.labels` 고정지평 net_rate + 고정창 경로 MFE/MAE

**정의**: dedup 후 각 챔피언 거래(§4)에 대해 t0 = 진입시각(매수시간의 초). tick DB(read-only, `mode=ro`)에서 해당 거래일·종목 테이블을 재조인하고, **봉인된 P1/P2 라벨 규약 그대로** 재라벨한다:

- **진입**: (t0+1초) 행의 매도호가1. 그 초 결측 또는 매도호가1≤0 → 표본 제외(정직 제외, 카운트 보고).
- **L1-h (h∈{60,180,300})**: (t0+h초) 매수호가1 청산, tick2 불리체결 + 수수료(0.00015 매수/매도 각)·세금(0.0018) 차감 net_rate ≥ +0.01 → 1. 세 지평 전부 관측 가능한 표본만 채택.
- **L2 트리플배리어**: TP +3% / SL −2% / 300초 timeout, (t0+1 이후 관측 초들의) 매수호가1 경로 net_rate first-touch, 동시 터치 SL 우선, timeout → 0.
- **MFE_300 / MAE_300 (고정창 경로 극값 — 비절단 MFE/MAE 재정의)**: 관측 초 s ∈ (t0+1, t0+300] 에 대한 net_rate(entry, 매수호가1[s]) 의 max / min. **창이 고정(300초)이라 정책 절단이 없고**, 원안의 "MAE P95 억제형" 성공 기준을 비절단 지표로 보존한다.
- **절단 방지 그리드 규칙 재사용**: t0 > 09:25:00 인 거래는 h_max=300 관측 불가 → 표본 제외(카운트 보고). tick DB 커버리지(09:00:01~09:29:59) 밖 진입도 동일 처리.

**구현 재사용(실측)**: `alpha_lab/dataset/labels.py`가 이미 존재하며 공개 심볼 `net_rate`, `l1_label`, `l2_triple_barrier`, `adverse_fill`, `tick_size_below`, 상수 `FEE_RATE=0.00015`/`TAX_RATE=0.0018`/`ADVERSE_TICKS=2`/`L1_NET_THRESHOLD=0.01`/`TP_RATE=0.03`/`SL_RATE=-0.02`/`TIMEOUT_SEC=300`을 제공한다. 호가단위는 `ai_strategy_loop/fitness/slippage_profiles.py`의 공개 심볼 `krx_tick_size` 재사용 + 사설 심볼 미러(대조 테스트 봉인). MFE_300/MAE_300은 L2가 이미 순회하는 (t0+1, t0+300] 경로에서 부산물로 산출 가능 — 신규 DB 순회 없음.

**피처 윈도우(인과)**: 조건 피처는 [t0−w+1, t0] 관측 초에서만 계산(§5). 저장 데이터는 시장 원천이므로 백테스트 재조인에는 챔피언 자기 체결이 반영되지 않는다. 라이브에서 필터는 매수 신호 틱에서 평가되므로 최대 1초 위상차가 있다 — 한계로 명기(Phase 2 등가성 검사 대상).

### 3.3 B안 — 절단 명시 복원 (보유구간 + 잔여 경로 복원)

**정의**: 원문 §3.3이 언급한 제안 5 방식. 관측된 R_MFE/MAE(보유구간)에, 매도시간 이후 고정 지평까지의 잔여 경로를 tick 재조인으로 이어붙여 "비절단 MFE/MAE 추정치"를 합성한다: `MFE_복원 = max(R_MFE, 매도 후 잔여 경로 max)`.

**잔존 결함(기각 사유)**:

1. **평가 단위 혼합**: 보유구간은 현재가 평가 수익률(§3.1-2), 잔여 구간은 호가 기반 net_rate — 한 지표 안에서 단위가 갈라진다. 단위 통일을 위해 보유구간도 호가로 재평가하면 결국 A안의 전체 경로 재계산과 같아지고 R_MFE 관측값은 버려진다 — B안의 존재 이유 소멸.
2. **정책 의존 잔존**: 이어붙이는 절단점(매도시간)이 여전히 정책 산물이라 구간별 가중이 정책·경로 의존적이다.
3. **신규 구현 비용**: 보유 경로 재생 + 접합 + 단위 재조정은 제안 5의 재현 게이트(§4.4 심사 지적 — "사실상 미니 엔진 재구현", 단일 실패점)의 부담을 P3가 선취하는 구조다. 실행 비용 최소가 P3의 존재 근거(§3.3 "실행 비용 최소")인데 이를 스스로 훼손한다.

## 4. 보수 (b) — 다중 게이트 런 CSV 거래 dedup

### 4.1 identity 4-튜플의 조작 정의

**거래 identity = (전략명, 종목코드, 진입일자, 진입시각)** — 슬롯별 조작 정의:

| 슬롯 | 조작 정의 | 근거 실측 |
|---|---|---|
| 전략명 | CSV 파일명에서 접두 `{savename}_`(주식 tick = `stock_bt_`)와 접미 `_{save_time}`(말미 14자리 숫자)을 제거한 나머지 = `buystg_name` | `backtest/backtest.py:283` 파일명 규약의 역파싱 |
| 종목코드 | CSV에는 `종목명`만 있으므로(§2.2) 1차 키는 종목명 원문. 종목명→6자리 코드 매핑은 tick 재조인 단계에서 수행하고, 해당 거래일 tick DB에 그 코드 테이블이 실재하는지로 최종 검증. 매핑·테이블 부재 행은 재조인 표본에서 정직 제외(카운트 보고). 매핑 사전 원천은 Phase 0 봉인 시점에 확정(후보: 엔진 `dict_cn` 원천 테이블 — `backtest/backtest.py:345-346`이 종목명→코드 역매핑에 사용하는 것과 동일 원천) | `back_static.py:661-679` (CSV에 종목코드 부재), 일 DB 테이블명 = 6자리 코드(tick DB 계약) |
| 진입일자 | `매수시간`을 int64 캐스팅 후 문자열 앞 8자리(YYYYMMDD) | `cli/research_metrics.py:26-28`, `trade_ledger.py:40-42`와 동일 파생 |
| 진입시각 | `매수시간` 정규화 14자리 전체(YYYYMMDDHHMMSS — tick CSV는 초 해상도). float 저장분은 반올림 후 int64. 12자리(분 계열 레거시)는 SS=00 패딩하되, P3 대상은 주식 tick CSV라 원칙적으로 14자리만 | `trade_ledger.py:40` "매수시간(YYYYMMDDHHMM(SS))" 주석 |

동일 4-튜플 = 동일 진입 사건 1건. **A안 라벨 교체 하에서 identity는 '진입 사건'만 정의하며 라벨은 tick 재조인으로 재계산되므로, 어떤 런의 행을 대표로 남기든 라벨이 동일하다** — 이것이 §3.4의 dedup 시너지다.

### 4.2 충돌 처리 규칙 (결정론 — 전 규칙 봉인 대상)

| 코드 | 충돌 유형 | 판정 | 처리 규칙 |
|---|---|---|---|
| C1 | 완전 중복 — 4-튜플 동일 AND 결과 필드 근사 동일(수익률 절대차 ≤1e-9, 매도시간 동일) | 동일 런 재실행(의사반복) | 1건 채택 — save_time(파일명 접미) 최소 CSV의 행. 제거 수 카운트 |
| C2 | 결과 상이 — 4-튜플 동일, 결과 필드(매도시간·수익률 등) 상이 | 프로파일/매도식이 다른 게이트 런의 같은 진입 | 진입 사건은 1개 — 대표 1건 채택. 우선순위(봉인): ① 공식 동결 프로파일 런(warm64 계열) > ② save_time 최신 > ③ 파일명 사전순. A안 하에서 결과 필드는 라벨로 쓰지 않으므로 대표 선택이 라벨에 영향 없음(근거 §4.1) |
| C3 | 동명이식 — 같은 전략명, 다른 조건식 원문 | 전략명 문자열 충돌 | 런별 `buystg`/`sellstg` 원문이 DB_BACKTEST에 저장됨(`backtest.py:325-329`) → sha256 대조로 검증, 상이하면 `전략명#sha상위8`로 분리해 서로 다른 챔피언으로 취급. `trade_ledger` 경유 표본은 후보 identity(buy_sha256/sell_sha256)가 정본(`trade_ledger.py:3`) |
| C4 | 동일 CSV 내 동일 4-튜플 2행 | 데이터 이상(거래행은 라운드트립 1행 — 분할·추가매수는 `추가매수시간` 컬럼으로 한 행에 흡수) | 해당 4-튜플 전체 제외(보수) + 이상 보고 |

### 4.3 dedup 절차와 감사 보고 의무

```

   진단 카운트로만 보고). research_runs/alpha_lab_20260705/ 아래 receipt 저장
```

## 5. F1~F11 × 윈도우 피처 동결표

**출처 명시**: 제안 3 원문 전문은 리포지토리에 없다. 프로그램 문서 §4.3의 열거("F1~F11 × 윈도우 {5,10,30}s — TFI, 금액가중 TFI, QIB, OFI 근사, L1 잔량 소진 속도, top-of-book 집중도, 스프레드, 라운드피겨, 체결강도 동학, VI 근접 베토, 스푸핑 위험")가 유일 정본이며, F-번호는 이 열거 순서를 따른다. **세부 조작 정의(식·윈도우 적용 여부)는 본 초안이 처음 고정하는 것으로, §8 봉인의 확정 대상이다.**

공통 규약: 윈도우 w ∈ {5,10,30}초, 관측 창 W(t0,w) = [t0−w+1, t0]의 관측 초(결측 초 제외). W 내 관측 초 수 < max(2, ⌈w/2⌉) 이면 해당 피처 결측 → 그 (피처,윈도우) 시행에서만 표본 제외(카운트 보고). "t0−w 초" 참조는 W 내 가장 이른 관측 초로 대체(명시적 결측 규칙). 순간형은 t0 행만 사용.

### 6.3 Phase 1 — 오프라인 lift 스크리닝 (엔진 0회)

### 6.4 n_trials 산정 (P3 태그, 통합 원장 합산)

- **계상 규칙(봉인)**: 시행 1 = (피처,윈도우) × 라벨 표적 1건의 검정. 분위수 셀·플라시보·연도 폴드·부트스트랩은 해당 시행 내부 절차로 추가 계상하지 않는다. 챔피언 풀은 **단일 통합 풀 1회**(챔피언별 분해는 안정성 진단으로만 — 추가 계상 없음, 단 분해 결과로 채택/기각을 바꾸는 것은 금지).

- **기록 방식**: Phase 1 실행 직전 150을 선계상(pre-commit)하며, 미실행분 반환 없음(보수). 원장 = 봉인된 `preregistration_v1.json`(program=alpha_lab_v1)의 ledger 선언 그대로 — 경로 `docs/research/condition_research/research_runs/alpha_lab_20260705/n_trials_ledger.jsonl`, 선언 programs에 **"P3" 기등재**, 규칙 "탐색 전수 정직 합산, 이중 장부 금지". - 피처·라벨·윈도우 추가는 봉인 위반(`SealViolation`) — 새 봉인 문서 + 새 n_trials로만.

## 7. MVP 성공/포기 판정 기준 — 원문 유지 + 보정 명기

**원문(§4.3 MVP, 유지)**: "성공 = FDR 생존 + 4분위 단조 + 연도 폴드 부호 안정 + 플라시보 소멸 피처 ≥2개(그중 ≥1개 MAE P95 억제형). 포기 = 생존 0개 → 'orderbook 축에 엣지 없음' 결론 자체를 백테 0회로 확보." 1주 / 백테 0회 / 스윕 병행 가능 — 전부 유지.

**보정 사항(본 초안 — 봉인 시 확정)**:

1. **라벨 조작 정의 교체(§3 확정)**: 전 판정은 교체 라벨 6종 위에서. "MAE P95 억제형" = 피처 상위(또는 하위) 분위수 셀의 **MAE_300 P95가 전체 대비 유의하게 얕은**(부트스트랩 CI 분리) 피처 — 비절단 지표로 재정의.
2. **FDR q 통일**: 원문 §4.3은 q<0.1이었으나, MVP-2 결정(§3.2 — "MVP와 본 프로그램 간 임계값 이원화·쇼핑 금지, q=0.05 봉인")과의 정합을 위해 **q=0.05로 강화 통일을 권고**한다. 완화가 아닌 강화 방향이므로 원문 정신(보수성)에 부합. 봉인에서 최종 확정.
3. **최소 표본 봉인(§3.1-b·§6-7 계약 이행)**: `ai_strategy_loop/fitness/lift.py:38`의 `DEFAULT_MIN_SAMPLES = 5` 사용 금지 — P3 선언값: **dedup 후 풀 N ≥ 2,000, 분위수 셀당 n ≥ 500, 꼬리(P95) 추정 셀 동일 n ≥ 500**. 미달 시 해당 시행 '판정 불가' 처리(심사 1 "분위수 셀당 수십 건 위 꼬리 추정은 극히 잡음" 지적의 조작적 방어).
4. **연도 폴드 수 정정**: 원문 "연도 3/4 부호 안정"은 4폴드 가정이나, 발견창(2022-03~2024-12)의 연도 폴드는 2022(부분)/2023/2024 **3개**다. 보정 규칙: **≥2/3 연도 부호 일치 AND 불일치 연도의 부트스트랩 CI가 0을 포함**(유의한 역부호 불허). 검증창 2025-01~2026-02는 봉인 — MVP 판정에 접촉 금지, Phase 4 엔진 확인에서만 1회.
5. **판정 3분지(포기와 표본 부족의 구분)**: (i) 성공 기준 충족 → Phase 2 진행. (ii) 시행은 유효했으나 생존 0개 → **포기** = "orderbook 축(챔피언 조건부)에 엣지 없음"을 축원장에 결론으로 기록(원문 유지 — 실패도 자산). (iii) dedup 후 N<2,000 또는 유효 시행 비율 미달(결측 규칙로 시행 과반 탈락) → **판정 불가(표본 부족)** — 포기 결론을 기록하지 않으며, 풀 확장 재시도는 새 봉인 + 새 n_trials로만.

**잔존 리스크(보수 불가 — 심사 지적 명시 보존)**: ① 챔피언 진입 표본 선택 편향(비진입 초 플라시보가 계속 짊어짐 — §3.4), ② 검정력 부족 + 승자의 저주(수백~수천 표본 vs 150 시행 — min_n 봉인으로 완화하되 소멸 아님), ③ F4/F5 pandas↔엔진 스트리밍 idiom 드리프트와 w=30 N-함수 30항 전개 장황(§5 표기 — Phase 3 선행 등가성 검사가 관문), ④ Phase 3b와 제안 5 청산 축 중복(통합 의무 §6.5).
