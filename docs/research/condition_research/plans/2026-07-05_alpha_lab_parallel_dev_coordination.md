## 2. 판정 논거

### 2.1 엔진 경합 — 가장 단단한 제약

| 제안 | 엔진 무관 (지금 병행 가능) | 엔진 필요 (min 스윕과 직렬) |
|---|---|---|
| **1 규칙채굴** | 모듈 1~8 (registry→bridge→대시보드 API) | 모듈 9: ρ게이트 10회 + OOS |
| **2 이벤트** | P0~P4 (registry·감지기·측정·통계·OOS 측정) | P5: 패리티 + 공식 게이트 |
| **3 MCL** | Phase 0~2 (피처 동결·오프라인 lift·번역) ※구조결함 2건 보수 선행 | Phase 3: 힐클라임 ≤50회 |
| **5 챔피언증류** | **Phase 0만** (원장 배선, 연구레인 파일) | Phase 1~2: 증류 + 재현게이트(사실상 미니 엔진) — 엔진 의존 최고 |

도출:
1. **오프라인 절반은 진짜로 병행됨** — 1·2·3 발견 단계는 read-only tick DB + CPU뿐. 엔진이 바쁜 지금이 오프라인 작업의 적기.
2. **검증 꼬리는 4개가 서로도, min 스윕과도 직렬** — warm64 엔진은 하나. 모듈9·P5·Phase3·Phase1-2 동시 실행 불가. 스윕 종료 후 하나씩 배치.
3. **제안 5는 "동시"에 부적합** — 가치 핵심(청산 최적화)이 Phase 1부터 엔진에 묶임 + 설계서가 "warm64 스윕 종료 후 착수"로 못박음. 지금 할 수 있는 건 Phase 0 원장 배선뿐.

### 2.2 데이터 파이프라인 공유 경제성

"동시 개발"이 싼 건 **제안 1·2뿐**(`dataset/reader.py` 모듈 2 공유, 이후 분기). 반면:
- **제안 3** = 거래 CSV(R_MFE/MAE) + 진입시점 tick 재조인 → 별도 파이프라인 + **라벨 절단(censored) 구조결함 2건 보수 선행 필수**(절단 처리·거래 dedup 규칙).
- **제안 5** = 챔피언 거래 원장(37컬럼) → 또 다른 별도 파이프라인 + 재현게이트 단일 실패점.

→ 1·2·3·5 동시 = **3개 독립 데이터 파이프라인** + 통합 n_trials 축원장 공유로 **다중검정 부담 증가**. 심사가 "제안 3·5는 조건부 대기 — 1차 2건 오프라인 빌드 대기 시간에 선행"으로 우선순위를 정한 이유와 정면 충돌.

### 2.3 대시보드 머지 토폴로지 — 모듈 8을 둘로 쪼갠다

| 알파 모듈 8 구성 | 충돌 위험 | 처방 |

## 3. 결정 — 계층형 병행

### 3.1 지금 (엔진 = min 스윕 점유 중, 오프라인 병행)

```
레인 A [주력]  제안 1 모듈 1~7  ──┐ 모듈 2(reader) 공유 후
레인 B [병행]  제안 2 P0~P4    ──┘ 분기
레인 C [3번째] 제안 3: 구조결함 2건 설계·보수 → Phase 0~2 오프라인 lift
레인 D [기회]  제안 5: Phase 0 원장 배선만 (연구레인 파일)
대시보드      알파 /api/alpha/* 백엔드만
```

### 3.2 min 스윕 종료 후 (엔진 free — 반드시 직렬)

```
모듈9(제안1) → P5(제안2) → Phase3(제안3) → Phase1-2(제안5)  ← 하나씩
```

### 3.3 머지 순서

```
v4 → wt-dev (PR) 먼저  →  알파 프론트 패널을 v4 ui/ 구조에 저작  →  알파 → wt-dev (PR)
```

- **v4 선(先) 머지 근거**: v4는 27커밋짜리 프론트 대개편으로 대시보드 서브트리를 크게 건드림. 먼저 착지시키면 알파는 자기 패널 하나를 최종 구조에 한 번만 저작(빌드-후-재작업 회피).
- 알파는 v4 착지 전까지 대시보드 작업을 **백엔드 API로 한정**(머지 순서 무관).

### 3.4 I/O 주의

지금 min 스윕이 62GB DB를 순회 중 → 알파 **본 빌드(952일)** 는 스윕 I/O와 경합. MVP 빌드(60일 ≈ 150만 행)는 작아 무해하나, 본 빌드는 스윕 휴지기에 배치(연구 프로그램 §5 규칙 1).

## 4. 불변 조건 재확인 (핸드오프 §5 승계)

1. DB 읽기는 전부 `file:...?mode=ro` URI (junction이 read-write — 실수 쓰기 시 wt-dev 공유 DB 손상).
2. 채굴 표본에 거래 CSV 사용 금지(선택 편향) — 단 제안 3은 설계상 거래 CSV를 쓰므로 절단·dedup 보수 후에만.
3. 미래 누수 차단 — 피처는 저장 54컬럼 + 같은 초 사칙연산만(v1).
4. 사전등록 봉인 우선 — registry sha 커밋 후에만 채굴.
5. 연구 레인 전용 — `backtest/graph/` 불가침, 최종 조건식은 기존 게이트 무특혜 통과.
6. 전략 DB 쓰기(모듈 7)는 백업 선행 + INSERT-only + 충돌 보고.
7. **통합 n_trials 축원장 단일화** — 제안 1·2·3·5의 탐색 전수를 하나의 원장에 정직 합산(이중 장부 금지).
