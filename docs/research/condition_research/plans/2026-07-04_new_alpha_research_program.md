## 1. 배경 — 왜 기존 생성-테스트 루프와 구분되는 새 탐사 축이 필요한가

**결론: 기존 AI 루프의 "조건식 생성 → 백테스트 채점" 방향은 실측상 한계에 도달했고, 남은 미개척지는 "데이터가 먼저 말하게 하는" 역방향 탐사로만 열린다.**

근거(전부 기존 실측·원장 기록):

1. **콜드 LLM 생성 전멸(0/88)**: gen1~23에 걸친 콜드 생성 계열은 게이트 통과 0건. 사전지식(prior)에서 출발하는 생성은 이 데이터에서 엣지를 만들지 못한다는 것이 반복 확인됐다.
2. **힐클라임은 유일 검증된 개선 경로이나 국소최적**: 인간 시드 + 단일 축 힐클라임(rr8_12 계보 4/4 연도 OOS, r8_exclude_cap_lt_1500 공식 OOS +7.29M, hard-stop 매도 축 +40K/MDD −1.45%p)만 성공했다. 그러나 이 경로는 인간이 선언한 시드 주변의 국소 탐색이며, 시드 공급 자체가 병목이다(2026-07-02 조건식 루프 전수감사: 병목=생성기 미배선).
3. **미개척 축이 실측으로 특정돼 있다**: orderbook/미시구조 축 커버리지 22.1%(최약 축), 레짐(전략 가동 스케줄) 레이어 부재, 청산 최적화(챔피언 표본 487거래에서 평균 MFE 2.83% vs 실현 0.39% — 거래당 평균 2.44%p giveback) — 어느 것도 "조건식 텍스트 생성"으로는 접근되지 않았던 축이다.
4. **반복 금지가 확정된 실패 교훈**: backfinder lift는 lookahead 편향(claim C20), 사후 CSV 슬라이스 ≠ 추출 가능 엣지(06-14), 두 번째 기회 계열(흡수·되돌림·재진입) 28좌표 전멸(F04/F18), CSS_V7 완결전략 번역 실패(MDD 51~65%, '서사→코드' 간극). 새 탐사 축은 이 실패 좌표를 **구조적으로**(운영 규율이 아니라 설계 자체로) 회피해야 한다.
5. **공통 설계 원리 — 백테스트 예산의 역전**: 5개 제안 전부가 "백테스트 = 생성 루프의 평가기"를 "백테스트 = 최종 심판(2차 필터)"으로 강등하고, 발견 단계를 오프라인(틱 DB 952개·62GB, 거래 CSV 5,971~5,982개, sklearn 1.8.0/scipy 1.17.1 기설치)으로 옮긴다. 오프라인 1회 연산이 수천 후보의 동시 평가와 등가이므로, 격자 스윕 288쌍 대비 동급 이하 예산으로 탐색 공간이 수십 배 넓어진다.

## 3. 우선순위 확정

### 3.1 판정: 1차 착수 = 제안 1(규칙 채굴) + 제안 2(이벤트 스터디)

**두 심사 합산 상위 2개(83, 82)이자 유일한 strong+strong 조합.** 우선순위 근거:

1. **스누핑 방어가 기계적**: 제안 2는 해시 봉인 사전등록 + 전 격자 BH-FDR + 날짜 블록 부트스트랩 + 이중 플라시보 + 셀당 1회 OOS로 5개 중 가장 기계적인 방어. 제안 1은 전향 라벨 + 화이트리스트 피처 + purged/embargo CV(claim C22 이행) + 최종 연도 완전 격리로 구조 자체가 견고.
2. **표본 규모**: 제안 1은 전수 시점 격자(일별 평균 ~77 종목 테이블 기준 명목 ≈1.2억 행, stride 5초 시 ~2,400만 행), 제안 2는 사건족당 연 ≥2,000건 목표 — 소표본 문제(제안 3·5의 수백 건, 제안 4의 n≈2 레짐 사건)와 근본적으로 다른 체급.
3. **번역 경로가 정의상 닫혀 있음**: 제안 1은 화이트리스트 피처 ↔ 조건식 템플릿 1:1(축-정렬 임계값 AND 결합 → 기계 번역, 생성적 자유도 0), 제안 2는 실재 확인된 화이트리스트 변수(`VI가격N`, `라운드피겨위5호가이내N`, `고가미갱신지속틱수`, `거래대금급증`)만 사용 — CSS_V7 '서사→코드' 간극이 구조적으로 부재.
4. **직교성**: 두 제안 모두 데이터-우선(data-first) 발견이며 기존 루프(시드 힐클라임·격자)와 발견 방향이 역전 — 산출물은 기존 루프의 시드로 환류된다(§7).
5. **상호 보완**: 제안 1은 "상태 단면의 임계값 규칙", 제안 2는 "사건(전이) 조건부 분포" — 탐색 공간이 겹치지 않고, 오프라인 표본·라벨 빌드 인프라(틱 DB 선형 스캔, 전향 라벨)를 공유해 빌드 비용을 분담할 수 있다.

**병행 착수 시 의무 조정(심사 1 공통 권고 반영)**:
- **(a) 프로그램 간 통합 n_trials 원장**: 제안 1의 추출 리프 전수 + 제안 2의 격자 셀 전수를 하나의 축 원장에 정직 합산해 전역 다중검정을 관리한다. 이중 장부 금지.
- **(b) `ai_strategy_loop/fitness/lift.py`의 `DEFAULT_MIN_SAMPLES=5`는 기본값이 지나치게 낮음** — 전 프로그램에서 프로그램별 사전 선언 최소 표본(제안 1: 리프 support ≥2,000, 제안 2: 셀 최소 표본 상향값)으로 반드시 상향 고정하고, 그 값을 사전등록 문서에 봉인한다.
- **(c) 일 단위 블록 부트스트랩을 제안 1 채굴(P1) 단계에 이식**: stride 5초·중첩 horizon 라벨의 단면·시계열 상관으로 유효 표본이 명목보다 훨씬 작으므로, 리프 lift 유의성 판정에 일 블록 부트스트랩을 채굴 단계부터 적용한다(제안 2의 P3 규율을 공유).
- **(d) 발견 중복 관리**: 제안 1의 발견 공간(화이트리스트 피처 축-정렬 임계값)이 진행 중 시드 격자 프로그램과 부분 중복 — 생존 규칙 등재 시 격자 좌표와의 중복 여부를 passport에 명기한다.

### 3.2 1차 착수 MVP 정의 (각 1주, 성공/포기 판정 명시)

#### MVP-1: 규칙 채굴 (제안 1)

- **범위**: 2023년 30일 + 2024년 30일(계절 매칭 60일), stride 5초 → 약 150만 행(일별 종목 테이블 수 가변, 평균 ~77 기준). 피처 25개(화이트리스트 — **P0 사전등록에서 25개 전수 열거·봉인하고 각 피처를 '저장 54컬럼 / 엔진 재계산 파생 19항' 중 하나로 분류 명기**, §4.1 데이터 근거), 라벨 L1-180초(tick2 순수익 ≥ +1% = 양성).
- **일정**: D1-2 표본·라벨 빌더 + lookahead 정적 감사 + (파생 피처 채택 시) avg_list 동결값 rolling 패리티 재계산기·엔진 산출값 스팟 대조 → D3 트리/HistGBM 학습 + 리프 추출(min_leaf 500 하향) → D4 양성 대조(rr8_12 진입 절 규칙 강제 주입 → 양의 lift 검출 확인) → D5 상위 10규칙 번역·연구 레인 등재·훈련 창 재현 백테 10회(자원 항 MVP 백테 상한 사용 — ρ 표본 n 확보 목적) → D6-7 교차창 안정성(2023↔2024 상호 lift) + 판정.
- **성공 판정**: (a) 양성 대조 lift > 1 검출, (b) 교차창 양방향 lift ≥ 1.3 규칙 ≥ 1개, (c) 채굴-백테 순위 Spearman ρ ≥ 0.5(D5 10규칙, n=10 — 판정 3분지는 아래 심사 반영 수정).
- **포기 판정**: 양성 대조 실패(파이프라인 결함) / 전 규칙 교차창 lift < 1.1(신호 부재) / ρ < 0.2(번역·체결 갭 — CSS_V7 재판) / 빌드 3일 초과(비용 구조 불성립).
- **스윕 제약**: D5 백테는 warm64 스윕 종료 후로 스케줄. D1-4는 읽기 전용이나 62GB DB 순회 I/O가 스윕과 경합하지 않도록 야간/스윕 휴지기 배치.
- **심사 반영 수정**: D3 리프 유의성 판정에 일 블록 부트스트랩 적용(§3.1-c). ρ 게이트가 빌드 비용 전액을 인질로 잡는 구조이므로, **MVP의 ρ≥0.5 통과를 본 빌드(952일 전체) 착수의 전제 조건**으로 격상한다 — MVP 실패 시 본 빌드 비용을 치르지 않는다.
- **ρ 게이트 판정 규칙(사전 봉인, 임계값 쇼핑 금지)**: ρ는 유의성 검정이 아니라 **사전 봉인된 점추정 결정 임계**로 선언한다 — n=5로는 Spearman α=0.05 임계값이 0.9라 검정으로서 거의 무정보이므로, D5 백테를 10규칙으로 고정해 n=10을 확보한다(그래도 ρ=0.5는 α=0.05 임계 ~0.56 미만 — 통계적 확증이 아닌 진행/중단 결정 규칙임을 명시). 판정은 3분지로 완결한다: **(i) ρ≥0.5 → 본 빌드 착수. (ii) 0.2≤ρ<0.5(중간지대) → 본 빌드 보류.** 번역 계층 결함(화이트리스트↔조건식 사전 오류, 체결 모델 불일치) 진단·수정에 한해 1회만 재판정을 허용하며, 재판정은 동일 10규칙 재백테(≤10회 추가)로 수행한다. 규칙 재선별·임계값 하향·표본창 교체는 금지. 재판정도 ρ<0.5면 포기와 동일 처리. **(iii) ρ<0.2 → 즉시 포기**(번역·체결 갭 — CSS_V7 재판).

#### MVP-2: 이벤트 스터디 (제안 2)

- **범위**: E1(VI 해제)·E4(초당거래대금 서지) 2족만, 발견 구간 2022-03~2024-12, 지평 3개(+30/60/120초). P0 사전등록 레지스트리 1문서 + P1~P3 오프라인 실행(엔진 0회, DB 읽기 전용).

- **스윕 제약**: 전 과정 읽기 전용이라 스윕과 병행 가능하나, DB I/O 경합 회피를 위해 스윕 휴지기 배치 권장. P5(엔진 확인)는 스윕 종료 후에만.

**데이터 근거(실측)**: `VI해제시간`·`VI가격`·`VI호가단위`·`라운드피겨위5호가이내`가 틱 DB 54컬럼 원시 저장(`utility/setting_base.py:155-166`), 화이트리스트 181함수에 `VI가격N`·`라운드피겨위5호가이내N`·`고가미갱신지속틱수`·`거래대금급증` 실재(`utility/ai_agent/system_prompt/v1/variables_reference.md`), VI 가드 관용구 `현재가 < VI가격` 기존 사전 존재(`idiom_dictionary.md:122`). 통계 모듈(`lift.py`·`placebo_check.py`·`holdout.py`·`multiyear.py`·`overfit_stats.py`·`slippage_stress.py`·`positive_control.py`·`edge_ratio.py`) 전부 실재. 일봉 DB 없음 → 갭은 `등락율`로 전일종가 역산. 유니버스 소급 불가 → 사건 모집단 = moneytop 수집 시점 유니버스 그대로(측정-배포 정합 보장).

**파이프라인**: P0 사건 레지스트리 사전등록(격자 총 셀 수 = n_trials 원장 합산) → P1 사건 추출기(`microstructure_analyzer.py` DB 읽기 패턴 재사용, 952일 선형 스캔, 인과적 탐지) → P2 전방 결과 측정(진입가 = t0+1초 `매도호가1` + tick2, `초당거래대금==0` 체결 금지, 09:30 절단) → P3 통계(`lift.py` 셀별 EV·lift·payoff + 날짜 블록 부트스트랩 + BH-FDR q<0.05, 셀 최소 표본 상향 봉인) → P4 OOS 봉인 평가(발견 2022-03~2024-12 / 검증 2025-01~2026-02, FDR 생존 셀만 각 1회, 재시도 금지) → P5 조건식 번역 + 오프라인↔엔진 패리티 검사 ≥95% + 공식 게이트(스윕 종료 후) → P6 힐클라임 접목.

**핵심 아이디어**: 새 조건식 대신, OOS 통과 전략(r8 계열, exit2_balance, THETA/T2C3)을 "어느 날 얼마나 켤지" 결정하는 일 단위 상위 신호. 근거: Q4 2025 공식 OOS 실측에서 r8_4 = −835,479원 vs exit2_balance = +640,100원 — 같은 기간 전략-레짐 궁합이 정반대(2026-06-18 문서). 메타 레이어 작동 전례: exit2 prior-month 규칙(+31.7M), 06-18 월간 선행 규칙 중 유일한 동시 개선(`r8_4+exit2_balance` 전월 −50만 이하 제외: +196,644원 / MDD −0.12%p). 차별점 = granularity를 일 단위로, 입력을 자기 P&L이 아닌 시장 상태 집계 피처(breadth·단면 분산·moneytop churn·VI 발동 수 등 사전 선언 ≤20개)로 확장. 산출물은 조건식이 아니라 장전 포트폴리오 배정 규칙(depth≤2 스텀프, 출력 {full/half/off/exit2 재배정}, 후보 ≈240 전수 n_trials 합산). MVP는 신규 백테 0회(기존 공식 OOS CSV 15개 재채점), 본 프로그램 전체 신규 엔진 백테 ≤15회 — 5개 중 최저가.

**검증 설계**: 누출 감사(일 D 신호는 D−1까지 또는 D 첫 K초만), 라벨 셔플 음성 대조, 양성 대조(Q4 2025 r8_4 decoherence 블라인드 재발견), 1-이벤트 레짐 검사(클러스터 1개=Q4 암기 시 기각, 2022 약세장 중립 이상), 비대칭 목적함수 사전 선언(수익 −1%당 MDD −3%p 이상).

**심사 지적 (보존)**:
- [심사 1, **치명 감점**] 유효 레짐 사건 n≈2(Q4 2025 + 2022 약세장) — 일 단위 ~950 표본도 자기상관으로 유효 n 급감, 어떤 통제 장치도 사건 수를 늘리지 못함(표본 축 3점).
- [심사 1, **프로그램 수준 스누핑**] 가설 자체가 Q4 2025 붕괴를 관측한 후 그 사건을 감쇠하도록 설계 — 규칙 적합을 2024까지 봉인해도 피처 가족 선택·목적함수 설계가 검증 표적을 이미 본 상태라 워크포워드가 진정한 블라인드가 아님(양성 대조가 순환 논증 위험).

## 6. 공통 검증 계약 — 새 방법론에 특혜 없음

**어떤 방법론이든, 최종 산출 조건식은 기존 게이트 체인을 그대로, 전량, 순서대로 통과해야 한다:**

```
스모크(문법·정적 검사) → train(훈련 창 재현) → OOS(블라인드 연도, 재시도 금지) → 슬리피지(tick2 생존, tick3 민감도)
```

세부 계약(5개 제안 공통 구속):

1. **연구 레인 전용**: 모든 실험·등재·백테는 연구 레인에서만. 공식 프로파일은 동결본(`smoke_config_tick_official_full_warm64_20260704.json` 계열)을 사용하고 임의 수정 금지.
2. **n_trials 정직 합산**: 엔진 투입분이 아니라 **탐색 전수**(추출 리프 전수, 격자 셀 전수, 임계값 스캔 전수)를 통합 축 원장에 기록. 다중검정 통계(PBO/CSCV·DSR — `overfit_stats.py`)는 advisory라는 실측 한계를 인지하고, 사전 등록·동결된 채택 임계값을 하드 게이트로 삼는다.
3. **OOS-blind**: 최종 검증 연도는 탐색 전 과정에서 완전 격리(제안 1: 2025-03~2026-02, 제안 2: 2025-01~2026-02). 승격 후보만 각 1회 평가, 재시도 금지.
4. **ML 사용 시 purged/embargo CV 의무(claim C22)**: 일 단위 그룹, 블록 경계 purge ≥1거래일 + embargo(제안 1: 5거래일). 일 단위 블록 부트스트랩을 발견 단계 유의성 판정에 공통 적용.
5. **슬리피지 생존 기준**: tick2 차감 후 순수익 양수(rr8_12 breakeven 2.03틱 실질 한계선 기준), `slippage_stress.py` tick3 민감도 통과를 승격 조건에 포함.
6. **양성·음성 대조 의무**: positive control(기존 4/4 세트, 자동화 실측 19/19 gate_healthy 기준) + placebo(`placebo_check.py` 패턴 — 무작위 진입/무작위 시각/라벨 셔플 중 방법론별 해당형).
7. **최소 표본 상향 고정**: `lift.py` `DEFAULT_MIN_SAMPLES=5`를 그대로 쓰는 것을 금지 — 프로그램별 사전 선언값으로 상향 고정하고 사전등록 문서에 봉인.
8. **사망 패밀리 감시**: 산출 규칙이 두 번째 기회 계열(흡수·되돌림·재진입, F04/F18 28좌표)과 패턴 일치하면 자동 태깅하고 승격 요건을 상향(연도 재현 4/4 + placebo 통과).
9. **번역 충실도**: 오프라인 발견 ↔ 엔진 결과의 정합을 정량 게이트로 감시(제안 1: Spearman ρ, 제안 2: 패리티 ≥95%, 제안 3: 등가성 스팟체크, 제안 5: 재현 게이트 ≤0.1%p). 미달 시 개별 규칙 폐기가 아니라 해당 축/파이프라인 중단 판정.

## 7. 기존 루프와의 관계 — 대체가 아니라 시드 공급원 다변화

**이 프로그램은 기존 정제 루프(인간 시드 + 힐클라임 + 격자 + ablation + 축원장)를 대체하지 않는다. 병목이었던 "시드 공급"을 데이터-우선 발견으로 다변화하는 상류(upstream) 계층이다.**

접점 명세:

1. **산출물 → 시드 풀**: 각 방법론의 생존 규칙(§6 계약 통과분)은 완결 전략이 아니라 **측정된 사전확률(EV·lift·payoff·연도별 성적)이 붙은 시드**로 격자 시드 풀에 편입되고, 유일하게 검증된 개선 경로인 힐클라임의 출발점이 된다.
2. **축원장·passport 등재**: 생존 규칙은 기존 축원장 + `condition_passports` 체계에 provenance(발견 방법론, 리프 경로/사건 정의/증류 원장 identity, n_trials 문맥, 연도별 성적)와 함께 등재한다. 격자 프로그램 좌표와의 중복 여부를 passport에 명기해 발견 중복을 관리한다(§3.1-d).
3. **ablation 접점**: 레이어형 산출물(제안 3의 필터/베토, 제안 5의 청산 절)은 기존 ablation 자산으로 해당 축이 load-bearing임을 증명한 뒤에만 승격 후보가 된다.
4. **평가 인프라 공유**: 엔진 검증은 전량 기존 배치 인프라(`claude_candidate_batch_eval` + 동결 공식 프로파일 + 48쌍 청크 p5 프로토콜, e32 공식 OOS 설정)를 재사용한다 — 신규 평가 경로를 만들지 않는다.
5. **실패도 자산**: 각 MVP의 포기 판정(예: 제안 3 "orderbook 축에 엣지 없음", 제안 2 "사건 전 셀 tick2 미달")은 그 자체로 축원장에 기록될 결론이며, 백테 예산 소모 없이 미개척지 지도를 갱신한다.
6. **기존 루프의 계속**: 진행 중인 시드 격자 프로그램(warm64 스윕 포함)은 본 프로그램과 무관하게 계속된다. 두 레인의 n_trials는 각자 원장을 유지하되, 발견 공간이 겹치는 제안 1은 §3.1-a·d의 통합 관리 규칙을 따른다.
