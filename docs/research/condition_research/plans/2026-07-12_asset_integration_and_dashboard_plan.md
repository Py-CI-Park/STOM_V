## 0. 쉬운 요약

부품(자산)이 충분히 쌓였다. 이제 세 가지를 한다: **① 창고 정리**(어느 부품이 어디 있고 서로 어떻게 연결되는지 카탈로그 DB로), **② 조립 라인 표준화**(연구 1건이 거치는 절차를 SOP+자동 게이트로), **③ 전시실 연결**(사장님이 대시보드에서 지도·판정·실전 채점을 직접 보게). 셋 다 이미 만든 것 위에 층을 얹는 작업이라 신규 위험이 작다.

## 2. 프로세스 구조화 — 표준 연구 사이클(SOP) + 자동화 장치

**SOP (7회 실증된 절차의 명문화)**:

```
아이디어 → ①원장 대조(창 지위·죽은 공간·기존 판정) → ②사전등록 초안(에이전트) →
③메인 검토·봉인 결정·커밋 → ④측정(체크포인트 러너, read-only) → ⑤판정(봉인 문구 그대로)
→ ⑥적대/독립 검산 → ⑦원장 기록 + 커밋(한국어 판정 메시지) → ⑧핸드오프 갱신
```

**자동화 장치 (메타 백로그 채택분 — 구현 순서 확정)**:

| 순서 | 도구 | 역할 | 출처 |
|---|---|---|---|
| P1-1 | `alpha_lab/discipline/` 가드 라이브러리 | known-창 차단·n_trials 자동 append·사전등록 스켈레톤 생성 — 규율을 양심에서 코드로 | 백로그 A1 |
| P1-2 | prereg-diff | 봉인 문서 ↔ 결과 json 자동 대조(경계·분모·창·비용) | A5 |
| P1-3 | measure_gate | 배치 기동 전 "봉인 커밋 존재·코드 clean·sha 일치" 검사 — O-1G 코드 커밋 누락 유형 재발 차단 | A7 |
| P1-4 | 분리형 배치 러너+워치독 | 배치가 세션과 함께 죽는 문제(2회 실측) 구조적 제거 | A18·A19 |
| P1-5 | ledger-lint + n_trials 병기 리포터 | 문서의 known 접촉·병기 누락 자동 검출 | A4·A6 |

## 3. 연구 자산 데이터베이스화 — `research_assets` 카탈로그

**원칙**: 정본은 기존 파일(json/parquet/md — git 추적 or 영수증 재생성 가능). DB는 **복제가 아니라 카탈로그+요약 계층** — 대시보드와 후속 연구의 단일 조회 창구.

| 테이블 | 내용 | 원천 |
|---|---|---|
| assets | 자산 레지스트리: id·종류·경로·생산 커밋·봉인 문서·창·지위 딱지(예: "함정 설명 전용"·"RR8_12 출구 조건부")·재생성 명령 | 본 계획 §1 표 |
| judgments | 판정 카드: 계열·결과(strong/weak/kill/inconclusive/양성)·핵심 수치·원장 행 번호·리포트 경로 | 판정 json 7건 |
| clauses | D1 절별 전 수치(39절: Δ·CI·MDE·분류) + W5 어휘 유형 | d1_summary + w5 json |
| strategies | W2 랭킹 + API 호환 + 원문 sha | w2 json |
| cells | S-v1/O-1G 셀 통합 뷰(파티션 union, 딱지 컬럼 필수) | stats_map*.db |
| ledger_mirror | n_trials 장부 미러(조회용) | jsonl |

- 위치: `research_runs/alpha_restart_20260710/research_assets.db` (git 제외, **빌더 스크립트+스키마+빌드 영수증만 커밋** — 언제든 재생성 가능).
- **지도 추가 적재(수집 아님 — 기존 원천 DB에서 추출)**: ① 돌파 온셋 은행(O-3 봉인 후) ② D9 전이 온셋 은행(D5 봉인 후) ③ min veto 오버레이(audit-grade 딱지) ④ 2절 교호작용 비트 확장 — 전부 해당 연구의 사전등록에 종속(카탈로그는 그릇만 준비).

## 4. 대시보드 v4 적용 방안 (wt-dev `loop/process-research-pipeline`)

**전제·규율**: ① 대시보드는 **read-only 뷰어** — 어떤 수치도 재계산하지 않고 research_assets 카탈로그만 읽는다(수치 불일치 원천 차단, 백로그 A10 원칙) ② 감사 구속 조항을 렌더링 규칙으로 강제(A11): n<2,000 회색, CI 하한 색상, "설명 지도/RR8_12 조건부/audit-grade" 워터마크 상시 ③ wt-dev 레인 코드 변경이므로 **구현은 사용자 go + 기존 V4 대시보드 PR(베이스 동일 브랜치, 보류 중)과 조율** ④ wt-alpha의 산출물을 wt-dev가 읽는 경로 문제: 카탈로그 DB 경로를 설정값으로(레인 간 심볼릭 의존 금지).

**신규 뷰 5종 (명세 우선순위 순)**:

| 뷰 | 내용 | 데이터 계약(카탈로그 테이블) |
|---|---|---|
| V1 연구 파이프라인 보드 | 판정 체인 타임라인(커밋·결과·원장 행), 진행 중 연구 상태 | judgments·ledger_mirror |
| V2 함정 지도 히트맵 | O-1G 144셀 + S-v1 셀 인터랙티브(출구·진입창 선택) — "피할 구역" 시각화 | cells |
| V3 절 실험실 | D1 39절 카드(압력 5종 강조·역생산 6종 경고색), W5 유형 분포 | clauses |
| V4 출구 은행 조회 | 조건(시간·갭·시총 등) 필터 → 온셋 L3 분포 즉석 표시(사전 집계 셀만 — 원시 재계산 금지) | cells(+은행 사전집계) |

## 5. 보완 목록 (본 계획이 함께 해소하는 갭)

1. O-1G 코드 커밋 누락이 보여준 "측정 코드 추적 공백" → P1-3 measure_gate.
2. parquet 등 git 제외 자산의 유실 위험 → assets 테이블의 "재생성 명령" 컬럼(영수증 연동)으로 상시 복구 가능.
3. 문서 크로스링크(계획↔봉인↔증거) 수작업 → 카탈로그가 기계가독 링크 제공, ledger-lint가 검증.
4. GA/최적화 결과 해석 주의(엔진 dict 공유 버그 — 수정 보류) → judgments에 "GA 경로 산출물" 플래그 컬럼으로 경고 표시.
