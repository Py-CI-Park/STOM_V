# OOS 거짓 기각 진단 + 연구 갭 1~5 해소 개발 연구·계획 (2026-06-12)

> 사용자 질문: "OOS가 걸러내서 좋은 조건 성과가 걸러지는 게 문제라면 해결하고
> 더 좋은 조건식을 찾는 프로세스를 연구하라." 본 문서가 그 답이며,
> 갭 1~5의 코드 수준 개발 설계와 실행 계획을 포함한다.

## 0. 결론 먼저

1. **거짓 기각 위험은 실재한다 — 단 원인은 OOS 규율이 아니라 표본 크기다.**
   9건 표본의 이항 계산: 진짜 에지가 있는 전략도 17~27% 확률로 합계 적자로
   끝난다(아래 §1.2). walk-forward 164건이면 0.5% 미만.
2. **해법은 규율 완화가 아니라 증거 확장이다**: ① 표본 큰 검증(V4)의 지위
   승격 ② 기각자의 '패자부활 레지스트리'(신규 데이터 도착 시 전수 자동
   재검증 — 사후 재선택 금지와 양립) ③ 신뢰구간 advisory 공시.
3. 갭 1~5는 전부 **엔진·하드게이트 무수정** 경로로 개발 가능하다(§3).

## 1. 문제 정의 — OOS가 좋은 조건식을 걸러낼 가능성

### 1.1 현행 판정 구조

고정 OOS 2022(1년, 후보 ~55건)·2026(2개월, ~9건)에서 p0 §5 기준
(연 흑자·MDD·거래수·payoff)을 이항(통과/기각)으로 적용한다. 기각 시
재선택 금지(같은 데이터 기준).

### 1.2 표본 크기의 정량 진단 (2026-06-12 계산, comb 기반 정확 이항)

진짜 수익 구조(승률 p·payoff u)를 가정하고 n건 합계가 ≤0일 확률:

| n (거래수) | 승률 .50/payoff 1.5 | .55/1.34 | .60/1.2 |
|---|---|---|---|
| **9 (고정 OOS 2026)** | **25.4%** | **16.6%** | **26.7%** |
| 55 (고정 OOS 2022) | 8.9% | 3.4% | 2.0% |
| **164 (V4 walk-forward 누적)** | **0.5%** | **0.1%** | **0.0%** |

**→ 2026 단독 흑자 요구는 동전 던지기의 1/4 수준 잡음을 판정에 섞는다.**

### 1.3 단, 지금까지의 기각 3건은 거짓 기각이 아닐 공산이 크다 (정직 재검토)

| 기각 | 표본 외 동반 증거 |
|---|---|
| C7 (6/10) | OOS 2022·2026 양쪽 열위 — 단일 표본 의존 아님 |
| EXIT2C take9 | maxMDD 20.14 위배 + 2026 시드 대비 열위(상대 비교는 표본 잡음에 강함 — 같은 창 동시 재측정이므로 시장 운이 양쪽에 공통) |
| EXIT2NA take6 | maxMDD 20.87 위배 + payoff 0.97<1 + **시드보다 절대 열위** + 비공격일수록 악화(단조 역방향 — 잡음이면 무작위였을 것) |

즉 기각들은 "흑자 미달" 단독이 아니라 구조 증거가 겹쳤다. **문제는 과거
판정이 아니라, 미래에 표본 단독으로 기각될 후보가 나올 수 있는 규칙 구조다.**

## 2. 해결책 — 더 좋은 조건식을 찾는 프로세스 개선 (규율 보존)

> 원칙: p0 §5 기준 자체는 유지한다(완화 금지 — 완화는 과적합 문으로 역행).
> 추가하는 것은 **증거 트랙과 부활 절차**다. 전부 사전선언으로만 도입.

### S1. 상대 판정의 명문화 (즉시 — 문서 개정)
같은 창·같은 배치에서 시드 동시 재측정 후 "시드 대비 비열등 + 절대 기준"을
공동 1차 증거로 명문화. 시장 공통 운이 상쇄되므로 9건에서도 정보량이 있다
(THETA의 2026 통과 논거가 정확히 이것이었다).

### S2. V4 walk-forward의 지위 승격 + 파이프라인 9번째 스테이지 (개발)
- 근거: §1.2 — 164건 누적은 거짓 기각 0.5% 미만. 고정 OOS의 "미접촉 순수성"
  은 유지하되, 표본 판정력은 V4가 담당하는 역할 분담.
- 코드: `research_pipeline.py` STAGES에 `walkforward` 추가(동결 후·OOS 후
  자동 실행), `build_stage_command()`에 wf 시나리오 명령 추가. 기존
  wf_scenarioD 도구 재사용 — 새 평가 로직 0. 단위 테스트:
  `pending_stages`/`build_stage_command` 케이스 확장.

### S3. OOS 차이의 블록 부트스트랩 신뢰구간 advisory (개발)
- (후보−시드) 일별 손익 차이의 블록 부트스트랩 CI를 OOS 결과에 병기.
  "기각이지만 CI가 0을 크게 걸침 = 표본 부족 신호"를 수치로 공시.
- 코드: `fitness/overfit_stats.py`의 `block_bootstrap_daily` 재사용 —
  `oos_diff_ci()` 순수 함수 추가 + 결산 뷰(/freeze_verdict) 1행 표시.

### S4. 패자부활 레지스트리 (오늘 구현 — 본 커밋 포함)
- **거짓 기각의 구조적 안전망**: 동결-기각자는 삭제가 아니라
  `rejected_registry.json`에 등재된다. **신규 데이터**(예: 사용자가 추가할
  2026-03+)가 도착하면 1-커맨드로 **전 기각자 + 챔피언 + 시드**를 같은
  배치에서 자동 재측정한다.
- 규율 양립 논거: 사후 재선택 금지는 "같은 데이터를 본 뒤 고르기"의 금지다.
  미접촉 신규 데이터의 전수(선별 없는) 재검증은 새로운 실험이며, 사람의
  선택이 개입하지 않는다(레지스트리 전원 자동 — 체리피킹 불가).
- 산출물: `.omo/evidence/tmap-walkforward/rejected_registry.json`(등재:
  EXIT2C take9, EXIT2NA take6) + `gen_revival_pairs.py`(pairs 생성기).
  실행: 신규 창 config로 `claude_candidate_batch_eval --pairs-json
  pairs-revival.json --config-json <새 창 config>`.

### S5. 신규 2026 데이터 도착 시 OOS 확장 (사용자 데이터 계획과 결합)
- 수집 → back DB 병합 → `oos-2026ext-config.json`(20260301~) 사전선언 →
  챔피언 V3′ + S4 부활 배치 동시 실행. 1-커맨드 준비 완료 상태 유지.

### 무엇을 하지 않는가
- 기존 기각의 번복(같은 데이터 재선택) · p0 §5 완화 · 엔진/하드게이트 수정.

## 3. 갭 1~5 상세 개발 연구

### 갭1 — 시간 확장 (시간대 고유 메커니즘)
- **진단**: 시드 구조의 시간 이식(min 2종)은 전부 실패. 시간대마다 미시구조가
  다르다 — 09:00~05(개장 모멘텀/흡수), 09:05~20(횡보 후 발화), 09:02~15
  (되돌림 재진입).
- **개발**: 템플릿 신설만으로 가능(엔진 무수정). F04(흡수·**진행 중** —
  window_end 09:15 확장 축 포함, 28좌표) → F18+F03(재진입 — `build_f18
  _template.py`, 되돌림 깊이·회복 속도·재진입 확인 축 ~10θ) → F19(이평 지지).
- **측정**: TMAP 스윕 → `/niche_compare`(시간버킷·동결상관) → 생존 시 P-A.
- **완료 기준**: 시간버킷 비중첩 + 동결상관 <0.5 생존 니치 1개 이상.

### 갭2 — 단일 시드 의존 (생성 다양화, P-F GPT 합류)
- **진단**: M5 실증 — 시드 DB 안에 제2의 산 없음. 새 구조의 공급원이 필요.
- **개발 설계** (`scripts/gen_template_hypothesis.py` 신규):
  1. 입력: v5.0 원리 문서 + 기존 템플릿 응답곡선 요약(실패 포함)
  2. P5 프롬프트(`brain/prompts/p5_template_hypothesis.md` — 자산 존재·미배선)
     → provider(gpt_auth) 호출 → 템플릿 JSON 초안(θ 축 포함)
  3. **가드 깔때기**: compile/token/scope/시간무결성 전 좌표 검증(LLM 신규
     함수 발명·역스캔 자동 차단 — F17 차단과 같은 메커니즘) → 실패 시 오류
     피드백 1회 재생성 → 통과만 스모크(2025Q1) → 스윕 후보 등록
  4. 토글 기본 OFF · 생성물은 `llmgen_` 접두사로 격리 · n_trials에 자동 합산
- **리스크 통제**: 코드 인젝션은 scope 가드가 차단, 다중성 폭증은 예산 가드
  (C5 계산예산)와 n_trials 정직 합산이 흡수.

### 갭3 — 레짐 인식 (P6 재개)
- **진단**: exit2가 2022 강세·2026 사망 — 구조의 생사가 레짐을 탄다.
- **개발 설계** (`fitness/regime_advisory.py` 신규, advisory 전용):
  1. 입력: 기존 per-trade CSV + moneytop 집계(일별 시장 거래대금·상승종목
     비율·등락 분산 — back DB에서 산출 가능, 신규 데이터 불필요)
  2. 산출: 월별 레짐 라벨(활성/위축 2단계부터 시작 — 과도한 세분화 금지),
     후보별 레짐 분해 성과표
  3. 표시: verdict 페이지에 "레짐 분해" 1행(2022형 레짐에서만 버는 후보 경고)
- **판정 불변**: 레짐 게이트는 검증 전엔 도입하지 않는다(advisory만).

### 갭4 — 유니버스 설계 (N3)
- **정직한 제약**: back DB의 유니버스는 수집 당시 moneytop 기록 그 자체 —
  과거로 소급한 유니버스 재설계는 **불가능**(원시 전 종목 데이터 부재).
- **가능한 것**: ① moneytop 내 필터 변형(시총·가격대·등락 구간)은 템플릿
  축으로 이미 수행 중 ② **전향 설계**: 사용자 2026 데이터 수집 계획에
  유니버스 폭 확대(기록 종목 수·시간 범위)를 포함시키는 설계 문서.
- **개발**: 수집 스펙 문서 1건(코드 변경 없음) — Phase D.

### 갭5 — 포트폴리오 레이어
- **진단**: 단일 전략 운용. M5의 저MDD 2종(payoff 2.08 포함) 상관 측정 메모.
- **개발 설계** (`fitness/portfolio.py` 신규, 순수 함수):
  1. 입력: 후보별 per-trade CSV → 일별 PnL 행렬(`align_daily_matrix` 재사용)
  2. 산출: 상관 행렬·균등/역변동성 결합 곡선·결합 MDD·한계 기여도
  3. 표시: `/niche_compare`에 "결합 시뮬" 패널
- **전제**: 독립 생존 니치 ≥1 (P-A `absolute_niche_v1` 스펙은 대장 §3에 동결).
- **주의**: 결합 가중 최적화는 새로운 과적합 문 — v0는 균등 가중 고정.

|---|---|---|---|

| **B** | F18+F03 재진입 템플릿+스윕 | 빌드 30분+스윕 ~1h | 가드 전 좌표 통과·지도 |
