## 2. 운영 중 발견·수정한 결함 (이 실증의 부수 성과)

1. **엔진 0거래 무산출 종료**(`backtest.py` Report 조기 SysExit)가 모호한 에러로 보고되던 것
   → 잡 매니저에 `no_trades` 정상 상태로 표준화 (PR2-1, `06874c64`)
2. **무출력 CLI(`--quiet`)에서 잡 타임아웃 미발동** — 데드라인 검사가 stdout 읽기 루프
   내부에만 존재 → stdout 독립 워치독 타이머 추가 (`d23f513a`)
3. **취소 시 자식 트리 미회수 → 동시 1실행 슬롯 영구 점유**(후속 잡 pending 갇힘)
   → psutil 프로세스 트리 킬로 교체 + 회귀 테스트 2건 (`d23f513a`)

## 3. v5 전략 연산 비용 분석과 권고

- 원인: 공통 파생변수 블록(이동평균·누적초당수량·횡보감지 등 고비용 롤링 호출 다수)이
  **시간 게이트(`90500 <= 시분초 < 92000`) 판정보다 앞에** 위치해 장 전체(~6시간) 모든
  tick에서 실행된다. 매수 가능 창은 09:05~09:20(15분)뿐인데 연산은 하루 종일 수행.
- 대조: 단순 전략은 동일 범위(1종목 1일 tick)를 43.5초에 완료 → 비용 차이는 전략 코드 기인.
- 멀티코드 모드(`종목코드별 분류`)에서는 같은 전략으로 엔진 데이터 응답 단계 교착도 관찰
  (5일×subset, engines 1·2 모두) — 전략 무관 코드 경로 차이인지 후속 조사 필요.

**권고 (적용방안 문서의 단계 ③ 보강):**
1. *즉효 경량화(OPTI v1)*: 파생변수 블록 전체를 시간 게이트 안쪽으로 이동 — 의미 변화 없이
   연산량 약 96% 절감 기대(6.5h→15min 창). 워크벤치 에디터에서 수정·재검증 가능.
2. 1차 동작 확인은 `timeout 1800` + 1종목 1일로 수행 후 점진 확장.
3. min 타임프레임 검증은 초당* 변수의 min 네임스페이스 대응(분당*) 확인 후 진행.
