## ① 쉬운 요약 (공장 라인 비유)

이 백테스트 엔진은 **원자재 창고 → 조립 라인 → 검수대 → 출하 기록**으로 이루어진 공장이다.

- **창고(로딩)**: 창고에 물건은 다 있는데 **선반 라벨(인덱스)이 하나도 없다**. 부품 하나 꺼낼 때마다 창고 전체를 훑는다(2,427개 테이블 전부 인덱스 0, EXPLAIN=SCAN). 그래도 창고가 아주 크진 않아서 지금까지는 버텼다.
- **조립 라인(틱 루프)**: 라인 자체는 빠르게 돌게 설계됐다(전략 1회 compile 후 exec 반복). 그런데 **작업대 하나에서 부품 상자를 여러 라인이 같이 쓰는 실수**(trade_info dict 앨리어싱)가 있어, 최적화 모드에서 서로의 재고를 오염시킬 수 있다.
- **라인 고장 경보(오류 처리)**: 라인이 멈춰도 **사이렌이 안 울린다**(BackStop(3)가 집계 큐에 아무것도 안 보냄). 관리자는 최대 1시간(3600s 타임아웃) 동안 완제품이 나오길 기다리다가 "시간 초과"라는 원인 없는 쪽지만 받는다.
- **교대 근무(웜 세션)**: 최근에 만든 웜풀은 훌륭하다 — 라인을 끄지 않고 설계도만 바꿔 끼운다(~273s → ~30-60s). 문제는 **optimize/sweep/wfo 같은 대량 주문이 아직 옛날 방식(매번 공장 재가동)을 쓴다**는 것.
- **검수대(체결 모델)**: 시장가가 호가를 실제로 걸어 내려가는 건 업계 평균 이상. 다만 부분체결이 없고, 내 주문이 시장에 남긴 자국(자기 충격)을 지우고 다시 계산한다 — 실전보다 낙관적이다.

**한 줄 결론**: 연구용으로 이미 실전 검증된 공장이지만, "라벨 없는 창고 + 안 울리는 사이렌 + 옛날 방식 대량 주문" 세 가지가 시간의 대부분을 낭비시키고 있으며, 셋 다 비교적 싸게 고칠 수 있다.

## ⑥ "더 많은 조건식 동시 백테스팅" 확장 가능성 판별

### 현행 구조로 이미 가능한 것 (설정·배치 수준, 코드 변경 불필요)
- **1 prepare + N run 직렬 배치**: 웜세션이 엔진·데이터를 살린 채 (buy,sell) 쌍만 교체(`warm_session.py:425-480`). `ai_strategy_loop/scripts/claude_candidate_batch_eval.py:3` 패턴이 이미 24페어를 로딩 1회 상각으로 처리(4y tick: 로딩 332s 1회 + ~103s/pair). GA·루프·격자배치는 이 경로가 표준(`controller/loop.py:1298`, `ga.py:266`).
- **vars 변형 동시 채점**: opti_kind 1/3은 한 틱 패스에서 변수조합 다중 채점 구조가 이미 존재(`backengine_base.py:591-597`, GA 50×20). 단 이는 "한 전략의 파라미터 변형"이지 임의의 N개 조건식 쌍이 아니며, **S9 앨리어싱 수정 전에는 이 경로 결과를 신뢰 불가**.

### 변경이 필요한 것
- **임의 N쌍 단일 로딩 동시 채점(멀티 전략 1-pass)**: run()이 (buy,sell) 1쌍 시그니처(`warm_session.py:425`)이고 채점 BackTest가 1개 직렬(`runner.py:597-608`, `ga.py:306-307` "직렬…병렬 불가" 명시). 구현하려면 (a) Strategy exec를 쌍 리스트 순회로 확장하고 trade_info를 쌍별 완전 분리(S9 선행 필수), (b) BackTest 집계를 쌍 차원으로 확장 — **난이도 상, 검증 부담 큼**. 대안: 현행 1 prepare + N run의 run 구간(~103s/pair)만 최적화하는 편이 비용 대비 효과 우수(추정).
- **콜드 경로 서브커맨드(optimize/sweep/wfo)의 웜 전환**: ⑤ S3. run_fn 주입점이 이미 있으므로 "변경 필요"이나 구조 신설은 아님.
- **배치 CLI 승격**: claude_candidate_batch_eval.py 패턴을 정식 cli 서브커맨드로 — 변경 소.

**판별 결론**: "동시에 더 많이"는 지금도 **웜세션 직렬 배치로 실용 수준 달성 가능**(로딩 상각이 지배 비용이므로). 진짜 1-pass 멀티 전략 채점은 앨리어싱 수정 + BackTest 확장이 선행되는 중대 개조이며, 현 시점 ROI는 S3(웜 전환)보다 낮다고 판단(추정).

## ⑦ 백테-실전 괴리 주의점 (감사 §10.2 상속)

1. **자기 충격 미반영**: 체결 후 호가 잔량 미차감 — 같은/다음 틱에 유동성 원상복구. LastSell은 잔량 부족 시 전량을 1호가 단일가 청산(`backengine_base.py:894-896`) — 낙관적.
2. **부분체결 없음**: 잔량 부족 시 주문 통째 소멸(`backengine_base.py:803` 전량 소진 시에만 상태 갱신) — 유동성 얇은 종목에서 거래 자체가 스킵되어 표본 편향.
3. **지정가 대기열 미모델**: 가격 뚫리면 잔여 물량 무관 전량 체결(`backengine_base_oms.py:230-237`); min2는 분봉저가 기준이라 봉내 순서 가정 낙관적(`oms.py:227-229`).
4. **레이턴시 0**: 신호 틱 스냅샷 즉시 체결 — 주문 왕복 지연 중 호가 변동 미반영.
5. **비용 상수 구식 가능**: 세금 0.18%+수수료 0.015%(10원 절사) 고정(`utility/static.py:753-760`) — 2025~26 인하 세율과 불일치 추정(외부 확인 필요). 수정 시 전 백테 결과 재산정 유발 — 봉인 게이트 필수.
6. **VWAP 원단위 반올림 후 손익 재계산**(`kiwoom_tick.py:161-165`, `base.py:912`) — 저가주에서 상대오차 확대.
7. 운영 대응: 실전 로그 대비 지정가 체결률·평균 슬리피지 대조 리포트는 **분석 스크립트만으로 가능**(엔진 무변경).

기존 감사와 일치 확인: 자기 충격(§10.2)은 본 검수에서도 동일 결론. 보수적 요소(시장가 호가 소진, strict-뚫림 지정가)와 낙관적 요소(1~4)가 혼재하므로 순편향 방향은 종목 유동성에 의존(추정).
