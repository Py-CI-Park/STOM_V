# Backtest Button Contract Fix Design

## 목적

정식 버전 업데이트 반영 후 `wt-dev`에서 백테스트 엔진은 구동되지만, 백테스트 버튼 클릭 시 `BackTest.__init__()` 인자 계약 불일치로 프로세스가 즉시 종료되는 문제를 해결한다. 해결 방향이 확정되면 같은 문제가 `STOM_Version_2U`, `STOM_Version_2U_C`, `research/init`에도 존재하는지 점검하고, 실제로 동일한 계약 불일치가 있는 워크트리만 함께 수정한다.

## 배경

현재 관찰된 핵심 오류는 다음 한 줄이다.

```text
TypeError: BackTest.__init__() takes 13 positional arguments but 25 were given
```

이 오류는 백테스트 버튼 클릭 시 `Process(target=BackTest, args=...)` 호출 경로에서 발생했다. 즉, 백테스트 엔진 자체가 뜨는지 여부와 별개로, 버튼을 눌렀을 때 새로 생성되는 백테스트 프로세스의 인자 계약이 깨져 있다는 뜻이다.

로그에는 텔레그램 polling 예외와 웹크롤링 네트워크 예외도 함께 섞여 있지만, 이들은 백테스트 버튼 클릭 즉시 발생한 `BackTest.__init__` 계약 오류와는 별개의 병렬 노이즈로 본다.

## 문제 정의

현재 `wt-dev`는 다음과 같은 불일치 상태일 가능성이 높다.

1. 버튼 클릭 코드가 예전 계약 기준으로 `BackTest`에 긴 인자 목록을 직접 넘긴다.
2. `backtest/backtest.py` 의 `BackTest.__init__` 는 이미 더 짧은 계약으로 정리되어 있다.
3. 두 코드가 동시에 갱신되지 않아 버튼 클릭 시 프로세스 시작 직후 `TypeError`가 난다.

핵심은 "정식 버전과 다르게 호출자와 대상 클래스의 계약이 어긋나 있다"는 점이다.

## 목표

1. `wt-dev`에서 백테스트 버튼 클릭 경로와 `BackTest.__init__` 계약을 일치시킨다.
2. `TypeError: BackTest.__init__()` 인자 수 오류를 제거한다.
3. 같은 계약 불일치가 있는 다른 워크트리에도 동일한 수정 방향을 적용한다.
4. 이번 종류의 계약 불일치를 다시 잡을 수 있는 검증 포인트를 남긴다.

## 비목표

1. 텔레그램 polling 네트워크 오류 수정
2. 홈탭/웹크롤링 네트워크 오류 수정
3. 백테스트 엔진 전체 아키텍처 재설계
4. GUI 전체 E2E 자동화 구축

## 접근 방식 비교

### 1. 호출자 정리 우선

버튼 클릭 코드에서 `BackTest`에 넘기는 인자를 현재 `BackTest.__init__` 계약에 맞게 줄인다.

- 장점: 현재 구조를 가장 적게 건드린다.
- 장점: `BackTest` 내부가 이미 큐 기반 설정 로딩 구조라면 가장 자연스럽다.
- 단점: 버튼 클릭 경로가 여러 파일에 퍼져 있으면 모두 찾아 정리해야 한다.

### 2. `BackTest.__init__` 를 과거 긴 시그니처로 복구

버튼 클릭 코드의 긴 인자 리스트를 다시 받도록 `BackTest.__init__` 를 넓힌다.

- 장점: 호출자 쪽 수정이 줄 수 있다.
- 단점: 현재 큐 기반 구조와 중복될 가능성이 높다.
- 단점: 정식 버전 동기화 이후 다시 같은 문제가 생길 가능성이 크다.

### 3. 버튼 경로와 백테스트 오케스트레이터 전면 재설계

UI -> Process -> Queue -> BackTest/Total 계약 전체를 다시 정리한다.

- 장점: 구조적으로 가장 깔끔하다.
- 단점: 이번 문제를 해결하기엔 범위가 너무 넓다.

## 추천 접근

추천은 **1. 호출자 정리 우선**이다.

이유는 다음과 같다.

- 현재 `wt-dev`의 `BackTest` 는 내부에서 큐를 통해 실제 설정을 읽는 구조다.
- 그렇다면 UI가 20개가 넘는 값을 직접 생성자 인자로 넘기는 것은 현재 설계와 중복되거나 오래된 호출 방식일 가능성이 높다.
- 정식 버전과 가장 같은 원칙은 "호출자와 대상 클래스의 계약이 일치한다"는 것이지, "항상 긴 인자를 직접 넘긴다"는 것이 아니다.
- 따라서 `wt-dev`에서는 현재 `BackTest` 구조를 기준으로 버튼 클릭 호출자를 맞추는 것이 가장 안전하다.

## 전파 기준

다른 워크트리에 함께 반영하는 기준은 아래 두 조건을 동시에 만족하는 경우다.

1. 버튼 클릭 코드가 `Process(target=BackTest, args=...)` 로 긴 인자 목록을 직접 넘긴다.
2. 해당 워크트리의 `BackTest.__init__` 는 이미 더 짧은 계약을 사용한다.

두 조건이 동시에 맞으면 같은 문제로 보고 함께 수정한다. 둘 중 하나라도 다르면 반영 불필요 또는 추가 조사 필요로 기록만 남긴다.

## 성공 기준

1. 백테스트 버튼 클릭 경로에서 `BackTest.__init__()` 인자 수 오류가 재발하지 않는다.
2. `wt-dev`에서 버튼 클릭 경로의 계약이 현재 `BackTest` 시그니처와 일치한다.
3. 동일 문제가 있는 다른 워크트리도 같은 방식으로 정리된다.
4. 관련 정적/스모크 테스트가 추가되어 다시 같은 계약 불일치를 잡을 수 있다.

## 검증 전략

### 1. 정적 계약 검증

- 버튼 클릭 파일의 `Process(target=BackTest, args=...)` 호출 형식
- `backtest/backtest.py` 의 `BackTest.__init__` 시그니처
- 두 계약이 맞는지 테스트로 고정

### 2. 경로 로딩 검증

- 관련 모듈 import
- 버튼 클릭 핸들러 import
- `BackTest` 대상 로딩 확인

### 3. 백테스트 시작 smoke

- 전체 GUI E2E 자동화가 아니라, 버튼 클릭 직후 프로세스 생성 인자 오류가 사라졌는지 확인하는 최소 smoke 수준

## 제외 로그 처리 방침

이번 설계에서는 다음 로그를 직접 수정 대상으로 보지 않는다.

- 텔레그램 `httpx.ConnectError`
- `get_korean_stocks`, `get_market_indicator`, `get_crypto_data` 네트워크 예외

이들은 별도 이슈로 분리하고, 본 작업에서는 백테스트 버튼 불능의 1차 원인인 `BackTest` 계약 불일치에만 집중한다.
