## 3. "너무 타이트한가?" — 게이트별 정직 판정

- **filter_gate(범주 5+)**: 인간 매수 10.1%가 2~4범주로 미달. 즉 인간 실전 기준으로는 다소 타이트.
  단 이 게이트는 §3.22 과발화 실측(느슨한 생성이 타임아웃/손실 유발)에서 나온 **연구 lane 전용
  reject**이고 기본 OFF다. 완화 비권장 — 대신 "인간 전략 10%는 4범주 이하로도 성립한다"를
  생성 프롬프트가 아닌 **평가 근거**로만 기억한다.
- **exec_budget(윈도우 호출 ≤8)**: 인간 매도의 42.6%(20/47)가 9~11개 호출. 인간 패턴 대비
  명백히 타이트. 그러나 상한 8은 2026-06-10 루프 warm 타임아웃 11/11 분리 실측에서 나온
  값이므로 유지한다. 실무 함의: **인간 매도식을 루프 시드로 재사용할 때 42.6%가 이 가드에
  걸린다** — few-shot(참고용)은 무관하나 seed-refine 출발점으로 쓸 땐 사전 간소화 필요.
- **principle_gate CSC-10**(tick 시간창, 26건): 인간 tick 매도 대부분이 `시분초>=93000` 강제청산
  분기가 없다 — 운영 GUI는 장중 전체 데이터와 운영 규칙이 있어 불필요했기 때문. 연구 lane은
  tick 데이터가 09:30에 끝나 미청산 포지션이 세대를 오염시키므로 **의도적 요구**가 맞다.
  오탐 아님(문맥 차이). CSC-07 손절 부재 2건은 정탐(실제 손절 없는 study 매도).

**종합**: "기계 검사가 잘못 거부하는가?" → **예, 2종(58건)이 실제 오탐이었고 교정했다.**
"매수/매도식 요구가 과도하게 타이트한가?" → 스코프/토큰 검사는 교정 후 적정. filter/budget/CSC는
인간 운영 대비 타이트함이 수치로 확인되나(10.1%/42.6%/CSC-10 26건) 각각 과발화 방지·타임아웃
방지·데이터 경계라는 연구 lane 실측 근거가 있어 **의도적 타이트로 유지**하고, 그 비용(인간 시드
재사용 시 마찰)을 본 보고서로 문서화한다.
