## 0. 핵심 결론 (먼저)

**지금 시스템은 "시초 09:00~09:28 초단타 tick 스캘퍼"라는 좁은 한 점에 구조적으로 묶여 있다.** 비전이 요구하는 넓은 시간지평(tick 최대시간·min 15시)을 코드 수준에서 막는 단 하나의 하드 클립이 **`bt_universe_end_time = 92800`(09:28, `controller/loop.py:385-386`)** 이다. 인간 라이브러리(`_database/strategy.db`: tick 09:00~09:30 + min ~15:15, 매수 88개)는 이미 훨씬 넓은 지평을 쓰는데, **루프는 그 넓이를 전혀 활용하지 못한다.**

성과는 실재한다 — 적응형 레짐타이밍이 다년 진짜 OOS에서 위험조정 3.5배 검증, 밴드 P0 컴파일러가 23테스트로 결정론·시드 round-trip 통과, edge_ratio/feature_importance 분석 백엔드와 도메인주입 생성(백지붕괴 구제)이 작동. **그러나 핵심 가치들이 전부 "측정은 됐지만 루프에 환류되지 않는 개루프(open loop)" 상태다**: adaptive_timing은 hot path에서 0회 호출, 밴드 P0는 어떤 controller도 import하지 않으며, 분석 3종은 프론트엔드 렌더러가 0개.

**AI가 인간 시드를 절대수익으로 못 이기는 진짜 원인은 "튜닝 부재"가 아니라 (a)시간지평 국한 + (b)레짐/윈도우 과적합** 두 가지가 겹친 것이며, (a)는 우리가 고칠 수 있는 시스템 한계, (b)는 인간·AI 공통 시장구조 난제다. **시간창을 풀세션으로 열면 (a)는 직접 제거 가능**하고, 그때 비로소 절대수익 head-to-head가 공정해진다.

방향: ① 시간창을 일급 축으로 만들어 넓게 열고, ② 백테 결과를 시각화/퀀트로 좁히는 폐루프를 닫고, ③ 밴드 P0를 생성 경로에 배선하며, ④ BackFinder forward-라벨을 자동 정제 엔진으로 차용 — 전부 기존 불변식 안에서 가능. 단, **시간지평 확장은 3년 풀유니버스 ~5세대 OOM 천장과 정면충돌**하므로 거래수 캡 + 짧은창 탐색→OOS 분리검증이 선결 인프라.

## 1. ① 전체 종합 — 지금까지 무엇을 만들고 무엇을 알아냈나 (도메인 망라)

### A. 조건식 생성 (LLM strategy generation)
- **프롬프트 조립 + PRE-SAVE 게이트 사슬**: `prompt.py:build_messages()`가 정규형 골격 + timeframe 변수강제 + 보고서 패턴 + (토글)필터게이팅을 user 메시지에 누적. `generator.py:generate_strategy()`가 compile→token denylist→**변수 스코프 가드**(timeframe 인지 AST 검사, 백테 이전 NameError 데드락 결정론 차단, `variable_scope.py:213-256`)→(옵션)거래대금 유동성 게이트→(옵션)필터범주 수 게이트→dedup→save 사슬을 강제. 실패 사유를 `prior_error`로 재프롬프트.
- **도메인주입 3종**: filter_gate(9범주 구조게이트, min 5~7) + few-shot(인간 study exemplar) + 시간×시총×등락률 분류축 프롬프트. 이 주입이 §3.17 "백지붕괴(fresh: winner −1·MDD 2851%·완전비수렴)"를 구제해 **fresh 생성을 viable하게 만든 것이 실증됨** (커밋 `eacd44da`).
- **밴드 파라미터화 P0** (`band_compiler.py` 434줄, `seed_902_band.py` 145줄): BandSpec(var,op,[lo,hi],active) + FixedFragment + op enum 6종 + 결정론 컴파일. 시드 Tick_B_902_905를 밴드로 round-trip 인코딩. **23개 단위테스트 전부 통과**, byte-결정론·게이트통과·논리동일 검증. 단 **생성 루프에 미배선**(grep: band_compiler/BandStrategy 참조 = 본인 2파일 + 테스트뿐).

### B. 적합도/채점 (fitness)
- **2층 구조**: 하드게이트 `compute_fitness`(`score.py:251`, `composite = calmar × uptrend_r2 × gate`, gate = 빈도 AND mdd≤cap AND profit>0 [AND tpi]의 0/1) = 졸업/우승 PASS/FAIL 무수정 불변식. 위에 `compute_graded_fitness`(0..∞ 선택 그래디언트, 통과>실패 불변: graded≥1.0 vs <1.0)가 토글로 얹힘.
- **winner_objective 6종**: risk_adjusted/profit/balanced/multi/uptrend/multiyear. profit_term은 부호보존 log1p로 광대역 적자에서도 단조 변별.
- **exit_quality 환류**: per-trade CSV의 payoff_ratio·give_back_rate를 게이트-실패 graded에 가산 + 매도 프롬프트 환류.
- **분석 전용 모듈 3종**(엔진/게이트/생성 무영향 계약): `edge_ratio.py`(MFE/MAE 엣지비율), `feature_importance.py`(B_* 진입변수 Cohen's d), `adaptive_timing.py`(인과적 레짐 FLAT 오버레이).

## 3. AI가 인간 시드를 못 이기는 진짜 원인 — 정직 진단

**한 줄: "튜닝 부재"가 아니라 (a)시간지평 국한 + (b)레짐/윈도우 과적합이 겹친 것이며, 둘은 성격이 다르다 — (a)는 고칠 수 있는 시스템 한계, (b)는 인간·AI 공통 시장구조 난제.**

1. **시간지평 국한 (시스템 한계 — 가장 직접적):** 절대수익 head-to-head(E8) 시드 +1,944,536 vs 최고 AI +257,237 = 시드 ~7.5배. 시드 우위 상당부분은 "더 넓은 시간지평에서 더 많은 기회를 잡는다". 인간 시드는 tick 09:30 + min 15:15까지 거래하는데 AI 루프는 09:28에 잘린다. **AI는 09:28~15:15 거래 기회 자체를 볼 수 없다.** 같은 알파 밀도라도 28분 vs 6시간이면 절대수익은 구조적으로 못 따라간다. "튜닝"보다 먼저인 1차 원인.
2. **레짐/윈도우 과적합 (시장구조 난제 — AI·인간 공통):** AI 발견 전략은 발견 윈도우 특이적(E15 교차연도 2024 Q1 −1.0M, E13 교차월 6월 −293k, E16 0/6). **그러나 AI만의 결함이 아니다** — E14 약세 5~7월 통합에서 인간 시드도 −2.18M로 동일 실패. 교차레짐 강건성은 단일 전략으론 인간도 못 푸는 문제. 시드가 이기는 이유는 "더 강건한 단일전략"이 아니라 "수년 인간 튜닝으로 찾은 다년 검증 니치(2024 +1.55M·2025 +1.94M)" — 운 아닌 실제 다년 엣지.
3. **게이트통과 ≠ 수익 (R7.4 인식론적 한계):** 정적 코드로 좋은 전략을 판별하는 품질판정기는 불가능(filter_gate.py 자인). 구조게이트는 범주 *폭*만 보고 *선별성*은 못 봐서 다중토큰 항상참 조합이 게이트를 통과.
4. **표현력/튜닝은 부차적:** 밴드 P0 미배선이라 결정론 튜닝(Optuna) 미사용은 맞지만, 자유형 LLM hill-climb도 과발화를 자율 교정한 실증 있음(E3 gen1 1073거래 → gen7 28거래). "튜닝 부재"는 보조 원인.

**종합 판정**: 1차로 시간지평이 09:28에 잘려 기회 모수가 작기 때문, 2차로 교차레짐 강건성이 시장구조상 미해결. AI의 현재 가치는 "대체"가 아니라 "보완"(시드 약세월 메우기, 앙상블 +79%·MDD −58%)이고, 가장 배포가능한 진짜 알파는 비전 외곽의 적응형 레짐타이밍. **시간지평을 풀세션으로 열면 1차 원인은 직접 제거 가능.**

## 4. 비전 대비 핵심 격차

1. **[시간지평]** 루프가 `bt_universe_end_time=92800`(09:28) 하드 클립 → 인간 풀세션(tick 09:30·min 15:15) 전혀 활용 못함. 비전 '핵심' 항목이 코드 수준에서 막힘.
2. **[넓은 생성]** classification 등 토글은 존재하나 전부 기본 OFF + reject 게이트 아닌 프롬프트 넛지라 실제로 넓게 생성됐는지 강제·측정 불가.
3. **[퀀트 정제 폐루프]** edge_ratio/feature_importance/adaptive_timing이 측정만 하고 채점·생성·프론트로 환류 안 되는 개루프 — '분석→불필요조건 제거→재생성' 자율 루프 미완성.
4. **[시각화]** 분포 히스토그램·시간대×시총 히트맵·변수중요도 막대·군집 4종이 프론트엔드 0개(백엔드는 있으나 렌더러 미연결).
5. **[밴드 그릇]** 밴드 P0가 어떤 controller도 import 안 해 '넓은 밴드 생성→is_off 결정론 정제' 미가동. 또 시각창이 BandSpec 연속축이 아니라 TimeBranch 구조라 '시간축을 넓히고 좁히는' 비전 어휘에 안 들어옴.
6. **[BackFinder 차용]** forward-라벨러가 positive-only(안 오른 같은피처 틱 미수집)라 precision 자동 게이팅 불가 — negative 샘플 + 실제 PnL 결합 필요.
7. **[인간초월 측정]** Sharpe/CVaR/PBO/Deflated Sharpe/거래비용 모델 전무 — '인간 수준/초월'을 판정할 척도 자체가 없음.
8. **[OOM 인프라]** 3년 풀유니버스 ~5세대 OOM 천장 + 고아 엔진 자동정리 부재 → 시간지평·풀세션 확장(거래수 폭증)의 직접 물리 제약.

## 6. 위험·반론 (정직)

1. **[OOM 정면충돌]** 시간지평 풀세션 확장(S0)은 거래수 선형이상 증가 → ~5세대 천장이 더 빨리 무너짐. 거래수 캡 없이는 S0 자체가 OOM 실패 가능. 캡은 엔진 보호영역 수정 필요할 수 있어 불변식과 긴장.
2. **[게이트≠수익 불변(R7.4)]** 어떤 정적 게이트·구조검사·밴드 좁히기도 '수익 보장' 못 줌. S1~S3는 '더 잘 측정·압박'할 뿐 레짐불변성 자체를 못 줌(시장구조적).
3. **[과적합 재생산]** band_optimizer(Optuna)가 1개월 graded 최대화 = 구간 곡선맞춤 위험. holdout/다년(S5) 없이 S3만 하면 과적합을 더 효율적으로 생산.
4. **[보완의 함정]** AI가 '대체' 아닌 '보완'에서만 가치(앙상블 +79%)인데, 이는 2025 시드 약세패치를 AI가 메웠기 때문 — 약세구간은 매년 달라 고정 전이 불가. 적응형 전제 깨지면 결합가치 소멸.
5. **[밴드 표현력 천장]** axis-aligned box는 변수 상호작용·함수형·파생위치를 못 담아 시드 조건 소수만 튜닝 표면(시드902 인코딩 시 box 12개 vs FixedFragment ~20개). 밴드 최적화 천장이 변수템플릿 완전성에 묶임.
6. **[positive-only 라벨]** BackFinder 차용(S4)은 negative/실제 PnL 결합 없이는 precision 못 줘 '오를 것 같은 피처'와 '실제 오른 피처'를 구분 못함. forward 라벨이 '고가 도달'이라 실제 체결가/슬리피지와 괴리.
7. **[16 vs 32 엔진 불일치]** 사용자 인식(16엔진)과 코드 기본값(32엔진, `config.py:132`)이 달라 메모리 예산 계산이 틀어질 수 있음.

## 7. 결정점 (사용자 확인 필요)

1. **[자유형 vs 밴드 우선순위]** S1(자유형 LLM 넓은생성 기본화)과 S3(밴드 배선)를 동시 추진? 아니면 밴드를 메인 생성기로 승격하고 자유형을 exemplar 소스로 강등? (표현력·결정론 트레이드오프 정반대)
2. **[1초봉 '최대시간' 정의]** tick=활용가능 최대시간이 정확히 어디까지? 09:30? 11:30(오전장)? 15:00? 15:30(동시호가)? (데이터 가용성·OOM 예산 직결. min은 15:00 명시됨)
3. **[거래수 캡 허용 여부]** OOM 우회를 위한 엔진측 거래수 캡은 '엔진 무수정' 불변식과 충돌 가능 — 별도 보호영역 수정 허용? 아니면 전적으로 생성측(PRE-SAVE reject)으로만?
4. **[시간지평 검증 전략]** 3년 단일 run(OOM 위험) 감수? 아니면 1개월 탐색→2022/2026 OOS 분리검증 분할?
5. **[퀀트지표 도입 범위]** Sharpe/CVaR/PBO 중 무엇 먼저? 전부 graded 가산(하드게이트 불변)? 일부를 졸업 하드게이트로 승격(불변식 변경 필요)?
6. **[배포 목표]** 최종 목표가 '시드를 대체하는 단일 AI 전략'? 아니면 '시드+AI 적응형 앙상블'? (전자는 교차레짐 난제, 후자는 검증된 3.5배 경로지만 시드 의존 잔존)
7. **[분석→생성 환류 강도]** stable_cells avoid를 프롬프트 넛지로만(약함)? reject 게이트로 강제(강함, 과적합 위험)?
