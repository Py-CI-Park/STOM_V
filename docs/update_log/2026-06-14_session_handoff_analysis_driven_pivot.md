## 1. 현재 위치 (한눈에)

사장님이 **연구 프로세스 자체의 한계**를 지적: "데이터로 못 찾는 게 아니라 프로세스 한계.
인간 사례는 고빈도 우상향 백테가 나온다. **시간대를 처음부터 고려한 시드를 (여러 개) 생성 →
첫 백테부터 분석 → 통계/히트맵(수익=색, 변수=축) → 개선 → 반복(루프)**"하라.

**나의 정직한 자기점검**: 사장님 제안 6요소 중 **분석·히트맵(4·5·6)만 했고, 시드 생성 +
시간대 설계 + 개선 루프(1·2·3)는 안 했다.** 즉 "기존 시드 1개를 1회 분석"했을 뿐,
사장님이 그린 *전체 시스템*을 안 지었다. → **다음 할 일 = 그 전체 시스템 구축.**

## 2. 사장님 제안 = 지을 시스템 (analysis_loop)

```
[A 시드 생성] 시간대별 여러 시드 (개장/오전/점심/오후 + 스타일) — 시간대를 처음부터 고려
[B 백테스트]  각 시드 → 거래별 데이터(CSV: 전 피처+MFE/MAE)
[C 분석]      거래 통계 + 수익 히트맵(변수×변수→수익) → 승자 구역 식별
[D 개선]      분석 기반 조건 정제 → ★재백테(진실 게이트) ← 어제 교훈 필수
[E 반복]      C-D를 수익 개선 멈출 때까지 LOOP
[F 검증]      살아남은 시드 → 홀드아웃/OOS
```
- 격리 위치 제안: `ai_strategy_loop/analysis_loop/`. 엔진 무접촉(분석은 백테 CSV에).
- 첫 시연 제안: 미탐사 시간대(오후 13:00~15:00 등) 새 시드 → 전체 사이클 끝까지.

## 3. 핵심 사실·교훈 (반드시 기억)

1. **★엔진은 .py다 (.pyd 0개)** — `backtest/backengine_base.py` 등 읽고 고칠 수 있는 소스.
   "엔진 무수정"은 *물리적 벽이 아니라 규율*(사장님이 풀면 수정 가능). 내가 "보호된 .pyd"라
   한 건 틀렸음.
2. **★엔진 개수 32 최적** — 단일 평가는 32(prepare 73s) < 64(prepare 104s, HT 초과로 느림).
   64는 대형 스윕(>16점)만 유리. 물리32코어/논리64.
3. **★사후 슬라이스 ≠ 추출 가능 엣지** — 백테 CSV를 사후에 필터로 쪼개 흑자 포켓을 찾아도,
   그 필터를 *진입규칙*으로 넣으면 거래셋이 바뀌어(선택편향) 재현 안 됨. min 중형주 포켓
   CSV +1.07M → 조각(MIN_MIDCAP_REFINED) 재백테 -1.15M. **D 개선 단계엔 재백테 게이트 필수.**
4. **랭킹(A)은 종목별 조건식이 아님** — STOM 실매매는 종목별 if-Buy. 랭킹(상위K)은 종목 비교라
   조건식으로 표현 불가 → 실매매 넣으려면 라이브 엔진도 개조 필요. 연구는 replay_engine
   (read-only·다종목 시간축 frame)으로 시뮬 가능하나, "배포 가능 조건식" 산출엔 부적합.
5. **D 운영 규모화 = 유일 확실 성과** — THETA 최대 2동시(운영자금 ~1000만), 포지션이 당일
   거래대금의 0.089% → **3~5배 사이징 가능 = 수익금 3~5배**(같은 검증 조건식, 페이퍼→실전 검증).
6. **데이터 경계**: tick 09:00~09:30 고정. min 2025-04~2026-02 (11개월·2022 OOS 없음).
7. **명예의 전당 불변**: THETA·T2C3·포트폴리오(V6) = 배포 가능 수익 조건식. 연 OOS 42~52%.
