## §1. 문제 — 축소 체제에서 일하고 있었다

루프의 백테가 **단일종목(single_stock, cap=1)** 으로 설정돼 있어, 사용자가 목표로 하는
**우수 전략 체제(유니버스 전체·다중포지션)** 와 약 1/40 스케일의 다른 세계였다.
그래서 그동안의 게이트 sweep(일평균 0.2~0.5), gen2/gen3/gen5 비교는 **목표와 무관한 축소 산물**이다.

|---|---:|---:|---:|
| 백테 범위 | **유니버스 ~1379종목** | 단일종목 1개 | 근본 |
| 적정최대보유종목수 | **6~12** | 1 | 핵심 |
| 일평균거래 | **10.6~23.2** | 0.40 | ~40배 |
| 연간수익률 | **134~262%** (평균 199%) | +4.96% | ~40배 |
| 최대낙폭률 | **1.9~6.75%** (평균 4%) | 32.6% | 8배 |
| 매매성능지수 | **1.15~1.47** (평균 1.27) | 1.03 | |
| 평균보유기간 | 142~387초 | — | |
| 승률 | 39~51% | — | |

근본 원인(코드 주석): `config.py:94` `'universe' — 풀 유니버스(1379종목). 세대 루프엔 너무 느림(~1시간)`.
→ 개발 속도를 위해 의도적으로 `bt_scope='single_stock'`(cap=1)로 축소.

### 3.3 적합도/게이트 재정의 (목표 체제 기준)
- **현 게이트(일평균≥0.4) 폐기** → 목표: **일평균 ≥ 8~10** (보고서 하단 10.6 근처), MDD ≤ 7%(가능하면 ≤5%), 흑자, 매매성능지수 ≥ 1.2.
- graded: 청산레버(payoff/give-back) 유지. winner_objective는 매매성능지수 또는 연수익 기준 재검토.
- 하위호환: config 토글로 신·구 게이트 전환. 기존 단일종목 테스트 깨지지 않게.

### 3.4 속도 문제 해결 (핵심 트레이드오프)
유니버스 = ~1시간/세대. 해법 3택(병행 가능):
1. **small_universe 개발 단계**: 커레이티드 N종목(예 50~200) + 다중포지션으로 빠르게 조건식 진화 → 후보 확보.
2. **병렬 백테 인프라**(앞서 미룬 항목): 유니버스가 느린 곳이라 여기서 처리량이 진짜 레버. 단 runlock single-writer·공유메모리·SQLite 충돌 해결 필요(별도 스코프).
3. **universe 최종 검증**: small_universe 우수 후보만 풀 유니버스로 최종 백테(과적합·일반화 검증 겸).

## §5. 위험 / pre-mortem
1. **유니버스 데이터 부재/불완전**: `_database/`에 1년치 전종목 틱 데이터가 있어야. 없으면 small_universe로 한정. → R0에서 데이터 커버리지 확인.
2. **속도**: universe 1시간/세대면 진화가 비현실적. → small_universe 개발 + 병렬화 없이는 풀 유니버스 진화 불가. 완화: 개발은 subset, 검증만 full.
3. **굴림금/배팅 fidelity**: GUI와 다르면 결과 불일치. → R0에서 GUI 1:1 재현 확인(보고서 한 전략 재현).
4. **과적합**: 다중포지션·유니버스는 자유도↑ → 과적합 위험↑. → holdout/WFO(앞 연구문서) 병행.

## §9. Open Questions 조사 결과 (2026-05-27, 읽기전용 확인)

**Q1 (굴림금/적정최대보유 입력 레버) — 해결.**
- `cli/warm_session.py:_spawn_backtest`(L540~553)는 백테 엔진에 **`betting`만 전달하고 seed(예수금) 자본을 넘기지 않는다.** 엔진(`back_static_numba.py:60-61`)은 `seed = betting; if seed < betting: seed = betting` → seed가 betting과 같으면 **동시보유 사실상 1개**. **이것이 단일포지션의 직접 원인.**
- 다중포지션(6~12) 활성화 조건: (a) `divid_mode='종목코드별 분류'`(universe scope) + (b) **seed 자본 = N × betting** 을 spawn 인자에 추가(현재 없음 → config 신규 필드 `bt_seed_capital` 또는 `bt_max_hold`).
- `set_weight`(비중 배팅, backengine_base.py)도 미사용 — 고정배팅 + seed로 N포지션 제어가 가장 단순.

**Q2 (전종목 1년 틱 데이터 커버리지) — 해결: 충분함.**
- `_database/stock_tick_*.db` **952일(2022-03-23~2026-02-27)** + **`stock_tick_back.db`에 2427종목**(풀 유니버스 백테 소스 기존재). 일별 DB는 64~79종목(당일 활성 유니버스).
- 보고서 기간(2022~2024)과 2025 모두 커버 → universe 백테 데이터 제약 없음.

**Q3 (small_universe N 선정) — 옵션 확인.**
- small_universe = 일별 tick DB(64~79종목) 그대로 쓰거나 거래대금순위 상위 N 큐레이션. full universe = `stock_tick_back.db`(2427종목).
- 권고: 개발은 일별 활성 유니버스(~수십종목), 최종검증은 stock_tick_back.

**Q4 (목표 일평균/MDD cap) — 사용자 확정 대기.** 보고서 기준 제안: 일평균 ≥ 8~10, MDD cap 5~7%, 매매성능지수 ≥ 1.25, 연수익 ≥ 130%.
