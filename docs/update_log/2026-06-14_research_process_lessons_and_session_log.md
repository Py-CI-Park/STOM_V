| build_v5(점수합산) 전멸로 사장님의 **이산분기 다밴드 아이디어를 오판 기각** | 두 다른 아키텍처(점수합산 vs if/elif 이산분기)를 뭉뚱그림 | **아키텍처를 구분하라.** 한 변형의 실패가 다른 변형의 실패를 뜻하지 않음. 반례(T2C3) 먼저 확인 |

## 4. 메타 교훈 — 앞으로 연구 프로세스 개선 원칙

1. **도구 표현력 먼저 의심** — 생성물이 빈약하면 "데이터/아이디어 한계"이기 전에 "생성기 표현력 한계"를 의심. (단일밴드 천장이 이 케이스.)
2. **아키텍처 구분** — 점수합산 ≠ 이산분기 ≠ 횡단면랭킹. 실패/성공을 구조 단위로 귀속.
3. **반례 우선 대조** — 비관 결론 전에 명예의 전당(THETA/T2C3) 같은 검증 자산과 먼저 대조.
4. **재백테 게이트 불가침** — 사후 슬라이스 흑자는 진입규칙화하면 재현 안 됨. 채택 전 반드시 재백테.
5. **비용은 백테에 net** — 엣지 재차감 금지(이중계산). 슬리피지만 별도 보정.
6. **오류를 자산으로 기록** — 본 문서처럼 오류·갭을 남겨 다음 세션이 같은 벽에 안 부딪히게.

## 8. 추가 기록 (2026-06-14 밤) — 하네스 기동 + 게이트 결함 교훈

**자율 하네스 구축·기동**: `ai_strategy_loop/scripts/tmap_multiband_discovery.py` 작성.
생성(다밴드)→q1 핵심축 스윕→(q1 양수면)q2 확인→**같은 좌표 양분기 흑자 게이트**→기록→반복.
tick·min 로테이션, 마감 0700. 레그 개별 검증(생성·백테·파싱) 후 1회 통합 테스트로 기동.

**★게이트 결함 발견·교정 (오류 자산)**:
- 초기 드라이버 게이트 = "분기별 *제각각* best>0". iter0 후보가 q1 best `b1_cap_max=1800`
  (+153K), q2 best `b1_sec_money_min=380`(+371K)로 **PROMISING 오판**.
- 정직 재검(같은 좌표): `b1_cap_max=2200`은 q1 +107K인데 **q2 −1.4M**. 같은 좌표 양분기
  흑자 코너 **0개** → 진짜 **no-go**(선택편향 거짓양성).
- **교훈**: 2분기 스모크는 *같은 θ 좌표*가 양분기 흑자여야 충분조건. 분기별 독립 best는
  체리피킹(선택편향) — 밤 루프 하드교훈 h의 정량 재확인. 게이트를 `min(q1,q2)>0` (공유
  라벨 robust)로 교정. 검증: 교정 게이트가 iter0를 정확히 no-go로 거름.
- **메타**: 내 *측정 도구(게이트)* 자체에도 선택편향이 숨는다 → 하네스 자기검증(테스트 먼저)
  필수. 이래서 밤샘 전 1회 테스트가 옳았다.

**밤샘 결과는 별도 누적**: `.omo/evidence/tmap-walkforward/multiband_escalation.md`(+.jsonl).

**드라이버 진화(사장님 협의 반영, 같은 밤)**:
1. **검색 폭 확대** — 스윕 축 3→5개, 포인트 20→40, 생성 슬롯 범위도 넓게(5~7점). 좁은
   검색이 수익 코너를 놓칠 위험 차단.
2. **전체기간 격상(escalation)** — 짧은 2분기 스모크만으론 거짓양성 통과(gen19 증거). 그래서
   스모크 통과분만 **전체기간 train(3년 tick / 11개월 min) + OOS(2022·2026)**로 검증. ★PROMISING
   = 스모크+전체기간+OOS 전부 흑자(THETA급 바). 짧은 슬라이스만 호출하던 것을 전체 DB 기간으로.
3. **다시간대 적극 고려** — 프롬프트가 가용 시간 전체를 구간 분할(tick 시초/중반/후반, min 개장/
   오전/점심/오후)해 **2~3 시간대 밴드** 생성하도록 강화.
4. **운영 교훈**: gen_template_hypothesis는 매 호출 프롬프트 파일을 새로 읽으므로, **p5 프롬프트
   편집은 돌고 있는 루프의 다음 생성부터 즉시 반영(재기동 불필요)**. 단 드라이버 TRACKS·게이트
   변경은 프로세스에 로드돼 있어 재기동 필요. → 생성 지침은 프롬프트로, 흐름은 드라이버로 분리 관리.
정직 기대치: 대부분 no-go. 전체기간+OOS까지 통과하는 다밴드가 나오면 진짜 후보.

**갭: min 어휘 발명(iter2 GEN-FAIL)**: min 트랙에서 LLM이 없는 변수(`직전분봉고가`·
`누적분당거래대금`·`보유수익률`)를 발명해 3회 검증 전멸. min_new 프린시플의 "직전 분봉고가
돌파" 표현이 유도. → p5 프롬프트에 **min 전용 어휘 화이트리스트 + 발명금지 목록 + 대체표현**
명시(검증된 min_session_rotation 어휘 기준). 프롬프트 편집이라 다음 min 생성부터 즉시 적용.
교훈: 트랙 프린시플이 *없는 변수*를 암시하지 않게 어휘를 명시할 것.

**★격상 게이트 첫 캐치(iter7) — 전체기간 요구의 실증**: `llmgen_theta_barbell_open_mid_late_highprint`
(3밴드, THETA 앵커)가 **스모크 같은좌표 게이트 통과**(q1 +205,715 & q2 +1,533,675, 같은 좌표
양분기 흑자) → 옛 설계(스모크만)였으면 PROMISING 오판. 그러나 **전체기간 3년 train −2,030,044**로
과적합 드러나 기각(smoke-pass에서 종료). gen19 패턴을 자동 캐치. 결론: **2분기 같은좌표 흑자조차
전체기간서 부호 반전 가능** → 전체기간+OOS 격상이 PROMISING의 필수 관문임을 실증(사장님 "전체 DB
기간 호출" 요구 정당성 확인).
