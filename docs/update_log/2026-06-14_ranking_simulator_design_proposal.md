# 엔진 보호 횡단면 랭킹 시뮬레이터 — 설계 제안서 (2026-06-14)

> 목적: 사장님 "거래 빈도↑" 요구를 충족할 **횡단면 랭킹 전략**(매 시점 전 종목 점수화→상위 K 매수)을,
> **보호된 .pyd 백테 엔진을 일절 수정하지 않고** 검증하기 위한 신규 시뮬레이터 설계.
> 상태: **제안(Phase 0)** — 사장님 승인 후 Phase 1 착수.

## 0. 왜 가능해졌나 (핵심 enabler)

`ai_strategy_loop/dashboard/replay_engine.py`가 이미:
- 일일 시세 DB(`stock_tick_YYYYMMDD.db`/`stock_min_YYYYMMDD.db`)를 **read-only(`mode=ro`)로만** 연다(원본 보호 계약).
- **다종목을 단일 시간축(HHMMSS)으로 병합 → 같은 슬롯의 종목 bar들을 한 frame으로 묶는다.**

→ 종목별 독립 엔진이 못 주던 **횡단면 스냅샷(매 시점 전 종목 동시 상태)**을 replay가 이미 제공.
랭킹의 가장 어려운 부분(시간 동기화·보호된 데이터 접근)이 해결돼 있다.

## 1. 아키텍처 (3층, 엔진 무접촉)

```
[데이터 층] replay_engine (재사용, read-only)
   일일 시세 DB → 시간슬롯 t별 frame = {종목: (o,h,l,c,vol,등락율,체결강도,...)}
        │  (전체 피처 필요 시 일일 DB를 read-only 직접 조회로 보강)
        ▼
[랭킹 층] (신규) ai_strategy_loop/ranking/
   각 frame에서 종목별 score 계산 → 정렬 → 상위 K 선택
   score = 모멘텀 피처 가중합(등락율·체결강도·거래대금 surge·전일동시간비 등)
        ▼
[체결/PnL 층] (신규)
   상위 K를 frame 가격에 진입 → 보유 규칙(익절/손절/시간/트레일) → 청산 → PnL
   수수료·슬리피지 명시 모델(틱 단위)
        ▼
   결과: 거래수·일평균빈도·수익·MDD·payoff (시드/랜덤과 대조)
```

**보호된 자산 일절 미접촉**: backtest 엔진(.pyd)·loop_strategies.db·THETA/T2C3 파이프라인·backtest/graph.
신규 코드는 `ai_strategy_loop/ranking/` 격리 디렉토리에만.

## 2. 보호 장치 (Safeguards)

1. 모든 시세 DB 접근 `file:...?mode=ro` — replay 계약 준수, 원본 쓰기 0.
2. 백테 .pyd·전략 DB·기존 파이프라인 **수정 0** — 새 디렉토리에만 코드 추가.
3. **PnL 캘리브레이션 게이트**: 시드(THETA) 진입규칙을 시뮬레이터로 재현 → 기존 THETA 백테 CSV와
   체결가·PnL **대조**. ±오차 내 일치해야 시뮬레이터를 신뢰(불일치면 신뢰 불가, 중단).
4. **null-control**: 점수 상위 K vs **랜덤 K** vs 시드 — 랭킹 엣지가 진짜인지 분리.
5. 결과는 기존 검증 체인(OOS 2022/2026·V4 워크포워드)으로 재검증.

## 3. 단계별 계획 (각 단계가 게이트)

| Phase | 내용 | 게이트(통과조건) | 실패 시 |
|---|---|---|---|
| **0 설계** | 이 문서 | 사장님 승인 | — |
| **1 데이터층 검증** | replay로 특정일 다종목 frame 추출 → 횡단면 스냅샷 + 피처 가용성 확인 | frame에 점수용 피처 충분 | 일일DB read-only 직접조회로 보강 |
| **2 PnL 캘리브레이션** ★ | 시드 진입규칙을 시뮬레이터로 재현 → THETA CSV와 대조 | PnL 오차 작음(예 ±5%) | **시뮬레이터 신뢰불가 → ② 중단·① 회귀** |
| **3 랭킹 연구** | 모멘텀 점수 상위 K 전략 → 빈도·수익 측정 vs 시드·랜덤 | 빈도↑ & 시드·랜덤 우월 | no-go(빈도 엣지 없음) 기록 |
| **4 검증** | go 후보 → OOS 2022/2026 + V4 | 기존 챔피언 검증 기준 | 기각 |

**Phase 2가 분수령**: 시뮬레이터가 THETA를 재현 못하면 신뢰할 수 없으므로, 거기서 정직하게 중단하고 ①로 회귀.

## 4. 정직한 리스크

- **PnL 재현 정확도**: 백테 엔진의 정확한 체결 타이밍·슬리피지를 replay+신규 PnL로 100% 재현 못할 수 있음.
  Phase 2 캘리브레이션으로 오차를 *측정*하고, 큰 오차면 중단(과신 방지).
- **빈도 엣지 부재 가능성**: 상위 K 랭킹도 엣지 없을 수 있음(보장 0). 단 이건 *처음 테스트하는* 공간.
- **빌드 규모**: replay 재사용으로 축소됐으나 랭킹+PnL 층 수백 줄 + 검증. 수일 작업.
- **고빈도≠고수익**: 상위 K로 빈도는 오르나 수익은 별개 — Phase 3에서 판정.

## 5. 기대 효과 (성공 시)

- 매 시간슬롯 상위 K 매수 = **빈도 자연 증가**(사장님 핵심 요구) + 자본 투입↑.
- 시드(절대 임계)와 다른 **상대 강도** 엣지 → 비상관 가능성.
- 실패해도 "현 데이터에 횡단면 랭킹 엣지 유무"를 정직하게 확정(미탐사 공간 종결).

## 6. 승인 요청

**Phase 1+2(데이터층 검증 + PnL 캘리브레이션)만 먼저 진행**을 제안합니다 — 이게 시뮬레이터가
신뢰 가능한지 판가름하는 *저비용 분수령*입니다. 통과하면 Phase 3(랭킹 연구) 본격 착수, 실패하면
정직하게 ②를 접고 ①(D 운영 규모화)로 회귀. 엔진은 끝까지 무접촉.
