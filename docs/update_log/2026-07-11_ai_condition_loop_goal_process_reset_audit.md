## 6. 방향성이 흐려진 원인

### 6.1 북극성이 실행 계약으로 고정되지 않음

`좋은 조건식을 만든다`는 목표는 있었지만 데이터 사용 경계, 세대 개선 정의, 실험 예산, 중단 기준, 인간 기준 비교 조건이 한 문서에 동시에 고정되지 않았다.

### 6.2 실행 소유자가 여러 개로 분리됨

| 경로 | 현재 역할 | 문제 |
|---|---|---|
| `ai_strategy_loop/controller/loop.py` | 원래 자율 생성·평가 루프 | 모든 연구 근거와 후보 생성이 이 경로를 통하지 않음 |
| `cli/research_loop.py` | 분석·후보팩·연구 반복 | controller와 별도 루프처럼 발전 |
| lattice/batch | 조합·고정 후보 평가 | 최신 실행이 이 경로에 머물러 세대 학습을 증명하지 못함 |
| dashboard | 관찰·표시 | 서로 다른 cohort와 버전 표기를 한 화면에서 오해할 수 있음 |

### 6.3 실패 후 핵심 가설보다 주변 절차가 증가함

실패할 때마다 Plan, Gate, 버전, 보정 문서가 추가되면서 `무엇을 배웠고 다음 조건식의 어떤 부분이 바뀌었는가`가 중심 산출물이 되지 못했다.

### 6.4 데이터 기반 생성의 provenance가 부족함

feature family와 실패지도는 활용됐지만 각 숫자 임계값이 어떤 B_* 입력 구간과 통계에서 나왔는지, 결과 변수나 holdout 정보가 섞이지 않았는지, 다음 세대가 정확히 무엇을 소비했는지가 단일 계약으로 연결되지 않았다.

### 6.5 매수·매도·리스크 효과가 결합됨

최신 V2 결과로 확실히 말할 수 있는 것은 `entry + exit` 결합이 실패했다는 점이다. 진입 신호가 나빴는지, 청산식이 우위를 훼손했는지는 ablation 없이 확정할 수 없다.

### 6.6 성공 기준보다 버전 이름이 앞섬

서로 다른 연구와 검증에 V1/V2/V3가 반복 사용돼, 독립적인 성과와 단계가 같은 진화 계열처럼 보였다.

## 7. 재고정할 단일 목표와 성공 기준

### 7.1 단일 목표

> 고정된 데이터 분할, 공식 STOM 엔진, 거래비용, 실험 예산 안에서 이전 조건식의 실패를 분석하고, 그 근거로 구조적으로 다른 다음 조건식을 생성하여, 보지 않은 기간에서도 이전 세대와 동일 조건 기준선보다 안정적으로 개선되는 것을 재현 가능하게 증명한다.

### 7.2 정본 폐루프

```text
B_* 입력 데이터와 허용 근거
        ↓
가설 + Candidate Passport + 조건식 AST/본문
        ↓
공식 STOM 제한 백테스트
        ↓
진입 / 청산 / 리스크 분리 부검
        ↓
실패 근거 ID + 다음 변경 명령
        ↓
다음 세대 생성
        └──────────── 반복

후보·설정 동결 후에만 → 봉인 OOS / walk-forward → 공정 인간 기준 비교
```

### 7.3 프로세스 성공 기준

| 기준 | 필수 증거 |
|---|---|
| 후보 계보 | 부모 후보, 생성 모드, 사용 근거 ID, buy/sell hash |
| 임계값 provenance | 사용한 B_* 데이터 범위, 계산 통계, 산출 시점, 코드/데이터 해시 |
| 피드백 소비 | 이전 부검 ID와 다음 후보에서 실제 변경된 clause |
| 의미적 다양성 | AST/행동 중복률, 후보 family quota, 동일 sell/buy skeleton 비율 |
| 인과 진단 | 매수 고정/매도 변화 및 매도 고정/매수 변화 결과 |
| 재현성 | 동일 profile·seed·data hash에서 동일 판정 |
| 예산 준수 | 세대 수, 후보 수, 계산 시간, stop reason |

### 7.4 성능 성공 기준

구체적인 수치 상한은 V3 평가 프로토콜에서 사전 등록한다. 최소 원칙은 다음과 같다.

- 거래비용과 슬리피지 후 기대값이 양수여야 한다.
- MDD 상한을 지켜야 한다.
- 일평균 거래 수는 양의 edge가 확인된 뒤에 판단한다. 거래량이 손실을 보상하지 않는다.
- 단일 전체기간 결과가 아니라 시간 순서가 보존된 validation과 봉인 OOS를 통과해야 한다.
- 최악 fold와 레짐별 성과가 허용 범위 안에 있어야 한다.
- 인간 조건식 비교는 기간·엔진·자금·비용·시간대가 동일할 때만 수행한다.

### 9.2 P5 승인 이후에만 열 수 있는 미래 페이지

아래 페이지는 로드맵이지 현재 실행 허가가 아니다. 각 페이지는 직전 증거와 별도 범위가 승인된 뒤 한 페이지씩 연다.

| 페이지 | 미래 작업 | 선행 조건 | 핵심 검증 | 완료 후 열리는 것 | 현재 상태 |
|---:|---|---|---|---|---|
| P6 | Canonical Loop Code Integration | P3 설계와 P4 프로토콜 승인 | controller가 research evidence·부검 ID·Candidate Passport를 실제 다음 생성에 전달하는 통합 테스트 | 후보 metadata dry-run 계획 | 잠금 |
| P7 | Candidate Metadata & Body Static Dry-Run | P6 통합 증거, 사전 등록 quota | 의미 중복, lineage, syntax, buy/sell 분리, 금지 입력 검사 | DB registration dry-run | 잠금 |
| P8 | DB Registration Dry-Run | P7 정적 게이트 통과 | 실제 DB 변경 없이 이름·충돌·INSERT 대상·rollback 범위 확인 | 명시적 INSERT 승인 요청 가능 | 잠금 |
| P9 | Bounded Mini Closed-Loop Replay | P8 완료와 사용자 명시 범위, INSERT-only 원칙 | min 중심 2~3세대, 세대당 제한 후보, 부검→다음 clause 변경 증명 | survivor가 있을 때만 robustness 페이지 | 잠금 |
| P10 | Blind/Walk-Forward Robustness | P9 survivor, 후보·설정 동결, OOS 사전 등록 | 시간 순서 보존, 비용·슬리피지, 최악 fold, 레짐 안정성 | 공정 benchmark 페이지 | 잠금 |
| P11 | Human Benchmark & Promotion Review | P10 통과, 동일 cohort 구성 | 동일 기간·엔진·자금·비용·시간대에서 기준 조건식과 비교 | 통과 시에만 별도 export/live 검토 | 잠금 |

P9에서 survivor가 없으면 P10을 열지 않는다. 실패 원인을 기록하고 가설을 종료하거나 P3 설계로 돌아가되, 같은 본체의 무제한 변형 루프는 금지한다.

## 10. 전체 단계 완료 시 예상 효과

### 10.1 구조적으로 기대할 수 있는 효과

| 영역 | 예상 효과 | 확인 지표 |

| 데이터 기반 생성 | 후보의 임계값과 feature family에 출처가 연결됨 | provenance 없는 임계값 0 |
| 실제 학습 증명 | 실패 분석과 다음 조건식 변경이 기계적으로 이어짐 | 후보별 parent autopsy ID와 changed clause 존재 |

| 재현성 | 동일 근거·설정·코드로 결과를 다시 확인할 수 있음 | data/code/config hash와 receipt 완비 |
| 대시보드 신뢰성 | 동일 cohort만 비교하고 버전 의미가 명확해짐 | 기간·조건 불일치 경고와 semantic version 표기 |

### 10.2 최종적으로 가능한 두 가지 정직한 결과

| 결과 | 의미 |
|---|---|
| 성능 통과 | 자율 루프가 이전 세대보다 개선됐고 봉인 OOS 및 동일 cohort 기준 비교를 통과했다는 재현 가능한 증거를 확보한다. 이때도 export/live는 별도 승인 대상이다. |
| 성능 미통과 | 현재 feature·데이터·생성 가설에 edge가 없다는 결론을 적은 비용으로 명확히 내리고, 무제한 연구 대신 가설 변경 또는 종료를 결정할 수 있다. |

전 단계 완료가 **수익 전략의 탄생을 보장하지는 않는다**. 보장되는 것은 방향·근거·검증·중단 기준이 연결된 연구 시스템이며, 그 결과 수익 전략을 발견할 확률과 실패를 정직하게 판정할 능력이 높아지는 것이다.
