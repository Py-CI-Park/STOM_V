## 3. 파이프라인 단계별 해부 — 생성 → 백테 → 분석 → 환류 (백테 결과로 조건식을 만드는 메커니즘)

> 코드 실측: `controller/loop.py` `run_loop`(세대 루프)·`brain/generator.py` `generate_strategy`(생성 게이트)·`brain/prompt.py` `build_messages`(프롬프트 조립)·`autopsy/*`(부검 환류). 모든 신규 단계는 토글 기본 OFF byte-identical(§10).

### 3.1 전체 루프 — 세대당 7단계 (`run_loop`, hillclimb 기본)

매 세대 다음을 돈다(괄호=LIVE phase 발행명):

| # | 단계 | 무엇 | 코드 |
|---|---|---|---|
| 0 | **종료 판정** | max-gen / 토큰캡 / target_score(winner 하드게이트 점수)로 조기 종료 | `loop.py:1103` |
| 1 | **생성** (`generate_*`) | gen0+시드→시드 평가. 그 외→`_generate_pair`로 매수/매도 LLM 생성(§3.2). refine면 현 best 코드를 출발점(hill-climb) | `loop.py:1117-1219` |
| 2 | **엔진 호환** | 빈 formula 테이블 보장 | `loop.py:1222` |
| 3 | **백테 + backstop** (`backtest_*`) | warm 엔진 1회 run(~60s, fail-fast 120s 컷). **어떤 예외도 흡수→score=0 후 continue**(절대 크래시·행 안 함) | `loop.py:1234-1300` |
| 4 | **채점** (`score_*`) | 하드게이트 `compute_fitness`(composite=calmar×R²×gate) + graded(winner_objective). **best=graded로 갱신**, **winner=하드게이트(+holdout)로만 갱신** | `loop.py:1311-1476` |
| 5 | **부검·환류** (`autopsy_*`) | ⭐ 백테 CSV를 해부해 **다음 세대 프롬프트 피드백** 생성(§3.3) | `loop.py:1488-1502` |
| 6 | **기록·발행** | record_generation(graded·게이트·MDD·부모델타·가정)·equity_points·LIVE 발행 | `loop.py:1352-1527` |

핵심 장치: robustness backstop(3)·seed-and-refine hill-climb(1·4)·holdout 졸업(4).

### 3.2 조건식 생성 단계 — PRE-SAVE 게이트 사슬 (`generate_strategy`)

매수·매도 각각 retry_max(기본 3)회 시도. **아래 게이트를 전부 통과한 코드만 DB 저장**(실패 시 `prior_error`로 재프롬프트 = 맹목 변이 차단):

1. **프롬프트 조립**(`build_messages`): system(v1 자산 `system_prompt.md`+`variables_reference.md`+`forbidden.md`) + user. **user 블록 순서** — 정규형 골격 → timeframe 변수강제 → (토글)sparse_positive → crossover/base_code(refine mutation) → **보고서 패턴**(19 우수전략 변수철학, 연130~262%·매매성능지수1.25+) → (토글)classification(시총/등락률/넓은 시간창) → **가정환류**(P2b-1) → **세그먼트 avoid**(T4) → **부검 피드백 슬롯** → few-shot(#67 구조학습·복제금지) → history/meta_seed/prior_error
2. **LLM 호출** → on_prompt 콜백(P1c 프롬프트 영속 + T3 시간창 측정)
3. 코드 추출 → 4. **compile 검증** → 5. **token denylist**(import/exec/eval/open/compile/dunder 거부)
6. **변수 스코프 가드**(timeframe 인지 AST — NameError 데드락을 백테 *이전* 결정론 차단)
7. **거래대금 유동성 게이트**(매수·토글) → 8. **필터 범주 게이트**(매수·≥N범주 AND·과발화 방지) → 9. **시간창 no-op 게이트**(매수·전범위만 reject, 좁은 창 보호)
10. **dedup** → 11. **save**

7·8·9는 **구조 게이트**(품질 판정이 아니라 "충분히 게이트됐는가" — R7.4 한계 준수).

### 3.3 ⭐ 백테 결과 분석 → 조건식 생성 환류 (autopsy — 사용자 강조 단계)

**"부검(autopsy)"** = 완료된 백테 결과 CSV(거래당 1행)를 해부해 *다음 세대 생성 프롬프트*로 되먹이는 폐루프. 세 갈래 + 보조 채널:

**(A) 진입(BUY) 부검** — `analyze_trades`→`summarize` (`autopsy/analyze.py:113`)
- CSV를 `수익률`로 win/loss 분할 → 존재하는 `B_*`(진입변수) 컬럼별 **표준화 평균차 SMD=(승평균−패평균)/pooled std**(=Cohen's d) 계산 → |SMD| 내림차순 top-K.
- NL 출력: *"직전 백테 부검: 거래 N건(수익 W/손실 L). 수익과 손실을 가장 잘 가른 진입 조건은 …. 이를 반영해 개선하라."* → 즉 **"이긴 거래에서 변별력 높던 변수를 강화"** 방향 신호.

**(B) 청산(SELL) 부검** — `analyze_exits`→`summarize_exits` (`autopsy/analyze.py:284`)
- give-back(MFE−실현=익절 반납폭)·MAE depth(손절 느슨)·보유시간(수익 vs 손실)·손실 집중 매도규칙 → *"익절 N% 반납→익절 강화", "손절 느슨→MAE −2% 컷", "손실 보유 1.3배↑→시간청산 추가"* 같은 구체 매도 처방.

**(C) 세그먼트 avoid** — `analyze_segments`+`_build_segment_avoid` (T4, `loop.py:1497`)
- 시총밴드×시간대 세그먼트 손익 → **패배 구간**(예: 등락 3~6% 적자)을 `segment_avoid_lines`로 다음 매수 프롬프트에 "이 구간 배제" 주입.

**보조 환류 채널**:
- **가정 루프**(P2a/P2b, `autopsy/hypothesis.py`): 이 세대가 다음 세대용 가정 방출 → 다음 세대 부모대비 델타로 채택/기각 → judged를 프롬프트에 "틀린 방향 반복 금지"로 환류(부검보다 *먼저* 주입).
- **메타 시드**(P4, `_load_meta_seed`): 여러 run 누적 "통과 전략 공통 변수/실패 패턴"을 다음 run 생성에 환류.
- **holdout 졸업검사**(P5, `loop.py:1456`): train 게이트 통과 후보를 결과 CSV의 최근 holdout 슬라이스로 재게이트 → 미통과면 winner 갱신 스킵(과적합 1차 방어).

### 3.4 ⚠️ 이 해부에서 드러난 결정적 사실 — 환류 신호가 전부 *인샘플*이라 구조적으로 과적합을 유도

§2 성적표(train 우수 / OOS 붕괴)의 **코드 레벨 원인**이 여기서 확인된다:

1. **부검은 train 거래에서만 수행** — `analyze_trades(..., is_holdout=True)`는 *ValueError로 거부*(`analyze.py:133`, RV2-4/A5). "수익/손실을 가른 변수" 신호는 곧 **학습창(2023~25)의 win/loss 분리**일 뿐이다.
2. **best 선택 = train graded 점수**(`loop.py:1422`), **winner = train 하드게이트**(`loop.py:1469`). 선택을 끌고 가는 신호가 전부 인샘플.
3. **holdout(P5)은 *게이트*(통과/탈락)이지 *선택 동력*이 아니며 토글**. 켜도 "통과면 winner 인정", 안 켜면 무시.

→ **귀결**: 루프의 학습 신호 전체가 "2023~25 train 창에서 잘 갈린 변수를 강화"로 수렴한다. 그 변수는 정의상 그 창에 특화되므로 **2022/2026 OOS엔 일반화되지 않는다.** gen4가 train +1,155,715인데 2022 OOS −222,400인 것은 버그가 아니라 **이 환류 설계의 직접 귀결**이다.

이 발견은 (a) §4 "과적합 생산 생성기" 진단을 *메커니즘으로* 확증하고, (b) **2안 1번(루프 내 교차검증 채점)·N1(과적합 측정 PBO/DSR)**이 왜 정공법인지를 코드로 정당화한다. 현재 폐루프는 정교하지만 **"인샘플에서 더 잘 갈리게"를 강화하는 루프**일 뿐, "OOS에서 더 잘 일반화하게"를 강화하는 루프가 아니다.

## 4. "잘 가고 있나?" — 정직한 재평가

### 3.1 강점 (유지·확대할 것)

1. **정직성·방법론**: OOS-blind 동결·사전선언 임계값·결정 카드·재선택 금지. 인샘플 자기기만을 막는 이 자산이 가장 값지다.
2. **비가역 ground-truth 확보**: "정적 코드로 좋은 전략 판별 불가(R7.4)", "교차레짐 강건은 단일전략 불가(시드도 2026 적자)", "09:28 하드클립". 헛돌이 방지 지식.
3. **배포 가능한 알파 1개**: 적응형 레짐타이밍(아래 §4.3 단서 포함).

### 3.2 위험 신호 (찜찜함의 정체)

1. **목표 미달이 아니라, 목표가 현 프레임으로 도달 불가일 가능성이 증거로 누적**. 정직 검증 즉시 일관 REJECT, 15배 열세, 엄격 회차는 후보 0개.
2. **자기 ground-truth와 목표의 충돌**: "차이는 코드가 아니라 레짐"이라 증명해놓고 "코드(생성)로 시드 초월"을 추격. 시드가 이기는 건 **수년 인간 튜닝으로 찾은 다년 검증 니치**라서지, 코드가 우월해서가 아니다.
3. **활동 > 진척, 검증 하네스 과잉설계 위험**: 50커밋 상당수가 대시보드·선택기 강화(sparse_positive_v1 → yearly_sparse_robust_v1 → 인간그래프 형태학 채굴 계획). **선택기를 빡세게 하는 건 생성기를 좋게 만들지 않는다 — 더 일찍·정직하게 떨어뜨릴 뿐.** 바늘을 움직일 "OOS 일반화 생성기"라는 어려운 핵심엔 직격이 덜 들어가고 주변 계측만 정교해진다.
4. **결론이 "대체→보완"으로 표류하나 결정으로 올린 적 없음**: 문서는 점점 보완(앙상블)·적응형 배포층·인간그래프 ranking prior로 이동하는데, 6/2 결정점 #6("시드 대체 vs 시드+AI 앙상블")이 미결인 채 작업은 "대체" 모드로 굴러간다. **이 어긋남이 방향 불안의 근원.**

### 3.3 ⚠️ 두 "배포 가능 결과"의 정직한 약화 (검토에서 새로 드러남)

검토 중 §부록 인용으로 확인된 중요한 정정:

- **앙상블 +79%/−58%는 in-sample이고 OOS 전이 실패**. 2025 H1(=AI E18gen4가 *발견된 바로 그 구간*)에서, 시드 1~4월 강세라는 *계절성 사전지식*으로 5~6월만 AI로 교체한 결과. **2024 H1로 naive 전이하면 실패**(+1,601,580, 시드보다 나쁨). 몬테카를로 77.9%/89.8%도 in-sample iid 부트스트랩(레짐 꼬리위험 과소평가).
- **적응형 3.5배만 진짜 다년 OOS(2022~2026) 통과**. 단 lookback=2 HP는 2024~25에서 개발됐고 2024년엔 −1,368,941원 휩쏘 비용. → "진짜지만 무비용 아님".

**함의**: 1안(보완)의 근거가 처음 보이던 것보다 약하다. **현재 통계적으로 가장 단단한 단일 결과는 적응형 타이밍 하나뿐**이다. 이 사실이 §8 권고의 토대.

## 5. 1안 — 보완으로 재프레임 (Complement)

### 핵심
"AI 하나로 시드를 이겨라"를 버리고 **"시드 + AI 팀(앙상블/적응형)으로 더 안정적으로 벌어라"**로 목표를 바꾼다. 채점 잣대를 *단일전략 OOS 시드초월* → *앙상블/적응형 OOS 개선*으로.

### 구체
1. **합격 잣대 교체**: "AI 단일 OOS > 시드"(거의 불가) → "시드+AI 또는 적응형의 OOS 수익/MDD가 시드 단독보다 우월".
2. **AI 역할 재정의**: 시드 *대체*가 아니라 **시드 약세 레짐을 메우는 보완 전략 양산기**.
3. **적응형을 배포 골격으로 승격**: `adaptive_timing.py`(인과적·미래 미참조)를 실운용 레이어로(현재는 분석 전용·hot path 0회 호출).

### 장단점 (정직 보정)
- ✅ 4일 REJECT를 "출하 가능한 결론"으로 전환. 자기 ground-truth와 충돌 안 함.
- ⚠️ **앙상블 근거가 in-sample/사전지식 의존**(§4.3) → "보완이 OOS에서도 유효한가"를 **고정 전이가 아닌 적응형 전제** 위에서 다시 증명해야 함. 적응형 전제가 깨지면 결합가치 소멸.
- ⚠️ "AI 초월"의 꿈은 한발 접음(증거가 그쪽).

## 6. 2안 — 단일 초월 계속, 공격 방식만 교체 (Beat-the-seed, attack-shift)

### 핵심
목표("AI 단일전략이 시드를 OOS에서 초월")는 유지하되, **헛도는 방식(선택기 강화)을 멈추고 생성기의 OOS 일반화 자체를 공격**한다.

### 구체 (택1~2)
1. **루프 내부 교차검증 채점**: 지금은 train에서 최고를 뽑고 *끝난 뒤* OOS를 본다. 대신 **생성 단계 적합도에 "2022·2026 동시 흑자"를 직접 보상**하도록 objective를 강화.
   - **단, 코드 사실 주의(검토 발견)**: `winner_objective='multiyear'`가 *이미 존재*하나 **약하다** — 전구간 누적곡선 우상향 R²만 보고 **연도별 흑자를 요구하지 않는다**(`multiyear.py:22-25`, 사용자가 per-year 균등성을 *명시적으로 거부*). 이것이 gen4가 train-multiyear는 통과하고 2022 OOS는 적자인 직접 원인. → **2안 1번은 사실상 "사용자가 거부한 per-year 강건성을 부활시키느냐"의 결정과 같다(§9 결정점).**
2. **시간지평 확장(S0/S1)**: 6/2 진단의 1순위 *고칠 수 있는* 원인 = `bt_universe_end_time=92800`(09:28) 하드클립. tick 09:30 / min 풀세션(15:19)까지 열어 기회 모수를 28분→수시간으로. (OOM 직결 → 거래수 캡·짧은창 탐색→OOS 분리 필수.)
3. **밴드 P0 배선 + Optuna**: 자유형 LLM 대신 결정론 밴드축 생성→is_off 좁히기(현재 어떤 controller도 미import).

### 장단점
- ✅ 원래 꿈 유지. 2안 1번(루프 내 교차검증)은 과적합 **원천 차단** 정공법.
- ⚠️ **원인 (b)가 시장구조적으로 미해결이면 무엇을 해도 계속 REJECT 가능**(이미 증명된 난제 재도전). 시간·OOM 비용 큼, 산출 시점 불확실.
- ⚠️ per-year 강건성 부활은 사용자 기존 평가기준과 충돌 → 명시 합의 필요.

## 7. 새 방향 (검토에서 도출) — N1·N2·N3

### N1. 과적합 측정 도구를 *먼저* 장착 (PBO/CSCV + Deflated/Probabilistic Sharpe) — **최고 레버리지·최저 위험**

**왜 새 방향인가**: 감사(`2026-06-02_analysis_capability_audit.md`)가 PBO/CSCV를 **"프로젝트 핵심 실패모드의 정답 진단"**, Deflated Sharpe를 **"세대선택 다중검정 보정 전무 = 우승자 상향편의"**라고 명시했는데도 **한 번도 구현되지 않았다.** 현재 루프는 수십 세대 중 최고를 고르면서 *여러 번 시도하면 최고가 우연히 부풀려진다*는 사실을 보정하지 않는다.

**핵심 통찰**: "train 좋고 OOS 무너짐"의 상당 부분이 **측정(선택 편의)** 문제일 수 있다. PBO(과적합확률)·DSR(시도횟수 보정 샤프)이 있으면 **AI든 시드든** "이 후보가 과적합인가"를 *수치로* 말할 수 있다 — 이건 1안·2안 어느 쪽을 택하든 **"인간 수준/초월" 주장의 전제조건**이다(없으면 어떤 우월 주장도 통계적으로 공허).

**범위(불변식 안)**: `compute_fitness` 하드게이트 무수정. 신규 지표는 **분석 전용 + graded 가산항(advisory)**으로만. Sharpe/Sortino/CVaR도 같은 등급으로 추가. 토글 기본 OFF.

**산출**: 결정 카드에 `PBO=...`, `DSR=...`이 *실측치*로 채워짐(현재는 전부 "advisory blocker, not run"). → 다음 모든 판정이 통계적으로 정직해짐.

### N2. 레짐-전문가 포트폴리오 (Mixture of Experts) — 과적합을 *기능*으로 전환

**왜 새 방향인가**: ground-truth("단일전략 교차레짐 불가")를 *받아들인다*. 하나의 강건한 전략을 만들려 하지 말고, **레짐별 전문가 전략 라이브러리**(강세/약세/횡보 각각에 *의도적으로* 특화)를 생성하고 **인과적 레짐 분류기로 라우팅**한다.

- 1안과 다른 점: 시드+AI가 아니라 **AI가 포트폴리오 전체**를 만든다.
- 2안과 다른 점: 단일 강건 전략의 꿈을 *완전히 버린다*.
- 토대: `adaptive_timing.py`(직전 lookback 적자면 OFF)가 이미 이 아이디어의 원시 버전 — "켜고 끄기"를 "어느 전문가를 켜기"로 일반화.

**위험**: 라우터 자체가 과적합/룩어헤드 위험(N1의 PBO로 감시 필수). 전문가별 데이터 희소 → 거래수 부족 재발 가능.

### N3. 시스템 자체를 산출물로 — Walk-forward 재적합 운용기

**왜 새 방향인가**: "어떤 동결 전략도 일반화 안 된다"를 받아들이면, **산출물은 전략이 아니라 루프**가 된다. 루프를 **주기적 walk-forward 재적합기**로 운용: N개월마다 직전 창으로 재생성 → 최근 holdout으로 검증 → 통과 시에만 (감독형) 교체.

- 그들이 만든 정직 인프라(OOS-blind 동결·결정 카드·재선택 금지)가 **그대로 운용 게이트**가 된다.
- "알파"는 특정 전략이 아니라 **자율 적응 시스템 자체** → 북극성의 "앞으로도 자율 개선"에 가장 직접 부합.

**위험**: 재적합 비용·운영 복잡도, 매 사이클 OOM. 실배포(감독형)는 V3K gate·USER_ACK 등 별도 관문(현재 3/6, live 금지).
