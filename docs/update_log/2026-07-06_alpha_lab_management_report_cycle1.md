## 1. 용어부터 — v1/v2가 무엇인가 (질문 ①②에 대한 답)

**비유**: 알파 랩은 "실험실"과 "실험"으로 나뉜다. 실험실(장비·측정기·안전수칙)은 한 번 지으면 계속 쓰는 자산이고, 실험(레시피 1판, 2판…)은 가설이 바뀔 때마다 갈아끼우는 소모품이다.

| 구분 | 실체 | v1 사이클에서의 상태 | v2에서 |
|---|---|---|---|
| **실험실 (인프라)** | alpha_lab 패키지 9모듈·CLI 6종·대시보드 API·봉인/원장 체계·리플레이 엔진·독립 DB | ✅ **완성·전량 커밋 (영구 자산)** | **그대로 재사용** (대체 아님) |
| **실험 레시피 v1** | 피처 25종 + 고정지평 라벨(60/180/300초) + "리프 = 단독 매수식" 산출 형태 | ✅ **끝까지 실행 완료, 판정 도달** | ❌ **이 레시피는 폐기** (측정 결과로 반증됨) |
| **판정 원장 (결과)** | 4개 아이디어의 최종 판정 + n_trials 745 시행 기록 + 봉인 4종 | ✅ 확정·동결 | **영구 보존** (대체 불가 — 감사 자산) |

**질문 ① "v1을 모두 개발한 것인가?"** → **네.** 계획된 모듈 1~9(기반→채굴→번역→이벤트→브리지→대시보드 백엔드→CLI→엔진 검증) 전부 + 계획에 없던 확장(P3 스크리닝 모듈, P5 리플레이 엔진, DB 독립화)까지 완성됐고, 실험도 판정까지 완주했다. 미완은 두 가지뿐: (a) 대시보드 **프론트 화면**(v4 대시보드가 wt-dev에 머지된 뒤 그 구조에 맞춰 짓기로 합의 — 재작업 방지), (b) P1 **본빌드**(952일 전체 채굴 — 관리자 결정으로 보류).

**질문 ② "v2는 대체인가 추가인가?"** → **셋 다 아니고 '다음 판'이다.** 소프트웨어는 추가(같은 인프라 위 새 실험), 레시피는 교체(v1 레시피는 데이터로 반증됐으므로), 결과는 보존(v1 판정은 영구 기록). 신약 개발에 비유하면: 1차 후보물질군이 세포실험(오프라인)은 통과했는데 동물실험(엔진)에서 약효가 없었다 → 같은 실험실에서 **제형을 바꿔** 2차 후보를 시험하는 것이지, 실험실을 부수고 다시 짓는 게 아니다.

## 3. 무엇을 측정했나 — 아이디어별 성과 상세 (질문 ⑤에 대한 답)

### P1 규칙 채굴 (심사 1위, 83점) — "순위는 맞히나 돈은 못 버는 나침반"

```
표본 678,451행(2023·2024 각 30일, 양성률 5.65%)
 → 트리 리프 80개 → 통계 관문(FDR) 생존 40 → 채택 30 → 조건식 번역 30/30 성공
 → 교차창 검증: 153규칙 중 57개가 양방향 lift≥1.3 (최상위 4.1배) ← 오프라인 신호 강함
 → 엔진 1차: 10규칙 전부 적자(-1,182만~-14억원), 순위상관 ρ=0.500 경계 + 2규칙 판정불능
 → 재판정(봉인 허용 1회): 결함(표본화 조건 누락) 수정 → ρ=0.6687 ≥ 0.5 = GO
 → 그러나 절대 성과는 여전히 전 규칙 적자 → 본빌드 보류(관리자 결정)
```
**한 줄 평가**: 채굴이 찾은 "덜 나쁜 순서"는 엔진에서도 유지된다(나침반 유효, ρ=0.67). 그러나 "그 초에 사서 N초 뒤 판다"는 라벨 가정과 실제 엔진 거래 방식(베팅·hard-stop 매도·연속 재평가)의 간극 때문에, 리프를 **단독 매수식**으로 쓰면 돈을 잃는다. → v2 방향의 직접 근거.

### P2 이벤트 스터디 (심사 2위, 82점) — "깨끗한 사망 판정"

```
사건 42,363건(VI해제 697·신고가 10,949·거래대금서지 26,297·갭 3,430·라운드피겨 990)
 → 층화 셀 138개 → FDR 생존 0개 (최소 p=0.01 vs 요구 임계 0.00036)
 → 봉인된 이분법 규칙대로 포기 확정. 원시 EV>0 셀 3개는 "비생존 관찰"로만 기록(재측정 금지)
```
**한 줄 평가**: "사건 뒤에 먹을 게 있다"는 가설은 이 데이터에서 통계적으로 죽었다. 백테 0회로 결론 — 이 축을 앞으로 헛파지 않게 하는 지도가 됐다.

### P3 미시구조 필터(MCL, 심사 3위, 77점) — "판정 불가(표본 부족)"

```
챔피언 거래 671건 중 재조인 성공 346건(76.2%) < 봉인된 최소 표본 2,000
 → 150개 시행 전부 표본 미달 → 판정 불가(신호 유무 자체를 말할 수 없음)
```
**한 줄 평가**: 실패도 성공도 아닌 "저울에 올릴 재료가 부족". 게이트런 CSV 전수 스캔으로 코호트를 키우면 재개 가능 — v2에서 P1 필터형과 자연 합류 후보.

### P5 챔피언 청산 최적화 (심사 4위, 75점) — "모형은 통과, 현실은 기각"

```
반사실 리플레이 재현게이트 통과(오차 중앙 0.0%p·1틱내 99.7%) ← 단일 실패점 우려 해소
 → 청산 정책 192개 전수 평가 → 유일한 유의 후보: 하드스톱-5%+타임스탑300초 (예측 +0.29%p/거래)
 → 엔진 확인 10회: 실측 +0.079%p(신뢰구간이 0 포함, p=0.209) + MDD 5창 중 4창 악화 → 기각
```
**한 줄 평가**: 리플레이 모형이 낙관 편향(원인 후보 4건 문서화)을 가진다는 것까지 밝혀냈다. 현행 챔피언 매도식이 옳다는 것을 **데이터로 재확인**한 것 + 리플레이 엔진 자산 확보가 성과.

## 4. v1 성과 평가 — "안 좋은가?"에 대한 정직한 답 (질문 ③)

**두 렌즈로 나눠야 정확하다:**

| 렌즈 | 평가 | 근거 |
|---|---|---|
| **알파 발굴** (배포 가능 조건식 확보) | 🔴 **0건 — 안 좋은 것 맞음** | 4개 아이디어 모두 엔진 현실을 통과한 산출물 없음 |
| **연구 프로그램** (싸고 빠르고 정직한 판정 + 재사용 자산) | 🟢 **설계 목적 100% 달성** | 아래 3가지 |

1. **손실 회피 가치**: 이 프로그램이 없었다면 "오프라인에서 lift 4.1배!" 같은 신호를 믿고 본빌드(952일)+대량 백테+어쩌면 실전 투입까지 갔을 것이다. 그 전에 32회의 백테만으로 "이 형태로는 안 된다"를 확정했다. 과거 CSS_V7이 같은 함정(서사→코드 간극)으로 MDD 51~65%를 맞고서야 발견한 것을, 이번엔 게이트가 사전에 잡았다.
2. **부정적 결과 = 지도**: "이벤트 축 사망", "청산 개선 여지 없음(현행이 옳음)", "리플레이 낙관 편향", "단독 매수식 형태의 구조적 한계" — 넷 다 다음 탐사가 헛돈을 쓰지 않게 하는 좌표다. 원장에 745회 시행이 전부 기록돼 같은 자리를 두 번 파지 않는다.
3. **양(+)의 신호도 있다**: ρ=0.669는 "채굴 통계가 엔진 성과의 순위를 맞힌다"는 뜻 — 이 나침반이 v2의 존재 이유다. 나침반이 아예 고장(ρ<0.2)이었다면 데이터-우선 발굴 자체를 접어야 했다.

## 5. 왜 v2인가 (질문 ④)

**비유**: 지도(채굴 통계)가 "어느 산이 더 높은지"는 정확히 맞히는데, 산 전체가 해수면 아래에 있었다. 지도를 버릴 게 아니라 **측량 기준(라벨)과 등반 방식(산출 형태)**을 바꿔야 한다.

v1이 반증한 것은 아이디어가 아니라 **레시피의 두 가정**이다:
1. ~~"고정지평 라벨(N초 뒤 매도호가 청산)이 실전 손익을 대표한다"~~ → 엔진은 그렇게 거래하지 않는다(베팅 규모·hard-stop 매도·연속 재평가). **v2: 재현게이트를 통과한 리플레이 엔진으로 "챔피언 매도 규율 하의 실현 손익"을 라벨로 생성** — 갭을 원천에서 줄인다.
2. ~~"채굴된 리프는 단독 매수식으로 쓸 수 있다"~~ → 단독으로는 전멸. 그러나 순위가 보존되므로 **v2: 검증된 챔피언 위의 필터/베토, 그리고 힐클라임 시드**로 쓴다(원래 프로그램 §7의 취지이기도 함). P3(필터 연구)와 문제 공간이 같아져 자연 통합.

**v2가 새로 만드는 것은 거의 없다** — 라벨 생성기 교체(리플레이 재사용)와 산출 배치 변경이 핵심이고, 채굴기·통계·번역기·봉인 체계·CLI·대시보드는 전부 v1 자산 그대로다. 단, 모든 측정은 **새 사전등록(새 봉인)** 아래에서만 한다(v1 기준을 사후에 구부리는 것 방지).

## 6. 무결성 관리 실적 (관리자가 신뢰해도 되는 이유)

- 봉인 4종 sha256 전 과정 무변조 (매 검증 라운드 재계산 대조)
- 임계 쇼핑 0건 — P2 포기·P5 기각 모두 봉인 기준 그대로 (아까워도 재측정 안 함)
- 검열(타임아웃) 처리 규칙을 **엔진 실행 전에 선언**하고 그대로 적용 (사후 재량 차단)
- 자기교정 4회: 수복 에이전트의 테스트 시딩(가짜 데이터로 녹색화) 적발·원복 / 기준선 실패 10건을 순수 기준선 재현으로 증빙 / 추적 파일 오삭제 즉시 복원 / 하네스 실패를 예산 0 소모로 재개
- wt-dev(본선) 무접촉 — 매 엔진 검증 라운드에서 mtime·sha 스팟체크로 확인
- 재판정은 봉인이 명시 허용한 1회만 사용, 리프 임계값 byte-identical 기계 검증

머지 대상은 "성공한 알파"가 아니라 **연구 인프라 + 판정 원장**이다 — 실패 기록을 포함한 원장이 본선에 있어야 다음 연구가 같은 함정을 피한다.

### 결정 요청 ② — v2 사이클 (지금 결정 불필요)
머지 완료 후, v2 상세 설계(새 사전등록 초안 포함)를 별도 보고로 올려 승인받는 것을 제안. 지금은 방향 문서만 동결돼 있다.
