# v5.5 전면 보정 계획 — 반영 실패 원인·구조 이해·기하 검증 프로토콜 (2026-07-20)

## 0. 왜 제대로 반영되지 않았나 (정직한 자기 감사)
1. **검증 방식의 결함**: 릴리스 검증을 "기능 존재(DOM 마커·클래스 유무)"로만 수행하고, **시각 기하(높이 편차·요소 겹침·축 라벨 겹침·정렬)**를 측정하지 않았다. 스크린샷을 찍고도 픽셀 검사 없이 통과 처리했다.
2. **개방형 요구의 축소 해석**: "고도화/재배치/연구해서" 류 요구를 최소 구현으로 좁혔다 — 상황판 자체 정돈 미실시, 백테스트 엔진 시각화 미실시(원장에 L4 완료로 잘못 체크), BT 스테이지 내부 그래프 매트릭스 미실시.
3. **기본값·상호작용 미확인**: "탭 선택 없이 매트릭스"가 의도인데 필터 칩 UI를 남겼고, 전폭(span-all) 배치가 4열 기준 사이즈 요구와 충돌함을 화면으로 확인하지 않았다.

→ 대책: **§3 기하 검증 프로토콜**을 릴리스 게이트로 의무화(수치 통과 없으면 merge 금지).
