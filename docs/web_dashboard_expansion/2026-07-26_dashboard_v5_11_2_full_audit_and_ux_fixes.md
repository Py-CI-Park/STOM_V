## 1. 이번 세션이 찾아낸 실제 결함 (사용자 지적의 진짜 원인)

### 1.1 몬테카를로 "미지원" 문구가 사실이 아니었다 — 기능 누락

화면은 `미지원 — 세대 요약에는 몬테카를로 입력 거래 표본이 없습니다`라고 말했다. 실제로는:

- `/bt/evo_gens?run_id=abmain0716f_p5_typed` → 15세대 **전부 `has_csv=true`**, 거래 23~2,363건.
- `_report_payload_for_run()`은 이미 같은 세대 CSV로 `analysis.monte_carlo(trades, n=2000)`를 **계산해서 HTML 리포트에 넣고 있었다.**
- 원인은 데이터가 아니라 **`/bt/analysis/montecarlo`가 `job_id`만 받는 것**이었다. 세대 경로가 없으니 프런트가 기능 자체를 꺼 버렸고, 그 상태를 "표본이 없다"로 설명했다.

수정: `_analysis_for_run()` 헬퍼 추가, `/bt/analysis/montecarlo`에 `run_id`·`gen_no` 경로 추가, `/bt/result` 세대 경로에 `t_start/t_end` 구간 지원 추가. 프런트는 `has_csv`로 기능 지원을 **동적 판정**한다(CSV 없는 세대는 정직하게 미지원 유지).

검증: `GET /bt/analysis/montecarlo?run_id=abmain0716f_p5_typed&gen_no=4&n=500` → `fan 200 · days 633 · ruin 1.0 · final.p50 -19,967,388`. 화면에서 팬 차트가 실제로 그려지고 구간 분석도 `지원`으로 바뀌었다.

**교훈: "미지원" 문구는 반드시 실제 입력 데이터를 확인한 뒤에 써야 한다. 이 문구는 두 달 넘게 사실이 아닌 상태로 사용자에게 표시됐다.**

### 1.2 카드 높이는 같았지만 그래프 높이는 제각각이었다

직전 인계는 "카드 높이 520px 통일 완료"라고 기록했다. 실측 결과 **카드 겉높이만 520px이고 안쪽 그래프는 303 / 372 / 420px로 3종류**였다.

- `.bt-result-flow .panel svg { max-height: 420px }` (특정도 0,2,1)가
  `.bt-analysis-matrix svg { max-height: 310px }` (특정도 0,1,1)를 이기고 있었다.
- 그 결과 자본곡선·언더워터·MAE/MFE의 svg(372px)가 `.chart-wrap`(310px)을 **62px 넘쳐 x축 라벨이 잘려 있었다.**
- 퀀트 차트는 인라인 `height:"auto"`라 420px로 따로 놀았다.

수정: `--bt-analysis-plot-height: 300px` 단일 토큰 도입, 동일 특정도·후순위 규칙으로 `.chart-wrap`과 `svg`를 함께 고정, `bt-quant`의 인라인 높이 제거(`.bt-plot-svg` 클래스로 이전).

검증: 20개 카드 전부 플롯 높이 `300px` 단일값, x축 라벨 복원.

### 1.3 Live의 "백테스트 탭에서 열기" 버튼이 404로 갔다

`v4-research.jsx`가 `/ui/evolution/backtest`로 이동시켰는데, 이 경로는 허용 하위탭 집합에 없어 **fail-closed 404 페이지**를 반환한다(`curl` 실측 404). 결과 출처 블록을 정리하면서 링크를 정본 `/?tab=backtest`로 교정했다.

## 3. 거버넌스·가정 루프 리모델 (요청 3·4)

### 무엇이 문제였나

- 세 영역이 탭으로 나뉘어 있어 **한 번에 하나만** 보였다. "왜 승격이 막혔나"는 규칙·과정·증거를 같이 봐야 답이 나오므로, 탭 전환이 곧 판단 비용이었다.
- 화면 문구가 백엔드 식별자 그대로였다: `zero-generation review`, `context pack health`, `fail_closed_budget_tokens`, `prompt receipts`, `score_can_promote=false`, `advisory-only`, `hard_gate_not_passed`.

### 어떻게 바꿨나

- 탭 제거 → **`① 규칙 — 어디까지 만들 수 있나` / `② 과정 — 이 후보가 어떻게 나왔나` / `③ 증거 — 무엇이 승격을 막고 있나`** 3분할 동시 노출(1500px 이하 2열, 1000px 이하 1열).
- 상단에 한 줄 안내를 두어 이 패널이 답하는 질문을 먼저 선언한다.
- **우리말이 화면 정본, 원어는 `<small>` 보조 표기.** 로그를 뒤질 때 쓰는 원어는 검색 가능하게 남겼다.
  - `preset` → 탐색 정책 · `MDD gate` → 최대 낙폭 한도(넘으면 무조건 탈락)
  - `trade gate` → 하루 최소 거래(표본 부족이면 탈락)
  - `context pack health` → 연구 자료 묶음 상태 · `candidate pack` → 후보 묶음
  - `promotion blockers` → 승격을 막는 항목 · `present/missing/required` → 있음/없음/필수
  - `advisory-only` → 참고용(승격 권한 없음)
- 라벨이 세로로 쪼개지던 3열 고정폭 행을 `[무엇] [값] / [설명]` 2행 구조로 교체.
- 가정 루프: `채택/기각/판정불가/미검증` → `맞았음/빗나감/판단 불가/확인 전`, `Δ` → `실제 변화`, `MDD ↓` → `최대 낙폭 · 낮추려 함 ↓`, 헤더에 `맞았음 n · 빗나감 n · 확인 전 n` 집계 추가.

## 4. 최대 약점 — 결과 소스 운영성 (5/12점)

`/bt/jobs`를 전수 조사한 결과:

```
총 333건 · cancelled 322 · error 11 · success 0
artifact_state: terminal_without_openable_artifact 322 · lost_tracking 11
openable: 0
mode: wfo 179 · sweep 154 · (plain backtest 0)
```

- **이 대시보드로 완주한 백테스트가 한 건도 없다.** 2026-06-12부터 2026-07-26까지 계속 그렇다.
- 기록된 잡은 전부 `wfo`/`sweep`(최적화·전진분석)이고, 지속 시간은 0.02~0.19초. 전부 중지 요청이 걸려 종료됐다.
- 그 결과 **완료 잡 전용 경로 — A/B 비교, 잡 기준 구간 브러시, 2·3·4열 실데이터 확인, 리포트 열기 — 는 실데이터로 한 번도 검증된 적이 없다.**

직전 인계는 이를 "종료된 실행 기록만 남아 있었다"로 기록했지만 **왜 전부 종료됐는지는 진단하지 않았다.** 프런트에는 자동 취소 경로가 없고(`중지` 버튼만 `/bt/job/cancel` 호출), 취소 플래그는 사용자 요청으로만 설정된다. 즉 **누군가 매번 즉시 중지시켰거나, 자식 프로세스가 즉사한 뒤 취소로 분류되는 경로가 있다.** 이 구분은 실제로 한 건 완주시켜 봐야 갈린다.

**이것이 남은 최우선 과제다.** 지금 UI는 "결과가 없다"를 정직하게 설명하지만, 정직한 설명이 기능 검증을 대신하지는 못한다.

## 5. Reports Summary — 화면은 있고 데이터가 없다 (3/6점)

`결과 Summary` 보드는 정상 렌더링되지만 현재 정본 리포트에서:

```
연평균 수익률 미발행 (annual_return_pct)   누적 수익률 미발행 (total_profit_pct)
MDD 미발행 (mdd_pct)                       일평균 거래 미발행 (daily_avg_trades)
하루 최대 보유 미발행 (max_hold_count)     총 거래 미발행 (trade_count)
```

6개 전부 미발행이라 **사용자에게는 빈 보드로 보인다.** 데이터 정직성 원칙은 지켰지만 화면의 값어치는 0이다.

한편 `/runs`는 같은 지표를 **이미 발행하고 있다**:
`total_profit_pct 164.37 · mdd 17.76 · daily_avg_trades 0.4 · max_hold_count 1.0 · trade_count 307 · years [2023,2024,2025]`

→ 제안: 리포트가 run에 연결돼 있을 때 `/runs` 발행 필드를 **출처를 명시한 대체 원천**으로 채운다(값을 만들어내는 게 아니라 이미 발행된 값을 연결하는 것). 연평균은 이번에 Live에 넣은 방식대로 `파생값` 배지를 달아 기하평균 환산으로 제공한다.

## 6. Replay — 미착수, 방안만 정리 (4/6점)

직전 세션이 `4401 session_required` 원인(프로세스 로컬 세션 + TTL, 페이지가 재시작 후에도 곧바로 WS를 염)을 잡고 사전 세션 갱신을 넣은 것은 정확한 수정이다. 기능 강화는 다음이 비용 대비 효과가 크다.

1. **신호 맥락 연결** — 결과 분석에서 특정 거래를 클릭하면 그 종목·그 시각으로 리플레이가 열리도록 파라미터 prefill. 현재 `▶ 리플레이에서 확인` 버튼은 날짜·종목 없이 탭만 연다.
2. **매수·매도 시점 오버레이** — 재생 중 해당 조건식이 언제 참이 됐는지 캔들 위에 마커로. "왜 여기서 샀나"가 리플레이의 유일한 존재 이유다.
3. **속도·구간 프리셋** — 09:00~09:28 연구 시간대가 정책으로 고정돼 있으므로 그 구간 원클릭 점프.
4. **세션 상태 표시** — 지금은 실패해야 세션 문제를 안다. 상단에 세션 유효/만료를 상시 표시.

## 8. 연구 프로세스를 제대로 연구하게 하는가

**부분적으로 그렇다.** 이번에 추가한 개선 추이 카드가 이 질문에 처음으로 직접 답한다.

실제 데이터가 말한 것:

```
15세대 · 게이트 통과 0건
지금까지 최고 수익금 +8,266,552원 (g0)
지금까지 최고 수익률 164.37%
연평균 수익률 38.27% (3년 기하평균 환산 · 파생값)
최고 기록 갱신 14세대 전 → 탐색 방향을 바꿀 시점
```

**즉 g0가 최고였고 이후 14세대가 아무것도 개선하지 못했다.** 기존 화면은 이 사실을 어디서도 한 문장으로 말해주지 않았다. 세대 표를 직접 읽어야만 알 수 있었다.

아직 부족한 것:

1. **비교 축이 없다.** "이 run이 이전 run보다 나은가"를 Live에서 답할 수 없다. History로 넘어가야 한다.
2. **다음 행동 제안이 없다.** 정체를 감지해도(위 카드가 감지한다) 무엇을 바꿀지는 사용자 몫이다. 부검 최악 구간과 가정 기각 이력을 결합하면 "이 구간을 제외하는 가정은 이미 3번 빗나갔다" 같은 조언이 가능하다.
3. **실패의 누적 학습이 안 보인다.** 기각된 가정은 세대별로 흩어져 있고, "지금까지 빗나간 가정 목록"이 한 곳에 없다.
