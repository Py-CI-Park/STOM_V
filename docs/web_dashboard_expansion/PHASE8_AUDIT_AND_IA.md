# Phase 8 — 성능 핫픽스 + 완성도 수치 감사 + 네비 구조(IA) 재검토

> 2026-06-13 · 브랜치 `feature/webbt-phase8` · 사용자 신고 대응(성능/축정보/히트맵/완성도/버튼구조).

## §1. 성능 핫픽스 (최우선 — "컴퓨터 전체 랙, 사용 불가")
- **원인**: 라이브 차트(`sim-live-chart.jsx`)의 rAF 루프가 애니메이션/가시성과 무관하게 차트마다 60fps로 캔버스 전체를 영구 재드로우. `live`가 기본 엔진(최대 10개) + Phase6.1 keep-alive(다른 탭 전환 시 언마운트 없이 `display:none`) 조합 → **숨겨진 시뮬 탭의 차트들이 영구 60fps 재드로우 = 전체 랙**.
- **수정**: ① 가시성 게이트(`wrap.offsetParent` 없으면 스킵) ② 더티 게이트(데이터/지표/hover/리사이즈 변경 또는 진행 중 애니메이션일 때만 재드로우) ③ 35fps 캡(`_SLC_MIN_FRAME_MS`).
- **실측(Playwright clearRect 계측)**: 재생@240x ≈26 redraws/s(캡 이하) · **숨김/유휴 0 redraws/s** (수정 전: 숨김에도 차트당 60fps×최대10개 = 초당 최대 600 영구 재드로우).

## §2. 축 정보 보강 + 히트맵 지표 (사용자 신고)
- X/Y축: 날짜축에 **연도** 표기, Y축은 양 끝값만이 아니라 **중간 눈금**까지(백테/진화 차트).
- 요일×시간대 히트맵: 수익금 → **수익률 합계(%)** 기준으로 전환(0 기준 발산 색·% 라벨).

### 상위 잔여 갭 3
1. 엔진 메트릭 패널(진화, 75%) — 렌더되나 메인 레이아웃에 노출 약함.

## §4. 네비게이션(IA) 재검토 — 버튼 상위 관계

### 현재 구조의 문제 (사용자 "구조적 상위 관계 재검토")
- **이중 진입 모델**: 상단 3탭(진화/백테/시뮬)은 SPA 즉시 전환, 페이지네비 4버튼(운영/연구실/리서치프로/결정)은 **별도 HTML 풀 리로드** — 응답성·WS 연결·스크롤 위치 불일치.
- **명명 혼란**: 페이지네비 "운영" == 상단탭 "진화 대시보드" (같은 화면, 다른 이름).
- **중복**: 연구실 패널이 진화 탭 안에도, 별도 /ui/lab.html 에도 존재(어느 게 정본인지 불명).
- **고립**: 결정(verdict) 페이지는 연구 흐름으로 돌아가는 백링크 부재.
- **데드/노옵 버튼**: 추적 결과 없음(모든 버튼 실제 엔드포인트 연결).

### 제안 (최소 app.jsx 변경, SPA 통합)
별도 HTML(lab/pro/verdict)을 **인페이지 탭으로 승격**해 단일 SPA 6탭으로 통일:
```
진화 루프 | 백테스트 워크벤치 | 차트 시뮬레이션 | 연구실 | 분석 프로 | 결정 이력
```
- 페이지네비는 "현재 위치" 브레드크럼/드롭다운으로 축소(풀 리로드 제거).
- 효과: 전 탭 즉시 전환·WS 유지·중복 진입 제거·연구→결정 1클릭·탭 상태 자동 유지.
- 비용: lab.html/pro.html/verdict.html → jsx 컴포넌트 전환(중간 난이도) + 사이드바 추출. **UX 대전환이라 사용자 승인 후 Phase 9 로 진행 권장**.

> Phase 8 은 §1(성능)·§2(축/히트맵)·§3(감사 문서)를 즉시 반영하고, §4(IA 대전환)는 사용자 방향 확인 후 별도 진행.
