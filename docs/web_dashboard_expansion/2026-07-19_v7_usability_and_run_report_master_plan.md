## 2. U3 답변 — 거버넌스·결정 원장·승급/Export 경계

**결론: "경계(契約)"는 유지 필수, "UI 패널"은 격하 가능.**
- **유지해야 하는 것(안전 계약, 화면 아님)**: 우승 후보의 운영 export 는 **human 승인 없이는 불가**(`final_approval` 해시 바인딩·hard gate). 이것은 백엔드 계약이며, 잘못된 조건식이 자동으로 실거래 후보가 되는 사고를 막는 마지막 방어선. `performance_proved=false` 체제의 핵심. **삭제 불가.**
- **격하 가능한 것(UI)**: History 하단 "거버넌스 · 결정 원장 · 승급/Export 경계" 섹션(AuditDecisionTrace+VerdictPanel)은 일상 연구 흐름에서 볼 일이 거의 없음 → **접힘(fold, 기본 닫힘) 서브섹션으로 격하**. 승인 다이얼로그(Live 반복 스테이지)는 그대로.
- V7.1에서 적용: History 거버넌스 → `기본 닫힘 fold` + 1줄 요약("결정 N건 · 마지막 결정일")만 상시.

## 4. V7.2 — Run 종합 HTML 보고서 시스템 (U4 핵심 신규 설계)

**목표**: 루프 1회(run)를 돌리면, 그 run 의 전 과정을 **하나의 HTML** 로 체계적으로 보는 결과 시스템. 기존 문서(docs/research)·개별 연구 보고서와 **별개의 정형 산출물**.

### 4.1 보고서 구조(정형화 — 루프 프로세스와 1:1)
```
run_report_<run_id>.html
├─ 0. 표지: run_id · 기간 · 설정 요약(게이트·모델) · 최종 상태 · best 요약
├─ 1. 개선 흐름도(핵심): 세대별 score/MDD/profit 라인 차트(SVG 인라인)
│     + gate 통과 마커 + best 갱신 마커 → "점점 개선되는 흐름" 한눈
├─ 2. 세대별 스텝 기록(반복 섹션, 세대당 1블록):
│     생성(조건식 gist·매수/매도명) → 백테스트(수익·MDD·거래수)
│     → 채점(score·gate 통과/사유) → 부검(실패 원인) → 다음 세대 반영점
├─ 3. 최종 우승/베스트 후보: 조건식 전문 + 지표 + (미승격 명시)
├─ 4. 한계·안전: 표본 내 · performance_proved=false · human gate 문구
└─ 5. manifest 연결: 세대별 개별 스텝 리포트(gen*.html) 링크(/reports/view)
```

### 4.2 구현 계약
- 생성기: `build_step_reports.py` 확장 `--run-report <run_id>` (loop_runs.db SELECT-only, 오프라인/수동. GET/WS 무쓰기 불변). 개선 흐름도는 **인라인 SVG**(script 없음 → CSP/sandbox 그대로 통과).
- 출력: `docs/generated_reports/run_report_<run_id>.html` + manifest 등록 → Reports 탭 "스텝 자동 리포트" 그룹 최상단 + "run 종합" 배지.
- 테스트: 합성 loop_runs.db(3세대) → 흐름도 SVG path 존재·세대 블록 3개·조건식 표기·무script.
- (후속) 라이브 자동 훅 승인 시: run complete 이벤트 → 이 생성기 큐 실행.

- 검사 방법(엔드포인트별): ① 호출→응답 스키마 정상 ② 에러/빈 데이터 envelope ③ 프론트 소비 지점 렌더 ④ PyQt GUI 파리티 필드(gui-parity 모듈 기준) ⑤ 실행 계열(/bt/run·strategy/delete)은 데모/확인 가드 확인. 결과를 **검사표(모듈×항목 pass/fail)** 로 커밋.

### 5.2 결과 분석 "너무 큼" 밀도 재배치
- 실측 후 기준 적용: 결과 화면도 Live 와 동일 수용 기준 — **첫 화면에 판정배너+핵심 메트릭+대표 차트 2개 동시**, scroll ≤ 2.0.
- 방법: 차트들을 2~3열 그리드(3440), 개별 차트 max-height 제한, 상세 차트는 클릭 확대(expand-to-focus), 통계 패널 fold.

### 5.3 시각화 다양화(인사이트 후보, 기존 데이터로 가능한 것만)
